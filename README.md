# 论衡（lunheng-article-pipeline）— 多 Agent 深度长文流水线

把一篇深度文章 / 论文的生产拆成 **8 个角色 + 5 个阶段**（6 主线角色 + **T6 案例检索员任何量级必 spawn，含 0 条空卡协议** + **T8 批判伙伴**），用 OpenClaw `sessions_spawn` 子代理编排（T1∥T2∥T6 三方真并行互不干涉），产出有**证据底座、反方论证、独立审计、人工核验节点**的交付物。

> **v2.2.8 定位**：通用深度长文引擎——**学术论文 / 商业评论 / 行业分析 / 公众号深度长文**通用。
> 经验证：一篇 ~9500 字的深度文，全流程约 2 小时完成。

---

## 何时使用（v2.2.7 软化分层）

**适用场景**（v2.2.4 定位升级：深度长文通用引擎）：
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 文章需要「人在环」把关：大纲确认后再写，终稿人工审
- 主人愿意等 1-3 小时

**字数分层建议**（v2.2.7 软化，不做硬性限制）：
- **≥5000 字**：强烈推荐全量流水线
- **3000-5000 字**：推荐全量流水线
- **2000-3000 字**：可走轻量档（跳 T8 批判）
- **<2000 字**：流水线偏重，建议简化为主控+写手两角色直写

**判断**：流水线成本（8 角色 + 4 闸门）与字数成正比，字数太少投入产出比低；但 <2000 字不是「不能用」，是「不划算」。

## 边界与轻量化建议

**论衡能主动采集**（T1/T2/T6 sub-agent）：
- ✅ 已发布的学术文献 / 统计数据 / 案例报道 / 政府文件

**论衡不擅长主动采集**（需主人投喂素材）：
- ⚠️ 一手原始数据（实验/调查/访谈）| ⚠️ 统计分析（SPSS/R/Python）| ⚠️ 图表原始数据 | ⚠️ 原创图片视频 | ⚠️ 代码执行（`exec` 不在白名单）

**判断口诀**：问「这个证据是**已发布**的数据/文献/案例吗」——是，论衡主动采集；不是，主人投喂后再用。

## ⚠️ 外部服务与数据流声明（v2.2.8 强同意关卡）

使用本流水线时，以下内容**会发送到第三方服务商**：

| 操作 | 第三方服务商 | 发送内容 |
|------|------------|---------|
| `web_search` | OpenClaw 内置 web provider | 检索关键词 |
| `tavily_search` / `tavily_extract` | **Tavily AI** | 研究主题/URL |
| `image_generate`（封面/插图） | **OpenAI gpt-image-2**（默认）→ fallback Google gemini / minimax-image | 主题 + 品牌 prompt |
| 大模型推理 | 当前模型 provider | 文献/数据/案例/草稿/大纲全文 |
| `memory_get` / `memory_search` | 仅本地 OpenViking（**不外发**） | 检索关键词 |

**v2.2.8 强同意关卡**：主控 Phase 0 必须给主人「4 选 1」明示同意：
1. **① 全部同意（默认）** | 2. **② 脱敏+SVG 封面+本地 Ollama**（未公开主题）| 3. **③ 部分同意** | 4. **④ 全部拒绝**（改纯本地）

详见 [`SKILL.md#外部服务与数据流声明`](SKILL.md)。

## 核心特点

### 三不原则（质量底线）
- **不编造** — 引用带 URL/DOI + 数据带来源年份 + 审计分级抽验
- **不堆砌** — 强相关性铁律（每条材料必答「它支撑哪个论点」+ 反向淘汰自查）
- **不重复** — 先行者检索 + 差异点声明 + 原创性审计

### 八角色流水线（v2.2.8 完整）

```
主控（Coordinator）—— 定题、拆解、派发、终检、状态机
  │
  ├─ T1 文献检索员（Literature Scout）── 文献卡 [Lxx]（A/B/C 可信度）  ┐
  ├─ T2 数据检索员（Data Scout）──────── 数据卡 [Dxx]（🟢🟡🔴 时效 + 信任级别）│ 三方真并行
  ├─ T6 案例检索员（Case Scout）──────── 案例卡 [Cxx]（任何量级必 spawn，含 0 条空卡）┘ 互不干涉
  │
  ├─ T3 分析员（Analyst）─────────────── 分析大纲（论证主线 + 论点-论据映射 + 反方论证）
  ├─ T4 写手（Writer）────────────────── 初稿（引用 [Lxx] / 数字 [Dxx] / 案例 [Cxx]）
  ├─ T8 批判伙伴（Critical Companion）── 批判报告（C1-C5 反方攻击）
  └─ T5 审计员（Auditor）─────────────── 审计报告（G0-G13 只审不改）
```

### 三角验证（证据底座）

| 卡片 | 给的是 | 适用论点 |
|------|--------|---------|
| 文献卡 [Lxx] | 理论 / 学术依据 | 「这事有没有人研究过」 |
| 数据卡 [Dxx] | 量级 / 趋势 | 「这事多大、占比多少」 |
| 案例卡 [Cxx] | 事件结构（who/when/what/各方说法）| 「这事具体怎么发生的」 |

### 人在环四节点
- **Phase 0 定题** · **Phase 2.5 大纲** · **Phase 3.5 洞察补充** · **Phase 5 终稿**

### M 机械化硬门 + F 失败模式防御

**M 门三层**（v2.2.8 合并完整版）：
- **M-Form 形式合规门**（6 项）：引用标注 / 文末四节 / 临时编号 / 元数据泄露 / 过程语言 / 信任级别（双格式）
- **M-Exist 存在性合规门**（3 项）：文末四节双向 diff（兼容 ## 附等非标准文末节 + 内联引用分支 + 补检索回填校验）/ 证据包 sha256 / 信任级别一致性
- **M-Integrity 阶段闸门**（2 项）：T2.5（T2 → T3）+ T5.5（T5 → T7）
- **T7 必跑全部 exit 0**

「**形式合规 ≠ 存在性合规 ≠ 信任一致**」—— vincentjiang06 objective/verify gate 论衡化。

**F 失败模式防御 F1-F9**：F1-F7（论证/格式专维度）+ F8 数据信任失败 4 子项 + F9 论证强度不足 5 表现。详见 [`references/failure-modes.md`](references/failure-modes.md)。

**修订回环 ≤2 轮硬约束**：第 3 轮触发 → Acknowledged Limitations 模式（未关闭 P0/P1 搬入 `final/局限性.md`）。

## 流水线全景（v2.2.8）

```
Phase 0 定题        确认主题/篇幅/引用格式 + 4 选 1 同意关卡 → 01-任务简报.md + status.md
Phase 1 并行检索    T1 文献 ∥ T2 数据 ∥ T6 案例（任何量级必 spawn，0 条空卡协议）
Phase 2 分析        T3 分析员 → analysis/分析大纲.md（三角验证 + 原创性声明）
Phase 2.5 大纲确认   主人过目（人在环）
Phase 3 写作        T4 写手 → drafts/初稿-v1.md（AI 去味 10 项 + 反方论证）
Phase 3.6 批判       T8 批判伙伴 → analysis/批判报告-vN.md（C1-C5 反方攻击）
Phase 4 审计        T5 审计员 → audits/审计报告-vN.md（G0-G13）
Phase 4.2 修订       写手交修订说明 + 修订稿（≤2 轮）
Phase 4.5 配图       （可选）程序化生成数据图表
Phase 5 终检        主控终检 → final/定稿.md + 证据包/ + 交付说明.md（含 AI 使用披露）
```

## 怎么用

### 方式一：OpenClaw 技能（推荐）
```bash
# 通过 ClawHub 安装
openclaw skills install lunheng-article-pipeline

# 或本地安装
openclaw skills add /path/to/lunheng-article-pipeline
```

### 方式二：参考方法论
即使不用 OpenClaw，这套「八角色流水线 + 三角验证 + 独立审计 + 三不原则」也可作为**多 Agent 写作 / 研究的通用设计参考**，移植到任意支持子代理编排的框架。

### 模型更换
模型是**能力分层**（检索便宜快 / 分析写作强推理 / 审计顶配 / 主控稳定），不是模型锁定。任何 OpenAI 兼容模型都可替换，详见 [`references/pipeline-readme.md#模型配置`](references/pipeline-readme.md)。

## 论衡哲学

> **「独立角色 + 机械化门 > 自我复核」** —— 论衡的核心命题。
>
> 主控自我复核是 LLM 的舒适区陷阱。M 门（机械化门）通过「LLM 兜底执行伪代码」强制把「自我审视」变成「结构化核验」；F 失败模式（借鉴 ARS Lu et al. *Nature* 2026）把质量维度变成「AI 失败模式清单」威慑设计；T8 批判伙伴（v2.2.2 新增）从反方独立攻击论证。

**M 门由 LLM 兜底执行，零 exec 依赖** —— 不引入 Python 脚本，不扩大 exec 白名单（论衡 agent 15 项白名单不含 `exec`），设计意图 100% 论衡哲学保持。

**版本升级自审门**（v2.2.6 引入，7 门机械化）：论衡自身版本升级 commit 前必跑，防「改 A 漏 B」（教训 #36/#58/#60）与「头痛医头」（教训 P1-3）。
