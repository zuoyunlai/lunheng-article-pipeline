# 论衡（lunheng-article-pipeline）— 多 Agent 深度长文流水线

把一篇深度文章 / 论文的生产拆成 **7 个角色 + 5 个阶段**（6 主线 + T6 案例检索员，重量场景才 spawn，v2.2+），用 OpenClaw 的 `sessions_spawn` 子代理编排，产出有**证据底座、反方论证、独立审计、人工核验节点**的交付物。

> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 ~9500 字的深度文，全流程约 2 小时完成。

---

## 何时使用 + 🌐 语言与定位声明（v2.1.1 新增）

**何时使用**：
- 主人要一篇「有深度、要站得住脚」的长文（>3000 字），且愿意等 1-3 小时
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 需要「人在环」把关：大纲确认后再写，终稿人工审

**🌐 语言与定位（v2.1.1 新增，回应 ClawHub 94% finding）**：
> 本技能面向**中文研究场景**——人文社科论文/公众号深度文/中文行业评论。角色 prompt/交付物/文件名/操作流程均默认中文。

- **如需要非中文（英文/其他）研究产出**：主人可修改 prompts 为目标语言（所有 prompt 在 `references/agents/` 和 `references/templates/` 目录），但**默认不提供多语言**（保持简洁）
- **如需要多 locale 数据源**：主人可调整 `references/agents/02-数据检索-data-scout.md` 的新闻源列表（当前默认中文新闻源 + 国际英文媒体 Reuters/Bloomberg/FT/WSJ/HBR）
- **设计取舍**：中文研究是论衡的核心定位，强加多语言会稀释质量

## ⚠️ 数据流与第三方服务（v2.1.2 新增 — 回应 ClawHub F5 96% / F9 91% findings）

使用本技能时，以下内容会**发送到第三方服务商**：

| 操作 | 发送内容 | 第三方服务商 | 适用阶段 |
|------|---------|------------|---------|
| `web_search` | 检索关键词 | OpenClaw 内置 web provider（路由可能含 Google/Bing） | T1/T2/T3/T6 |
| `tavily_search` / `tavily_extract` | 研究主题、子问题、URL | **Tavily AI** | T1/T2/T6 |
| `image_generate`（封面） | 文章主题 + 品牌 prompt + 排版位置 | **OpenAI gpt-image-2**（默认）→ fallback：Google gemini-3.1-flash-image-preview → minimax/minimax-image-01 → SVG 矢量风（本地） | Phase 4.5 |
| 大模型推理 | 文献/数据/案例/草稿/大纲全文 | 当前模型 provider（deepseek / MiniMax / Anthropic 等，按 `agents.defaults.models`） | T3/T4/T5 + 主控 |
| `memory_get` / `memory_search` | 检索关键词 | 仅本地 OpenViking 记忆库（**不外发**） | 全程辅助 |

**主控必须在 Phase 0 主人确认时同步告知上述外发项**。涉及未公开主题/客户内部信息/商业机密的研究：
- 改用匿名化措辞（脱敏）
- 把封面生成改为 SVG 矢量风（本地零外发）
- 主控推理改用本地 Ollama 模型（`ollama/gemma4:31b` 等，零成本）

**主人拒绝任一外发项** → 主控调整方案并重做 Phase 0 确认。详见 SKILL.md 「⚠️ 外部服务与数据流声明」章节。

## 核心特点

### 三不原则（质量底线）

| 原则 | 机制 | 防什么 |
|------|------|--------|
| **不编造** | 引用带 URL/DOI + 数据带来源年份 + 审计分级抽验 | 幻觉 / 假引用 / 假数据 |
| **不堆砌** | 强相关性铁律（每条材料必答「它支撑哪个论点」+ 反向淘汰自查）| 材料凑数 / 观点堆砌 |
| **不重复** | 先行者检索 + 差异点声明 + 原创性审计 | 重复 / 改写已公开文章 |

### 七角色流水线（6 主线 + T6 案例检索员可选）

```
主控（Coordinator）——定题、拆解、派发、终检、状态机
  │
  ├─ T1 文献检索员（Literature Scout）── 文献卡 [Lxx]（A/B/C 可信度分级）
  ├─ T2 数据检索员（Data Scout）────── 数据卡 [Dxx]（🟢🟡🔴 时效评级 + 冲突并列）
  │    └─ 顺带产出案例卡 [Cxx]（事件结构证据，三角验证第三块）
  ├─ T3 分析员（Analyst）───────────── 分析大纲（论证主线 + 论点-论据映射 + 反方论证）
  ├─ T4 写手（Writer）───────────────── 初稿（引用标 [Lxx] / 数字标 [Dxx] / 案例标 [Cxx]）
  ├─ T5 审计员（Auditor）───────────── 审计报告（G0-G10 十项检查，只审不改）
  └─ [可选] T6 案例检索员（Case Scout）─ 重量场景独立检索事件结构
```

### 三角验证（证据底座）

任何论点必须能映射到三类证据，涉企业行为 / 事件必须有案例卡：

| 卡片 | 给的是 | 适用论点 |
|------|--------|---------|
| 文献卡 [Lxx] | 理论 / 学术依据 | 「这事有没有人研究过」 |
| 数据卡 [Dxx] | 量级 / 趋势 | 「这事多大、占比多少」 |
| 案例卡 [Cxx] | 事件结构（who/when/what/各方说法）| 「这事具体怎么发生的」 |

### 人在环四节点

- **Phase 0 定题** —— 人工确认主题
- **Phase 2.5 大纲** —— 人工确认论证方向（改方向成本最低）
- **Phase 3.5 洞察补充** —— 人工补充一线经验/具体场景（v2.1.3 新增，审计前进入正文）
- **Phase 5 终稿** —— 人工终审

### 独立审计（G0-G10）

审计员与写手分离，十项检查：G0 覆盖度 · G0.5 视角一致性 · G1 引用核验 · G2 数据溯源 · G2.5 案例核验 · G3 逻辑 · G4 格式 · G5 规范 · G6 论据自标 · G7 原创性审计 · G8 成品度 · G9 时序合理性 · G10 核心模型一致性。

## 流水线全景

```
Phase 0 定题        确认主题/篇幅/引用格式 → 任务简报 + 状态机
Phase 1 并行检索    T1 文献 ∥ T2 数据（+ 可选 T6 案例），先行者检索
Phase 2 分析        T3 分析员 → 分析大纲（三角验证 + 原创性声明）
Phase 2.5 大纲确认   主人过目（人在环）
Phase 3 写作        T4 写手 → 初稿（AI 去味 10 项 + 反方论证）
Phase 3.5 洞察补充   主人补充一线经验（人在环，v2.1.3）→ 写手 v2 融入
Phase 4 审计        T5 审计员 → 审计报告（G0-G10）
Phase 4.2 修订       写手交修订说明 + 修订稿（≤2 轮）
Phase 4.5 配图       （可选）程序化生成数据图表（数字与数据卡一致）
Phase 5 终检        终稿 + 证据包（文献+数据+案例+审计）+ 交付说明
```

## 怎么用

### 方式一：OpenClaw 技能（推荐）

```bash
# 通过 ClawHub 安装
openclaw skills install lunheng-article-pipeline

# 或本地安装
openclaw skills add /path/to/lunheng-article-pipeline
```

装好后，主控 Agent 按 `references/pipeline-readme.md` 里的派发话术 spawn 各角色。

### 方式二：参考方法论

即使不用 OpenClaw，这套「七角色流水线（6 主线 + T6 案例检索员）+ 三角验证 + 独立审计 + 三不原则」也可以作为**多 Agent 写作 / 研究的通用设计参考**，移植到任意支持子代理编排的框架。

### 模型更换

流水线模型是**能力分层**（检索便宜快 / 分析写作强推理 / 审计顶配 / 主控稳定），不是模型锁定。任何 OpenAI 兼容模型都可替换，详见 `references/pipeline-readme.md` 的「模型配置与更换指南」。
