# 论衡（lunheng-article-pipeline）— 多 Agent 深度长文流水线

把一篇深度文章 / 论文的生产拆成 **8 个角色 + 5 个阶段**（6 主线 + T6 案例检索员**任何量级必 spawn** + T8 批判伙伴 v2.2.2 新增，含 0 条场景走空卡协议，**v2.2.0**），用 OpenClaw 的 `sessions_spawn` 子代理编排（**T1∥T2∥T6 三方真并行互不干涉，教训 #56** + **M 机械化硬门 + F1-F7 失败模式清单 + 修订回环 ≤2 轮降级，教训 #64**），产出有**证据底座、反方论证、独立审计、人工核验节点**的交付物。

> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 ~9500 字的深度文，全流程约 2 小时完成。

---

## 何时使用 + 🌐 语言与定位声明（v2.1.1 新增）

**何时使用**：
- 主人要一篇「有深度、要站得住脚」的长文（>3000 字），且愿意等 1-3 小时
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 需要「人在环」把关：大纲确认后再写，终稿人工审

**🌐 语言与定位（v2.1.1 新增，回应 ClawHub 94% finding）**：
> 本技能面向**中文研究场景**——人文社科论文/公众号深度文/中文行业评论。角色 prompt/交付物/文件名/操作流程均默认中文。

- **如需要非中文（英文/其他）研究产出**：主人可修改 prompts 为目标语言（所有 prompt 在 `references/agents/` 和 `references/templates/` 目录），但**默认不提供多语言**（保持简洁）
- **如需要多 locale 数据源**：主人可调整 `references/agents/02-数据检索-data-scout.md` 的新闻源列表（当前默认中文新闻源 + 国际英文媒体 Reuters/Bloomberg/FT/WSJ/HBR）
- **设计取舍**：中文研究是论衡的核心定位，强加多语言会稀释质量

## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

**论衡是「论文/深度文章」写作流水线**，擅长**主动检索已发布证据 + 整合主人投喂的证据**。下列场景**不能**主动完成，需主人投喂素材后再用：

- ❌ **一手原始数据采集** —— 实验 / 调查 / 访谈 / 田野调查 → 主人调研后投喂
- ❌ **统计分析**（SPSS / R / Python）—— 论衡可引用结果，**不执行计算**
- ❌ **图表原始数据采集** —— 论衡做**数据可视化**，爬虫 / OCR / 语音转文字需主人用专门工具
- ❌ **原创图片 / 视频生成** —— 论衡有 `image_generate`（封面 / 插图），但不**拍摄实物 / 录制视频**
- ❌ **代码执行** —— `exec` 不在 15 项白名单内（denied）

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」—— 是，论衡主动采集；不是，主人投喂后再用。详见 `references/pipeline-readme.md` 的「🚫 不适用场景」段。

## ⚠️ 数据流与第三方服务（v2.1.2 新增 — 回应 ClawHub F5 96% / F9 91% findings）

使用本技能时，以下内容会**发送到第三方服务商**：

| 操作 | 发送内容 | 第三方服务商 | 适用阶段 |
|------|---------|------------|---------|
| `web_search` | 检索关键词 | OpenClaw 内置 web provider（路由可能含 Google/Bing） | T1/T2/T6 |
| `tavily_search` / `tavily_extract` | 研究主题、子问题、URL | **Tavily AI** | T1/T2/T6 |
| `image_generate`（封面） | 文章主题 + 品牌 prompt + 排版位置 | **OpenAI gpt-image-2**（默认）→ fallback：Google gemini-3.1-flash-image-preview → minimax/minimax-image-01 → SVG 矢量风（本地） | Phase 4.5 |
| 大模型推理 | 文献/数据/案例/草稿/大纲全文 | 当前模型 provider（deepseek / MiniMax / Anthropic 等，按 `agents.defaults.models`） | T3/T4/T5 + 主控 |
| `memory_get` / `memory_search` | 检索关键词 | 仅本地 OpenViking 记忆库（**不外发**） | 全程辅助 |

**主控必须在 Phase 0 主人确认时同步告知上述外发项**。涉及未公开主题/客户内部信息/商业机密的研究：
- 改用匿名化措辞（脱敏）
- 把封面生成改为 SVG 矢量风（本地零外发）
- 主控推理改用本地 Ollama 模型（`ollama/gemma4:31b` 等，零成本）

**主人拒绝任一外发项** → 主控调整方案并重做 Phase 0 确认。详见 SKILL.md 「⚠️ 外部服务与数据流声明」章节。

### ⚠️ v2.1.7 升级 — Phase 0 强同意关卡（ClawHub F5 闭环）

上面「数据流与第三方服务」表的工具都会外发——**项目名/主题/论文纲要可能含未公开信息**（客户内部 / 商业机密 / 个人隐私）。主控 Phase 0 必须给主人「4 选 1」明示同意：

| 选项 | 适用 | 零外发项 |
|------|------|---------|
| ① 全部同意（默认）| 公开主题 / 不介意外发 | 无 |
| ② 脱敏+SVG 封面+本地 Ollama（`gemma4:31b`）| 未公开主题 / 客户内部 / 商业机密 | Tavily / OpenAI / Google / minimax-image |
| ③ 部分同意 | 主人指定具体外发项 | 主人未勾选的项 |
| ④ 全部拒绝 | 极端敏感 | 全部 → 改纯本地（Ollama + SVG）|

**主控必须**把主人选项 + 同意时间写入 `01-任务简报.md` 头部作为审计可追溯依据。详见 `references/pipeline-readme.md` 的「Phase 0 强同意关卡」段。

## 核心特点

### 三不原则（质量底线）

| 原则 | 机制 | 防什么 |
|------|------|--------|
| **不编造** | 引用带 URL/DOI + 数据带来源年份 + 审计分级抽验 | 幻觉 / 假引用 / 假数据 |
| **不堆砌** | 强相关性铁律（每条材料必答「它支撑哪个论点」+ 反向淘汰自查）| 材料凑数 / 观点堆砌 |
| **不重复** | 先行者检索 + 差异点声明 + 原创性审计 | 重复 / 改写已公开文章 |

### 八角色流水线（v2.2.2 升级：批判伙伴 T8 + AI 使用披露）

> **v2.2.2 补强**（教训 #86，v2.2.0 路线图三发计划最后一发）：**T8 批判伙伴**（从反方角度攻击论证 C1-C5，`agents/08-批判-critical-companion.md`，「不是 adversarial，是 critical companion」）+ **F9 论证强度不足失败模式**（论据单一/因果倒置/以偏概全/回避反方/反方走过场）+ **Disclosure AI 使用披露**（三段披露：AI 生成内容/主人原创洞察/检索真实证据，「不是免责声明，是诚实透明」）。论衡 7 角色 → 8 角色（T0-T8）。v2.2.1 补强：**数据信任级别 3 档**（已发布 / 主人投喂 / 二手转引，每条数据/案例必填，M-Form-6 + M-Exist-3 校验）+ **F8 数据信任失败模式**（F8.1 来源混入 / F8.2 公众号版不同步 / F8.3 转引未标注 / F8.4 信任级别遗漏）+ **阶段闸门 T2.5 + T5.5**（主控 checkpoint，不引入新 agent，update_plan + read 实现，「不绕过交接直接派发」）。v2.2.0 补强：**M 机械化硬门**（M-Form 5 项 + M-Exist 2 项 sha256+grep+comm 三件套，T7 必跑 exit 0）+ **F 失败模式清单 F1-F7**（G 项映射表）+ **修订回环 ≤2 轮硬约束**（第 3 轮触发 → Acknowledged Limitations 模式）。v2.1.8 补强：三检索员独立并行 + 互不干涉 + 0 条空卡协议（教训 #56 + #58）。**任何量级必 spawn T6**（含 0 条场景走空卡协议），**取消 v2.1.7 三档决策**（轻/中走 T2 顺带已废弃）。v2.1.4 补强：添加 G8 成品度 + G9 时序合理性 + G10 核心模型一致性三项审计；定稿采用「数据来源 / 案例来源 / 参考文献 / 先行者文献」四节引用清单 + 双向 diff 机械化校验（教训 #47）；查看 `references/pipeline-readme.md` 包含 v2.0.2 → v2.2.2 完整版本日志。

```
主控（Coordinator）——定题、拆解、派发、终检、状态机
  │
  ├─ T1 文献检索员（Literature Scout）── 文献卡 [Lxx]（A/B/C 可信度分级）  ┐
  ├─ T2 数据检索员（Data Scout）────── 数据卡 [Dxx]（🟢🟡🔴 时效评级 + 冲突并列）│ 三方真并行
  │    └─ **纯量级数据**（v2.1.8 起不兼带案例）                                       │ 互不干涉
  ├─ T6 案例检索员（Case Scout）────── 案例卡 [Cxx]（**任何量级必 spawn**，含 0 条空卡）┘
  ├─ T3 分析员（Analyst）───────────── 分析大纲（T1+T2+T6 全 Done 后启动，论证主线 + 论点-论据映射 + 反方论证）
  ├─ T4 写手（Writer）───────────────── 初稿（引用标 [Lxx] / 数字标 [Dxx] / 案例标 [Cxx]）
  ├─ T5 审计员（Auditor）───────────── 审计报告（G0-G10 十项检查，只审不改）
  └─ T6 案例检索员（Case Scout）─ **任何量级必 spawn**，独立检索事件结构（含 0 条场景走空卡协议）
```

### 三角验证（证据底座）

任何论点必须能映射到三类证据，涉企业行为 / 事件必须有案例卡：

| 卡片 | 给的是 | 适用论点 |
|------|--------|---------|
| 文献卡 [Lxx] | 理论 / 学术依据 | 「这事有没有人研究过」 |
| 数据卡 [Dxx] | 量级 / 趋势 | 「这事多大、占比多少」 |
| 案例卡 [Cxx] | 事件结构（who/when/what/各方说法）| 「这事具体怎么发生的」 |

### 人在环四节点

- **Phase 0 定题** —— 人工确认主题
- **Phase 2.5 大纲** —— 人工确认论证方向（改方向成本最低）
- **Phase 3.5 洞察补充** —— 人工补充一线经验/具体场景（v2.1.3 新增，审计前进入正文）
- **Phase 5 终稿** —— 人工终审

### 独立审计（G0-G10）

审计员与写手分离，十项检查：G0 覆盖度 · G0.5 视角一致性 · G1 引用核验 · G2 数据溯源 · G2.5 案例核验 · G3 逻辑 · G4 格式 · G5 规范 · G6 论据自标 · G7 原创性审计 · G8 成品度 · G9 时序合理性 · G10 核心模型一致性。

### F 失败模式防御（v2.2.0 新增）

论衡按「失败模式」组织防御能力（F1-F7），不替换内部 G 体系。借鉴 ARS Lu et al. *Nature* 2026 论文的失败模式组织。

| F 模式 | 防御能力 | 状态 |
|------|---------|------|
| **F1 幻觉引用** | 引用分级抽验 + 存在性双向 diff | 强 |
| **F2 幻觉数据** | 数据溯源 + 时效告警 | 强 |
| **F3 早期框架锁定**（**新增**）| 反方论证覆盖必查 + Phase 3.5 主人洞察补充窗口 | 补强 |
| **F4 论证自洽陷阱**（**新增**）| 论点-论据一对一验证 + G3 逻辑核验 | 补强 |
| **F5 拼凑式章节断裂** | 结构检查 + 段落对称检查 | 强 |
| **F6 过度防御口吻** | 视角一致性 + 论据类型自标 + 「据行业经验估算」限定 | 强 |
| **F7 主人风格模仿失真**（**新增**）| G0.5 + 主人深度洞察融合协议 | 补强 |
| **F8 数据信任失败**（**v2.2.1 新增**）| M-Form-6 + M-Exist-3 + G12 + T2.5 + T5.5 | 补强 |
| **F9 论证强度不足**（**v2.2.2 新增**）| T8 批判伙伴 C1-C5（论据单一/因果倒置/以偏概全/回避反方/反方走过场）| 补强 |

**F8 数据信任失败 4 子项**（v2.2.1 新增）：
- **F8.1 来源混入** | **F8.2 公众号版不同步** | **F8.3 转引未标注** | **F8.4 信任级别遗漏**

**M 机械化硬门**（v2.2.0 + v2.2.1 扩展）：v2.2.0 M-Form 5 项 + M-Exist 2 项 → v2.2.1 扩展为 M-Form 6 项（+ M-Form-6 信任级别标注完整性）+ M-Exist 3 项（+ M-Exist-3 信任级别一致性 diff）+ M-Integrity 2 项（+ M-Integrity-1 T2.5 + M-Integrity-2 T5.5）。T7 必跑全部 exit 0 才能返回。「**形式合规 ≠ 存在性合规 ≠ 信任一致**」—— 借鉴 vincentjiang06 objective/verify gate 硬约束理念的论衡化实现。

**修订回环 ≤2 轮硬约束**（v2.2.0 同步新增）：第 3 轮触发 → Acknowledged Limitations 模式（未关闭 P0/P1 搬入 final/局限性.md）。

**阶段闸门 T2.5 + T5.5 硬约束**（v2.2.1 新增）：T2.5（T2 数据检索 → T3 分析前）+ T5.5（T5 审计 → T7 终检前），主控 checkpoint；不引入新 agent；「不绕过交接直接派发」。

**AI 使用披露（Disclosure）**（v2.2.2 新增）：`final/交付说明.md` 必加「AI 使用披露」段（三段披露：AI 生成内容 / 主人原创洞察 / 检索真实证据）；学术期刊投稿时 `final/定稿.md` 加「AI 使用声明」段。「不是免责声明，是诚实透明」。

## 流水线全景

```
Phase 0 定题        确认主题/篇幅/引用格式 → 任务简报 + 状态机
Phase 1 并行检索    T1 文献 ∥ T2 数据 ∥ **T6 案例（任何量级必 spawn，v2.1.8）**，先行者检索
Phase 2 分析        T3 分析员 → 分析大纲（三角验证 + 原创性声明）
Phase 2.5 大纲确认   主人过目（人在环）
Phase 3 写作        T4 写手 → 初稿（AI 去味 10 项 + 反方论证）
Phase 3.5 洞察补充   主人补充一线经验（人在环，v2.1.3）→ 写手 v2 融入
Phase 4 审计        T5 审计员 → 审计报告（G0-G10）
Phase 4.2 修订       写手交修订说明 + 修订稿（≤2 轮）
Phase 4.5 配图       （可选）程序化生成数据图表（数字与数据卡一致）
Phase 5 终检        终稿 + 证据包（文献+数据+案例+审计）+ 交付说明
```

## 怎么用

### 方式一：OpenClaw 技能（推荐）

```bash
# 通过 ClawHub 安装
openclaw skills install lunheng-article-pipeline

# 或本地安装
openclaw skills add /path/to/lunheng-article-pipeline
```

装好后，主控 Agent 按 `references/pipeline-readme.md` 里的派发话术 spawn 各角色。

### 方式二：参考方法论

即使不用 OpenClaw，这套「八角色流水线（6 主线 + T6 案例检索员 + T8 批判伙伴）+ 三角验证 + 独立审计 + 三不原则」也可以作为**多 Agent 写作 / 研究的通用设计参考**，移植到任意支持子代理编排的框架。

### 模型更换

流水线模型是**能力分层**（检索便宜快 / 分析写作强推理 / 审计顶配 / 主控稳定），不是模型锁定。任何 OpenAI 兼容模型都可替换，详见 `references/pipeline-readme.md` 的「模型配置与更换指南」。
