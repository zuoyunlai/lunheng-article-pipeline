# 论衡（lunheng-article-pipeline）— 多 Agent 深度长文流水线

把一篇深度文章 / 论文的生产拆成 **6 个角色 + 5 个阶段**，用 OpenClaw 的 `sessions_spawn` 子代理编排，产出有**证据底座、反方论证、独立审计、人工核验节点**的交付物。

> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 ~9500 字的深度文，全流程约 2 小时完成。

---

## 核心特点

### 三不原则（质量底线）

| 原则 | 机制 | 防什么 |
|------|------|--------|
| **不编造** | 引用带 URL/DOI + 数据带来源年份 + 审计分级抽验 | 幻觉 / 假引用 / 假数据 |
| **不堆砌** | 强相关性铁律（每条材料必答「它支撑哪个论点」+ 反向淘汰自查）| 材料凑数 / 观点堆砌 |
| **不重复** | 先行者检索 + 差异点声明 + 原创性审计 | 重复 / 改写已公开文章 |

### 六角色流水线

```
主控（Coordinator）——定题、拆解、派发、终检、状态机
  │
  ├─ T1 文献检索员（Literature Scout）── 文献卡 [Lxx]（A/B/C 可信度分级）
  ├─ T2 数据检索员（Data Scout）────── 数据卡 [Dxx]（🟢🟡🔴 时效评级 + 冲突并列）
  │    └─ 顺带产出案例卡 [Cxx]（事件结构证据，三角验证第三块）
  ├─ T3 分析员（Analyst）───────────── 分析大纲（论证主线 + 论点-论据映射 + 反方论证）
  ├─ T4 写手（Writer）───────────────── 初稿（引用标 [Lxx] / 数字标 [Dxx] / 案例标 [Cxx]）
  ├─ T5 审计员（Auditor）───────────── 审计报告（G0-G7 八项检查，只审不改）
  └─ [可选] T6 案例检索员（Case Scout）─ 重量场景独立检索事件结构
```

### 三角验证（证据底座）

任何论点必须能映射到三类证据，涉企业行为 / 事件必须有案例卡：

| 卡片 | 给的是 | 适用论点 |
|------|--------|---------|
| 文献卡 [Lxx] | 理论 / 学术依据 | 「这事有没有人研究过」 |
| 数据卡 [Dxx] | 量级 / 趋势 | 「这事多大、占比多少」 |
| 案例卡 [Cxx] | 事件结构（who/when/what/各方说法）| 「这事具体怎么发生的」 |

### 人在环三节点

- **Phase 0 定题** —— 人工确认主题
- **Phase 2.5 大纲** —— 人工确认论证方向（改方向成本最低）
- **Phase 5 终稿** —— 人工终审

### 独立审计（G0-G7）

审计员与写手分离，八项检查：G0 覆盖度 · G0.5 视角一致性 · G1 引用核验 · G2 数据溯源 · G2.5 案例核验 · G3 逻辑 · G4 格式 · G5 规范 · G6 论据自标 · G7 原创性审计。

## 流水线全景

```
Phase 0 定题        确认主题/篇幅/引用格式 → 任务简报 + 状态机
Phase 1 并行检索    T1 文献 ∥ T2 数据（+ 可选 T6 案例），先行者检索
Phase 2 分析        T3 分析员 → 分析大纲（三角验证 + 原创性声明）
Phase 2.5 大纲确认   主人过目（人在环）
Phase 3 写作        T4 写手 → 初稿（AI 去味 10 项 + 反方论证）
Phase 4 审计        T5 审计员 → 审计报告（G0-G7）
Phase 4.2 修订       写手交修订说明 + 修订稿（≤2 轮）
Phase 4.5 配图       （可选）程序化生成数据图表（数字与数据卡一致）
Phase 5 终检        终稿 + 证据包（文献+数据+案例+审计）+ 交付说明
```

## 怎么用

### 方式一：OpenClaw 技能（推荐）

```bash
# 通过 ClawHub 安装
openclaw skills install lunheng-article-pipeline

# 或本地安装
openclaw skills add /path/to/lunheng-article-pipeline
```

装好后，主控 Agent 按 `references/pipeline-readme.md` 里的派发话术 spawn 各角色。

### 方式二：参考方法论

即使不用 OpenClaw，这套「六角色流水线 + 三角验证 + 独立审计 + 三不原则」也可以作为**多 Agent 写作 / 研究的通用设计参考**，移植到任意支持子代理编排的框架。

### 模型更换

流水线模型是**能力分层**（检索便宜快 / 分析写作强推理 / 审计顶配 / 主控稳定），不是模型锁定。任何 OpenAI 兼容模型都可替换，详见 `references/pipeline-readme.md` 的「模型配置与更换指南」。
