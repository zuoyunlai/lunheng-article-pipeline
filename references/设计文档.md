## 一、结论

**可以。** 方案：主控 Agent（论衡/当前会话）负责任务拆解与派发、终检，**7 个角色**通过「共享目录 + 结构化交接报告」协作，流水线 + 审计回环。（6 主线角色 + T6 案例检索员：重量场景才 spawn，v2.2+）

**7 角色编号**（T 编号与 `agents/0X-*.md` 文件命名一致）：
- **T0** 主控 Coordinator
- **T1** 文献检索员 Literature Scout（并行①）
- **T2** 数据检索员 Data Scout（并行②，含轻量/中量案例卡）
- **T3** 分析员 Analyst
- **T4** 写手 Writer
- **T5** 审计员 Auditor
- **T6** 案例检索员 Case Scout（并行③，可选，重量场景才 spawn）
- **T7** 主控终检交付（final/定稿.md + 证据包/ + 交付说明.md）

- **流水线**：检索(并行①∥②∥③可选) → 分析（三角验证）→ **大纲确认(人在环)** → 写作 → 审计 → 修订回环 → 终检交付
- **审计不过 → 写手交修订说明 + 修订稿，最多 2 轮；仍不过 → 升级主控决策**
- **T6 案例检索员启用判定**：主控在 Phase 0 / Phase 1 进展中按「轻量(≤3 条,T2 顺带) / 中量(4-8 条,T2 重点) / 重量(≥9 条,spawn T6)」三档决策，写入 status.md 案例决策行

## 四、工作流程（7 阶段）

### Phase 0 定题（主控 × 人类）
确认：主题、论文类型、篇幅、引用格式、**目标期刊模板**、deadline、可用数据源、**案例检索强度（轻/中/重量）**。产出 `01-任务简报.md` + `status.md`（含案例决策行）。

### Phase 1 拆解 + 并行检索
主控把主题拆成 3-5 个可检索的子问题 → 决策案例检索强度：
- **轻量案例**（≤3 条）→ 同时 spawn T1 文献 + T2 数据，T2 顺带出案例卡
- **中量案例**（4-8 条）→ T1 + T2 派发话术里加一条「重点出案例卡」
- **重量案例**（≥9 条 / 司法 / 多企业对比 / 复杂事件链）→ spawn **T6 案例检索员**（与 T1/T2 并行，独立第三子代理）

→ `sessions_yield` 等待三者完成。
检索员产出带分级的卡片：文献 A/B/C 可信度、数据 🟢🟡🔴 时效、案例事件结构 + 多方立场。

### Phase 2 分析
分析员产出：研究问题界定、文献缺口、论证主线、**论点-论据映射表**（v2.2 三角验证 [L]+[D]+[C] 标注）、**反方论证规划**、分析框架、章节字数预算。任一核心论点缺角 → 退回主控补检索或降级为「观点」不可写入分析。

### Phase 2.5 大纲确认（人在环，v2 新增）
分析大纲送主人过目。主人确认或提出修改后才放行写手——**大纲阶段改方向成本最低**。

### Phase 3 写作
写手按大纲成文。每处引用标 [Lxx]、每个数字标 [Dxx]、每条案例标 [Cxx]；遵守 **AI 去味禁做清单 10 项**（v2.1.1 改 #3 为「主体声音 ≠ 第一人称经历」）；每核心论点写「反驳 + 回应」；写不出的标 `[待补]`；**「据行业经验估算」使用须满足 5 条限定**（v2.1.1 新增）。

### Phase 4 审计 + 修订回环
审计员独立检查，产出问题清单（P0/P1/P2）：
- **G0 覆盖度**（v2）：对照任务简报逐项核对研究问题是否被回答、有无跑题（防选题漂移）
- **G1 引用分级核验**（v2）：C 级 100% / B 级 ≥50% / A 级 ≥10% 抽验 + 上下文匹配抽查（防张冠李戴）
- **G2 数据溯源**：每个数字有来源；红级数据用于关键论点未说明 → P1
- **G2.5 案例核验**（v2.2，仅当存在案例卡）：每条 ≥2 来源不达标 → P1；缺检索截止日期 → P1；多方立场未并列 → P1；C 级案例当 A 级用 → P0
- **G3 逻辑**：论点-论据对应、论证链断裂
- **G4 结构与格式**：结构完整、期刊模板、引用格式统一
- **G5 学术规范**：查重意识 + 禁做清单 10 项 + AI 痕迹
- **G0.5/G6**（v2.3）：反方论证覆盖 + 论据类型自标
- **G7 原创性**（v2.4）：核心论点是否与先行者清单中已发表文章重复
- **G8 成品度**（v2.1.0）：8 项必查——过程语言 / 角色元数据 / 临时编号 / 元话语 / 修订文件 / 占位符 / 结构对称 / 字数偏差
- **G9 时序合理性**（v2.1.0）：4 项必查——总耗时 / 分阶段 ack / 心跳记录 / 文件时间戳

P0/P1 → 写手交**修订说明**（逐条回应）+ 修订稿 → 审计复核 → 最多 2 轮 → 仍不过升级主控。

### Phase 5 终检交付（T7，主控自己执行）
主控汇总审计报告，通读全文，交付：定稿 + **图件**（若简报「配图需求」非无：按写手 [图N] 图位程序化生成的数据图表 + 封面视觉）+ **证据包**（文献卡+数据卡+案例卡+审计报告+核验记录）+ 交付说明（图件清单、遗留风险 + 建议人工核验项）。每单结束将高频问题产出**反哺报告**（v2.0.2 起默认只产出，不自动 commit 角色卡，等主人人工 merge）。

## 五、交接协议（Handoff）

每个角色完成任务时必须交「交接报告」，六要素：
1. **做了什么** 2. **产物在哪** 3. **怎么验证** 4. **已知问题** 5. **下一步** 6. **状态机更新**
写手修订时另附「修订说明」：问题编号 → 修改内容逐条对照。

## 七、关键防坑（人文社科特有）

1. **引用幻觉是头号风险** — 三层防御：检索员只写真实检索到的 + 强制带 URL + 审计员分级抽验（C 级 100%）。
2. **张冠李戴**（v2.0）— 文献真实但用错语境：审计抽验时做上下文匹配检查。
3. **数据编造/过时**（v2.0）— 所有数字强制「来源+年份+时效评级」，冲突强制并列口径。
4. **选题漂移**（v2.0）— G0 覆盖度检查：审计员对照任务简报查跑题（08-10 教训 #13 机制化）。
5. **AI 痕迹**（v2.0）— 禁做清单 10 项（排比堆砌/金句密度/模板腔等）写进写手硬约束 + 审计逐项查（08-10 教训 #26 落地）。
6. **创新性不保证** — 机制保证流程严谨、论证有据；人在环三节点：定题、大纲、终稿。
7. **成本控制** — 检索用 flash 级，审计顶配；单篇全流程约 30-60 分钟。
8. **案例卡 vs 数据卡边界**（v2.2 新增）— 纯量级（占比/规模/趋势）入数据卡；具体事件/人物/企业行为/各方说法入案例卡；同一事实可互引编号但不重复录入。**失败案例（JCPenney/MUJI/宜家）实操中常被错误塞进数据卡**，08-13 优化后单独立档。
9. **执行层脆弱**（v2.1.0 教训 #43）— 子代理静默超时、模型掉线、心跳缺失都可能拖垮整条流水线；执行韧化协议（30s 心跳 + 分阶段 ack + 健康度预检 + 8 分钟硬卡）必须全员就位。
10. **成品度盲区**（v2.1.0 教训 #43）— G8 成品度 8 项 + G9 时序合理性 4 项，专门查「过程语言残留」「临时编号」「文件时间戳异常」等只在最终交付时才暴露的问题。

## 八、和"直接让一个 AI 写论文"的区别

| 维度 | 单 Agent 直写 | 本机制 |
|------|--------------|--------|
| 引用真实性 | 高幻觉风险，无法自检 | 检索-写作-审计三环 + 分级抽验 |
| 论证严谨性 | 依赖单次生成运气 | 独立分析员建框架 + 反方论证强制 |
| 数据可靠性 | 常编造 | 强制溯源 + 时效评级 + 冲突并列 |
| 选题一致性 | 容易跑题 | G0 覆盖度门禁 |
| 可追溯性 | 黑盒 | 每个论点回溯到文献卡/数据卡/案例卡编号 |
| 交付可复核 | 无 | 证据包随稿交付 |
| 原创性 | 易与已发文章雷同 | T1 先行者检索 + T3 差异点声明 + G7 原创性审计（v2.4） |
