## 一、结论

**可以。** 方案：主控 Agent（论衡/当前会话）负责任务拆解与终检，6 个角色通过「共享目录 + 结构化交接报告」协作，流水线 + 审计回环。

- **流水线**：检索(并行) → 分析 → **大纲确认(人在环)** → 写作 → 审计 → 修订回环 → 终检交付
- **审计不过 → 写手交修订说明 + 修订稿，最多 2 轮；仍不过 → 升级主控决策**
- **2026-08-13 v2.2 新增可选 T6 案例检索员**：与文献员∥数据员并行；重量案例场景（≥9 条/司法/多企业）才 spawn，轻/中量案例由数据员顺带补；详见第七节防坑 + 第六节目录

## 三、角色定义

| # | 角色 | 职责 | 产出物 | 模型建议 |
|---|------|------|--------|---------|
| 0 | 主控 Coordinator | 定题、拆解、维护 status.md、Phase 2.5 送审、终检、证据包、反哺 | 任务简报、status.md、交付说明 | deepseek-v4-pro（fallback minimax-m3） |
| 1 | 文献检索员 Literature Scout | 检索真实文献，标可信度等级 A/B/C，按目标格式出条目 | 文献卡（带 URL/DOI+分级） | deepseek-v4-flash |
| 2 | 数据检索员 Data Scout | 检索统计数据，标时效评级🟢🟡🔴，冲突强制并列；**v2.2 扩权**：启用时顺带出案例卡（轻/中量） | 数据卡（来源+年份+时效）+ 案例卡（如启用） | deepseek-v4-flash |
| 6 | **案例检索员 Case Scout（v2.2 新增可选）** | 重量场景独立检索事件结构、多方立场、≥2 来源；中文新闻源用 tavily include_domains 限定 | cases/案例卡.md | deepseek-v4-flash |
| 3 | 分析员 Analyst | 构建论证框架、论点-论据映射、反方论证规划 | 分析大纲 | deepseek-v4-pro / minimax-m3 |
| 4 | 写手 Writer | 按大纲成文，遵守禁做清单，交修订说明 | 初稿/修订稿 | deepseek-v4-pro / minimax-m3 |
| 5 | 审计员 Auditor | G0-G5 六项审计、分级核验、修订复核 | 审计报告（问题清单） | minimax-m3 / claude-opus-5 |

> 规则：一人一职。写手不审自己的稿，审计员独立于写作链（交叉验证是整个机制的核心）。

## 四、工作流程（7 阶段）

### Phase 0 定题（主控 × 人类）
确认：主题、论文类型、篇幅、引用格式、**目标期刊模板**、deadline、可用数据源。产出 `01-任务简报.md` + `status.md`。

### Phase 1 拆解 + 并行检索
主控把主题拆成 3-5 个可检索的子问题 → 同时 spawn 文献检索员 + 数据检索员 → `sessions_yield` 等待。
检索员产出带分级的卡片：文献 A/B/C 可信度、数据 🟢🟡🔴 时效。

### Phase 2 分析
分析员产出：研究问题界定、文献缺口、论证主线、**论点-论据映射表**、**反方论证规划**、分析框架、章节字数预算。

### Phase 2.5 大纲确认（人在环，v2 新增）
分析大纲送主人过目。主人确认或提出修改后才放行写手——**大纲阶段改方向成本最低**。

### Phase 3 写作
写手按大纲成文。每处引用标 [Lxx]、每个数字标 [Dxx]；遵守 **AI 去味禁做清单 10 项**；每核心论点写「反驳 + 回应」；写不出的标 `[待补]`。

### Phase 4 审计 + 修订回环
审计员独立检查，产出问题清单（P0/P1/P2）：
- **G0 覆盖度**（v2）：对照任务简报逐项核对研究问题是否被回答、有无跑题（防选题漂移）
- **G1 引用分级核验**（v2）：C 级 100% / B 级 ≥50% / A 级 ≥10% 抽验 + 上下文匹配抽查（防张冠李戴）
- **G2 数据溯源**：每个数字有来源；红级数据用于关键论点未说明 → P1
- **G3 逻辑**：论点-论据对应、论证链断裂
- **G4 结构与格式**：结构完整、期刊模板、引用格式统一
- **G5 学术规范**：查重意识 + 禁做清单 10 项 + AI 痕迹

P0/P1 → 写手交**修订说明**（逐条回应）+ 修订稿 → 审计复核 → 最多 2 轮 → 仍不过升级主控。

### Phase 5 终检交付
主控汇总审计报告，通读全文，交付：定稿 + **图件**（若简报「配图需求」非无：按写手 [图N] 图位程序化生成的数据图表 + 封面视觉）+ **证据包**（文献卡+数据卡+审计报告+核验记录）+ 交付说明（图件清单、遗留风险 + 建议人工核验项）。每单结束将高频问题**反哺**进写手角色文件。

## 五、交接协议（Handoff）

每个角色完成任务时必须交「交接报告」，六要素：
1. **做了什么** 2. **产物在哪** 3. **怎么验证** 4. **已知问题** 5. **下一步** 6. **状态机更新**
写手修订时另附「修订说明」：问题编号 → 修改内容逐条对照。

## 七、关键防坑（人文社科特有）

1. **引用幻觉是头号风险** — 三层防御：检索员只写真实检索到的 + 强制带 URL + 审计员分级抽验（C 级 100%）。
2. **张冠李戴**（v2）— 文献真实但用错语境：审计抽验时做上下文匹配检查。
3. **数据编造/过时**（v2）— 所有数字强制「来源+年份+时效评级」，冲突强制并列口径。
4. **选题漂移**（v2）— G0 覆盖度检查：审计员对照任务简报查跑题（08-10 教训 #13 机制化）。
5. **AI 痕迹**（v2）— 禁做清单 10 项（排比堆砌/金句密度/模板腔等）写进写手硬约束 + 审计逐项查（08-10 教训 #26 落地）。
6. **创新性不保证** — 机制保证流程严谨、论证有据；人在环三节点：定题、大纲、终稿。
7. **成本控制** — 检索用 flash 级，审计顶配；单篇全流程约 30-60 分钟。
8. **案例卡 vs 数据卡边界**（v2.2 新增）— 纯量级（占比/规模/趋势）入数据卡；具体事件/人物/企业行为/各方说法入案例卡；同一事实可互引编号但不重复录入。**失败案例（JCPenney/MUJI/宜家）实操中常被错误塞进数据卡**，08-13 优化后单独立档。

## 八、和"直接让一个 AI 写论文"的区别

| 维度 | 单 Agent 直写 | 本机制 |
|------|--------------|--------|
| 引用真实性 | 高幻觉风险，无法自检 | 检索-写作-审计三环 + 分级抽验 |
| 论证严谨性 | 依赖单次生成运气 | 独立分析员建框架 + 反方论证强制 |
| 数据可靠性 | 常编造 | 强制溯源 + 时效评级 + 冲突并列 |
| 选题一致性 | 容易跑题 | G0 覆盖度门禁 |
| 可追溯性 | 黑盒 | 每个论点回溯到文献卡/数据卡编号 |
| 交付可复核 | 无 | 证据包随稿交付 |
