## 二、角色定义（10 张角色卡；本节历史演进见 glossary 一）

| 编号 | 角色 | 职责 | 何时启动 |
|------|------|------|---------|
| **T0** | 主控 Coordinator | 定题、拆解、派发、终检、状态机 | 始终在线 |
| **T1** | 文献检索员 Literature Scout | 已发布学术文献/政策文件/统计年鉴检索 | Phase 1 |
| **T2** | 数据检索员 Data Scout | 已发布统计数据/行业报告/新闻数据检索 | Phase 1 |
| **T3** | 案例检索员 Case Scout | 多 Agent + Phase 0 确认案例需求时检索；cases=0 产空卡 | Phase 1 |
| **T4** | 分析员 Analyst | 论点拆解 + 论证结构设计 + 大纲编写 | Phase 2（T1+T2+T3 完成后） |
| **T5** | 写手 Writer | 正文撰写 + 修订执行 | Phase 3 |
| **T6** | 批判伙伴 Critical Companion | 从反方攻击论证（C1-C7） | Phase 3.6（T5 v2 后） |
| **T7** | 审计员 Auditor | 质量审计（G0-G14）+ 修订任务书 | Phase 4 |
| **T9** | 同行评审 Peer Reviewer | 预演期刊审稿（6 维度评分 → accept/minor/major/reject） | T7.5 完整性门通过后、T8 终检前（公众号可选） |

> **T8 终检** = 主控亲完成不 spawn（有独立角色卡）
> **G14 中文 AI 痕迹闸**：**Phase 4.4 前置**（`g14_style_gate`）——定稿前最后一道闸，**全流程只审一次、不再复检**；触发前提 = 前置修订已收敛「已可定稿」。8 类检测维度，LLM 推理判定（零 exec），0-2 类 Pass / 3-4 类 Warning（呈报 3 选 1）/ 5+ 类 Fail → 由 T5 做最后一次风格层修订（`t5_style_revision`）。位置与八类判定真源 = `_shared/phase-order.yaml` / `gates/14-中文AI痕迹-gate.md`。

详细定义：见 `agents/0X-*.md` 角色卡 + `_shared/glossary-full.md § 一 核心角色`

## 三、工作流程（Phase 0-5 共 6 个阶段：Phase 0 定题 + Phase 1-5 主流程）

### Phase 0 定题（主控 × 人类）
- 4 选 1 同意关卡（全部同意 / 脱敏+本地 / 部分同意 / 全部拒绝）
- 主人确认主题/类型/篇幅/引用格式/deadline

### Phase 1 并行检索（T1∥T2∥T3 三方真并行）
- T1 文献 + T2 数据 + T3 案例（含 0 条场景走空卡协议）

### Phase 2 分析（T4）
- 三角验证：[L] + [D] + [C]
- 反方论证规划 + 原创性声明

### Phase 2.5 大纲确认（人在环）
- 主人过目分析大纲

### Phase 3 写作（T5）
- 初稿 v1 → 修订（**Phase 3.6/3.7 批判修订** / **Phase 4.2 审计修订**）；轮次映射与判定 → 见 `_shared/pipeline-overview.md`『修订回环仲裁规则』（单一真源；本文件不复述轮次数字）
- AI 去味 10 项 + 反方论证

### Phase 3.5 洞察补充（人在环）
- 主控向主人呈现初稿 v1
- 主人明确选择：补充深度洞察，或「无补充」；两者都写入项目状态
- 只有在有洞察时，T5 写手才产出 v2；「无补充」不是静默跳过
- 随后进入 Phase 3.6，由 T6 批判伙伴产出 `analysis/批判报告-vN.md`

### Phase 4 审计（T7）
- M 门+ G 清单（G0-G14）+ F 失败模式（F1-F9）
- 修订任务书（如打回）

### Phase 4.4 前置 G14 痕迹闸（`g14_style_gate`）
- **G14 中文 AI 痕迹闸**：定稿前最后一道闸，**全流程只审一次（不再复检）**；8 类检测维度，LLM 推理判定（零 exec），0-2 类 Pass / 3-4 类 Warning（呈报 3 选 1）/ 5+ 类 Fail → 由 T5 做最后一次风格层修订（`t5_style_revision`）
- 位置真源 = `_shared/phase-order.yaml`；八类判定真源 = `gates/14-中文AI痕迹-gate.md`（本文件不复述八类明细）

### Phase 4.5 同行评审（T9）
- **T9 同行评审**（按模式触发）：行业分析/学术论文默认开启，公众号可选关闭；模拟期刊审稿人 6 维度评分 → accept/minor/major/reject 建议
- **方法论实时可见面板**：status.md 加「方法论足迹」段（当前阶段/证据强度/已触发闸门/下一步预测/不确定性/模型健康度），主人实时看清进度

### Phase 5 终检（T8 主控亲完成不 spawn，人在环）
- 证据包完整性 + 引用一致性 + AI 使用披露
- 主控向主人呈现 `final/定稿.md` + `交付说明.md`
- 主人明确选择接受、补改、重走某阶段或延期；未留下决策记录不得标记项目完成

**M 门渐进式执行**（分批触发，P0 错误提前暴露；**各项的项数与闸门步数一律以 `_shared/M-Gate-Algorithm.md` 伪代码为准，本文件不复述**）：
- Phase 1.5（T1/T2/T3 完成后）：T2.5 完整性门（M-Integrity-1 + M-Form-6）
- Phase 2.5（T4 分析后）：M-Form-3
- Phase 3.5（T5 v1 后，主人洞察）：M-Form-1/2/4/5
- Phase 3.6（T6 批判后）：M-Form-7 论证强度
- T7.5（T7 审计后）：M-Exist-1/2/3 + M-Integrity-2（完整性门）
- Phase 5（T8 终检）：按 M-Gate 真源跑 **T8 兜底集**（项数以 `_shared/M-Gate-Algorithm.md` 为准，本文件不复述）

（P0 错误提前暴露，详见 `_shared/M-Gate-Algorithm.md` M-Form / M-Exist / M-Integrity 各阶段描述；该文档为 🟠 分片必读——伪代码段必读，附录按需）

## 五、仓库目录职责（工程侧）

> **本段只描述「仓库自身」的目录职责**。单篇论文/文章的**产物目录树**（`run/<项目名>/`）另有真源 = [`_shared/asset-index.md`](_shared/asset-index.md)「项目目录结构」，本段**不重列**（重列违反一条款一真源）。

| 目录 / 文件 | 面向 | 职责 | 何时读 / 何时改 |
|---|---|---|---|
| `SKILL.md` | 使用者 + 宿主 | 入口契约：触发场景、能力边界与权限声明、Phase 0 启动清单、单源指针与派发索引 | 使用者首读；正文规模受 ratchet 门约束（`tests/test_doc_quality.py`） |
| `QUICKSTART.md` | 使用者 | 安装 / 宿主适配要点 / 5 分钟上手 / 不适用场景 / FAQ | 新使用者首读 |
| `README.md` | 外部读者 | 对外介绍与导读：核心特点、外发类别导读、实战案例、版本演进 | 发版时核对 |
| `references/agents/` | 子代理 | 10 张角色卡（T8 终检由主控亲完成不 spawn，仍有独立卡） | 派发前主控必读对应卡 |
| `references/gates/` `references/checkers/` | 子代理 | 闸门定义与检查器 | 跑对应闸门前 |
| `references/templates/` | 子代理 | 产物模板（任务简报 / status / 交接报告 / 卡片 / checkpoint-card 等） | 产出物落盘前 |
| `references/dispatch/` | 主控 | 各阶段派发话术 | spawn 前 |
| `references/_shared/` | 主控 + 子代理 | **共享真源层**：口径、算法、协议、索引（`phase-order.yaml` / `asset-index.md` / `pipeline-overview.md` 等） | 按 `_shared/asset-index.md` 核心文档索引表定位 |
| `references/设计文档*.md` | 开发者 | 设计说明（总览 / 架构 / 哲学）；**不入 ClawHub 净化包** | 设计变更时同步 |
| `scripts/` | 开发者 | 构建期工具链：版本同步、changelog 校验、链接 / 流程检查、净化打包、发版前置闸、自审门 | 发版前必跑（入口见 `Makefile`）；**各脚本用途的真源 = 脚本头部注释**；**索引视图 = `scripts/README.md`（自动生成，勿手改）** |
| `tests/` | 开发者 | pytest 断言层：门禁规则、真源一致性、文档质量、历程回归 | `make test` |
| `Makefile` `pyproject.toml` `requirements.txt` `.github/` | 开发者 | 开发者工具入口（自审门 / pytest / 净化链 / CI）；**不入 ClawHub 净化包** | 见 `README.md` 卷首说明 |
| `CHANGELOG.md` `CHANGELOG-archive.md` | 开发者 | 版本演进记录与冷归档 | 每个发版 tag 必有章节（`scripts/changelog-check.py` 门） |

**分层原则**：

1. **使用者可读层**（`SKILL.md` / `QUICKSTART.md` / `README.md`）**只引用不重列**运行时真源；重列即构建期红。
2. **运行时正文层**（`references/`）内同一口径**只有一个真源文件**，其余为**派生视图**并显式标注真源指针。
3. **工程层**（`scripts/` / `tests/` / 根级配置）**不承载运行时口径**，只承载机械校验；其变更不改变流水线语义，但对使用者不可见（不进净化包）。
