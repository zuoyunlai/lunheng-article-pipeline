# 论衡核心概念词汇表

## 一、核心角色（8 个）

### T0 - 主控（Coordinator）
- **职责**：流程编排 + 任务派发 + 质量把关 + 人机交互
- **不做**：不替代任何子代理执行具体工作
- **关键协议**：Phase 0 同意关卡 / spawn-yield 模式 / 完成验证铁律

### T1 - 文献侦查（Literature Scout）
- **职责**：已发布学术文献 / 政策文件 / 统计年鉴检索
- **输出**：`[Lxx]` 文献卡
- **并行模式**：T1 ∥ T2 ∥ T6 独立运行

### T2 - 数据检索（Data Scout）
- **职责**：已发布统计数据 / 行业报告 / 新闻数据检索
- **输出**：`[Dxx]` 数据卡
- **铁律**（v2.1.8）：只产数据卡，不产案例卡
- **并行模式**：T1 ∥ T2 ∥ T6 独立运行

### T3 - 分析（Analyst）
- **职责**：论点拆解 + 论证结构设计 + 大纲编写
- **输入**：T1 + T2 + T6 全部完成后触发
- **输出**：`drafts/大纲.md`

### T4 - 写手（Writer）
- **职责**：正文撰写 + 修订执行
- **铁律**：禁做清单 10 项（AI 去味）
- **独立性**：修订轮必须重新 spawn，不能主控代执行

### T5 - 审计（Auditor）
- **职责**：质量审计（G0-G13）+ 修订任务书
- **输出**：`drafts/审计报告-v[x].md`
- **双完整性门**：T2.5（数据卡完整性）+ T5.5（引用完整性）

### T6 - 案例检索（Case Scout）
- **职责**：案例/事件/人物/企业案例检索
- **输出**：`[Cxx]` 案例卡
- **0 条空卡协议**：0 条场景输出 `[C-空]`
- **并行模式**：T1 ∥ T2 ∥ T6 独立运行（v2.1.8）

### T8 - 批判伙伴（Critical Companion）
- **职责**：批判性审查（非对抗性）
- **触发**：T4 写手 v1 完成后、T5 审计前
- **输出**：`drafts/批判审查-v[x].md`
- **定位**（v2.2.2）：不是 adversarial，是 critical companion

## 二、三层防御体系

### M 门（形式合规门）
- **性质**：机械化、零人工判断、可自动化
- **算法**：Python 伪代码 + Bash 验证命令
- **执行模型**（v2.2.12 澄清）：
  - ✅ **主控 LLM 推理判定**：主控用 `read` 读取算法文档，按伪代码**推理**判定
  - ❌ **不执行 shell**：算法中的 `sha256sum` 等命令仅供人类手动验证
- **覆盖范围**：11 项检查（M-Form-1 到 M-Integrity-4）
- **单一真源**：`references/_shared/M-Gate-Algorithm.md`

### F 模式（失败模式清单）
- **性质**：面向用户的叙事层，解释"为什么要这么做"
- **覆盖范围**：F1-F9（v2.2.2）
  - F1：证据链断裂
  - F2：论证跳跃
  - F3：数据来源不明
  - F4：逻辑循环
  - F5：过度依赖单一来源
  - F6：时效性失效
  - F7：引用形式不规范
  - F8：数据信任失败
  - F9：论证强度不足
- **单一真源**：`references/_shared/failure-modes.md`

### G 清单（质量审计清单）
- **性质**：面向审计员的执行层，详细的操作手册
- **覆盖范围**：G0-G13（v2.2.11）
  - G0：大纲合规性
  - G1：证据完备性
  - G2：论证强度
  - G2.5：估算专项（v2.2.0）
  - G3：时效性
  - G4：数据真实性
  - G5：逻辑一致性
  - G6：融合自然度
  - G7：原创性
  - G8：成品度（v2.1.0）
  - G9：时序合理性（v2.1.0）
  - G10：核心模型一致性（v2.1.3）
  - G11：数据时效告警（v2.1.5）
  - G12：数据信任验证（v2.2.1）
  - G13：AI 使用披露（v2.2.2）
- **单一真源**：`references/_shared/audit-checklist-quickref.md`

## 三、数据信任级别（v2.2.1 核心机制）

### 🟢 Level 1：已发布公开数据（最高信任）
- **定义**：通过正规渠道发布的官方/学术数据
- **示例**：
  - 官方统计年鉴（国家统计局）
  - 学术论文中的研究数据（已发表）
  - 行业协会公开报告（中国汽车工业协会）
- **验证要求**：M-Exist-1 检查来源 URL
- **引用形式**：内联引用 `(来源，年份)` 或编号引用 `[Dxx]`

### 🟡 Level 2：主人投喂数据（中信任）
- **定义**：主人提供的一手数据、内部资料、专家访谈记录
- **示例**：
  - 主人提供的企业内部销售数据
  - 主人进行的问卷调查结果
  - 主人的实地考察笔记
- **验证要求**：M-Exist-3 检查主人确认记录
- **引用形式**：标注 `[主人提供]` 或 `[内部数据]`

### 🔴 Level 3：二手转引（低信任，严格限制）
- **定义**：从新闻报道、自媒体、二手资料转引的数据
- **限制条件**（v2.2.1 铁律）：
  1. 必须回溯到一次文献（新闻/报告必须引出原始来源）
  2. 顶部标注 `[二手转引]` 警告
  3. T5 审计 G12 专项检查
- **禁止场景**：核心论据、统计数据、精确数字

## 四、关键协议

### Phase 0：同意关卡（v2.1.7 金标准）
**触发**：主控接收到论文写作请求后，第一时间执行

**4 选 1 模式**：
1. ✅ **直接开工**：主人明确说"开始写"/"按这个题目来"
2. 📋 **补充信息**：主人提供素材但题目/角度模糊
3. ⏸️ **暂停讨论**：主人说"先别动手"/"我再想想"
4. ❌ **拒绝任务**：违反论衡适用边界

**禁止**：未经 Phase 0 直接 spawn 子代理

---

### 0 条空卡协议（v2.1.8）
**适用场景**：T6 案例检索员检索结果为 0 条

**输出格式**：
```markdown
## [C-空] 案例检索结果（0 条）

**检索简报**：
- 检索关键词：xxx
- 检索范围：xxx
- 结果：0 条
- 原因分析：xxx
```

**后续流程**：主控读取 `[C-空]` 后告知主人，询问是否需要：
- 调整检索策略
- 主人投喂案例
- 不使用案例

---

### 三检索员并行独立运行（v2.1.8 核心架构）
**并行模式**：T1 ∥ T2 ∥ T6 任何量级必须独立 spawn

**互不干涉铁律**：
- T1 不产数据卡/案例卡
- T2 不产文献卡/案例卡
- T6 不产文献卡/数据卡

**触发条件**：T3 分析员在 T1 + T2 + T6 全部完成后才 spawn

---

### 修订回环 ≤2 轮降级（v2.2.0）
**规则**：
- 第 1 轮修订：正常流程（T5 审计 → T4 修订 → T5 复审）
- 第 2 轮修订：警告模式（主控提示"最后一轮"）
- 第 3 轮：自动降级为"人工介入模式"

**降级原因**：
- 防止无限循环（教训 #64）
- 强制人工决策介入（主人判断是否继续/终止/调整方向）

---

### 完成验证铁律（v2.1.3，教训 #46）
**主控收到子代理完成报告后，第一动作**：

```bash
ls -lh drafts/[产物文件]  # 验证文件存在 + 非空
grep -c "关键特征" drafts/[产物文件]  # 验证内容完整性
```

**不采信报告**：T4 写手两次"报告完成但未写盘"事故触发此铁律

---

### 执行韧化协议（v2.1.0）
**四层防御**：

1. **心跳机制**：每 30 秒一次心跳 ACK
2. **分阶段 ACK**（3 档）：
   - 短任务（<3 分钟）：不需要
   - 中任务（3-8 分钟）：1 次中途 ACK
   - 长任务（>8 分钟）：多次 ACK
3. **模型健康度预检**：spawn 前 1-token ping（30s 无响应降级 fallback）
4. **8 分钟硬卡**：6 分警告 / 7 分 partial / 8 分 kill

**Fallback 链**（4 档）：
```
deepseek-v4-pro → minimax-M3 → deepseek-v4-flash → glm-5.3
```

## 十一、关键术语

### 主控 vs 子代理
- **主控**：T0，流程编排者，不替代子代理执行具体工作
- **子代理**：T1-T8，专项任务执行者

### spawn vs yield
- **spawn**：主控通过 `sessions_spawn` 创建子代理
- **yield**：主控通过 `sessions_yield` 挂起等待子代理完成

### 真源 vs 副本
- **真源**：论衡工作区 `~/.openclaw/workspace-paperwriter/pipeline/`
- **副本**：ClawHub skill ZIP / GitHub 仓库

### 蒸馏 vs 压缩
- **蒸馏**（Distillation）：从日记忆提炼长期记忆（有损压缩）
- **压缩**（Compact）：减少重复内容（无损压缩）
