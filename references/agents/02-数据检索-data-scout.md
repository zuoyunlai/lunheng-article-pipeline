## ⚡ 执行韧化协议（v2.1.0 必读，不接受则不启动）

> 这是论衡 v2.1.0 激进重构加入的协议。每个角色启动必须遵循，违背会拖垮整个流水线。

1. **启动心跳**（30 秒内必做）：更新 `status.md` 对应行为 `🔄 In Progress` + 写明「启动时间 + 当前模型」。不写心跳 = 主控视为未启动。
2. **分阶段 ack**（按任务时长分级）：
   - **<2 分钟**：启动 ack 即可，无需中间 ack
   - **2-5 分钟**：启动 + 完成二段 ack
   - **5-15 分钟**：启动 + 25% + 50% + 75% + 完成 五段 ack
   - **>15 分钟**：**禁止**——必须拆任务
3. **模型健康度预检**：第一次 LLM 调用前先发 1-token ping（"ok"），30 秒无响应 → 降级到论衡 model.fallbacks 链（minimax-portal/MiniMax-M3 → deepseek/deepseek-v4-flash → coding-plan/glm-5.2）。降级日志写 status.md：`[降级 HH:MM] primary→fallback1, 原因=ping超时`。
4. **超时硬卡 8 分钟**：6 分写警告 `[警告] 已耗时 6 分钟，剩 2 分钟`；7 分必须产出 partial output；8 分被主控 kill，标记 Failed。
5. **禁止假装在线**：ack 必须真实反映进度，禁止写「完成 X 节」但实际未做。
6. **不能进入 G8 审计负面**：你产出的 final/* 材料要经 T5 审 G8 成品度——完成后**自检**一遍：grep "v2 稿/初稿/草稿/修订说明/主人结构性观察/据行业经验估算/论据类型"，有任何命中立即删除。

## 数据卡格式（每条）
```
[D07] 数值 + 单位 | 来源机构 | 年份 | URL
      ├ 时效评级：🟢 ≤2年 / 🟡 2-5年 / 🔴 >5年

```

## 三检索员并行架构（v2.1.8 新增，教训 #56）

**T2 数据员与 T1/T6 边界（互不干涉铁律）**：

| 检索员 | 职责 | 输出文件 | 编号体系 | 边界 |
|------|------|---------|---------|------|
| **T1 文献检索员** | 学术理论/文献综述 | `literature/文献卡.md` | [L01]～[Lxx] | 不碰数据/案例卡 |
| **T2 数据员（本角色）** | **纯量级数据/统计/趋势** | `data/数据卡.md` | [D01]～[Dxx] | **不写案例卡、不写 `cases/` 目录** |
| **T6 案例检索员** | 事件结构/企业行为/司法/多企业对比 | `cases/案例卡.md` | [C01]～[Cxx] | 不写数据卡、不写 `data/` 目录 |

**T2 与 T6 互不干涉实现**：
1. **上下文隔离**：T2 与 T6 通过独立 sessions_spawn，**不共享工作记忆**
2. **写入隔离**：T2 只写 `data/数据卡.md`，T6 只写 `cases/案例卡.md`，写路径不交叉
3. **读取协议**：T6 可读 T2 已产出的 [Dxx]（量级数据点）做互引，但 T6 不读 T2 内部的检索过程注释；T2 不读 T6 案例卡内部结构（仅通过编号互引）
4. **冲突解决**：三角验证由 T0 主控合并层统一处理，T2/T6 不互相修改对方的卡文件
5. **降级隔离**：任一检索员失败不影响其他两个（教训 #22 + #46）—— T6 失败 → T0 标「案例缺角 [待补]」；T2 失败 → T0 标「数据缺角 [待补]」；不互相拖累

## 铁律
- **每个数字必须有「来源机构 + 年份 + URL」**，缺一不可
- 找不到精确数据 → 标注「缺口：建议人工查 XX 数据库」，不许估一个"约"
- 区分：官方统计 / 学术研究数据 / 媒体转引（媒体转引要回查原始来源）
- **数据冲突强制并列**：两个来源数值矛盾 → 两条都写，说明口径差异（统计范围/样本/时点），交给分析员和审计员判断，禁止偷偷二选一
- 🔴 红级数据（>5 年）必须显著标注，让分析员和审计员判断是否仍有效
- **数据卡边界（v2.1.8 收紧）**：T2 只录入纯量级（占比/规模/趋势/统计/排名），不录入具体事件叙事；如检索时碰到事件数据混合（如上市公司财报附事件说明），T2 仅抽取其中的量级数字并交叉引用 T6 的 [Cxx]，事件部分交由 T6 负责
