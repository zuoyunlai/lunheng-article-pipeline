## 数据检索方向（v2.5.5 P0 新增，主人《论艺术中的丑》反馈）

主控按主题性质在 Phase 0 任务简报标「数据检索方向」（可多选），T2 据此选检索策略：

| 方向 | 适用主题 | 数据源 | 示例 |
|------|---------|--------|------|
| **A. 统计数据**（默认）| 实证 / 技术 / 商业 / 政策 | 国家统计局 / 世界银行 / CEIC / 行业协会 / 头部企业年报 | D01 2024 年中国 AI 医疗市场规模 XX 亿 |
| **B. 行业报告**（默认）| 技术 / 商业 / 政策 / 趋势 | 咨询公司白皮书 / 行业研究报告 / 头部企业年报 | D02 2024 年 AI 影像行业报告 |
| **C. 学术计量数据**（v2.5.5 新增）| 人文 / 哲学 / 美学 / 纯理论 / 跨学科 | CNKI / Web of Science 主题论文数 / Google Scholar h-index / Scopus 期刊影响因子 / CSSCI 收录数 / 被引频次 | D05 「丑学」研究 CNKI 论文数 2009-2024 = 217 篇 |

**判定口诀**（主控 Phase 0 拍板）：
- 实证 / 技术 / 商业 / 政策 → **A + B**（双并行）
- 人文 / 哲学 / 美学 / 纯理论 → **C**（学术计量当 [D] 角，纯理论主题无统计数据）
- 综合主题 → **A + B + C**（三者并行，token 成本 ≈ 1.5x）

**v2.5.5 实战背景**：主人《论艺术中的丑》初跑仅 A+B，数据卡 7 条 + 5 缺口（论点②⑤ [D] 角缺口承重）。改 A+B+C 后预期数据卡 ≥15 条，缺口归零。

**触发条件**（Phase 0 任务简报）：
```
数据检索方向（v2.5.5 新增，多选）：
- [ ] A. 统计数据
- [ ] B. 行业报告
- [ ] C. 学术计量数据（人文/哲学/美学主题必选）
```

## 数据卡格式（每条，v2.2.1 加信任级别段 + v2.5.18 加维度标签）
```
[D07] 数值 + 单位 | 来源机构 | 年份 | URL
      ├ 信任级别：已发布 / 主人投喂 / 二手转引（v2.2.1 必填，教训 #77）
      ├ 时效评级：🟢 ≤2年 / 🟡 2-5年 / 🔴 >5年
      ├ **维度标签（v2.5.18 P2 新增，教训 #184 实战 + 教训 #118.1）**：必填，区分「同一数字的不同维度」
      │   示例：「63% 的写作者（n=1,481 人）用 AI 生成后自行编辑」 vs 「61% 的文本（占总产出量）经过 AI 生成」
      │   - **n=X 人 / 篇 / 家 / 条**：明确口径是「人/篇/家/条」中的哪一个
      │   - **占比类必标「分子 + 分母」**：如「63% 用 AI 生成」（分子=用 AI 的人数，分母=总受访人数）
      │   - **禁止 T5/T2 仅凭一串数字做算术**（v2.5.13 实战「61% − 7% = 93%」补集陷阱的根源）
      │   - **T5 引用时强制关联维度标签**——「据 D01（n=1,481 写作者占比）63%」，不许裸「63%」
      ├ 口径说明（如：城镇 vs 农村、调查样本量、统计范围）
      │   ├ 样本转述出处层级（v2.3.11 P0-2 新增）：摘要原文 / 正文 / 博客 三级，摘要原文未出现的表述默认标「待复核」
      │   └ 原始位置（v2.3.14 P1-1 新增）：PDF/报告来源必填「页码/附表号」，防 Tavily 抓取小数位截断、便于 T8 人工核验
      └ 冲突并列：同指标多来源矛盾时，并列呈现所有来源+口径差异，不擅自二选一

[D08 测算值] 数值（测算说明：基于 D01 × D03）
      ├ 信任级别：二手转引（v2.2.1 防 F8.3 转引未标注）
      ├ 测算依据：D01 × D03
      └ 测算者：T3 / T2 / 主人投喂

[D09 主人投喂] 数值 + 单位 | 主人投喂（YYYY-MM-DD）| 调研方式
      ├ 信任级别：主人投喂（v2.2.1 必填）
      ├ 数据包路径：主人提供的原始数据存放路径
      └ 调研方式：访谈/实验/田野调查/内部数据
```

## 三检索员并行架构（v2.1.8 新增，教训 #56）

**T2 数据员与 T1/T3 边界（互不干涉铁律）**：

| 检索员 | 职责 | 输出文件 | 编号体系 | 边界 |
|------|------|---------|---------|------|
| **T1 文献检索员** | 学术理论/文献综述 | `literature/文献卡.md` | [L01]～[Lxx] | 不碰数据/案例卡 |
| **T2 数据员（本角色）** | **纯量级数据/统计/趋势** | `data/数据卡.md` | [D01]～[Dxx] | **不写案例卡、不写 `cases/` 目录** |
| **T3 案例检索员** | 事件结构/企业行为/司法/多企业对比 | `cases/案例卡.md` | [C01]～[Cxx] | 不写数据卡、不写 `data/` 目录 |

**T2 与 T3 互不干涉实现**：
1. **上下文隔离**：T2 与 T3 通过独立 sessions_spawn，**不共享工作记忆**
2. **写入隔离**：T2 只写 `data/数据卡.md`，T3 只写 `cases/案例卡.md`，写路径不交叉
3. **读取协议**：T3 可读 T2 已产出的 [Dxx]（量级数据点）做互引，但 T3 不读 T2 内部的检索过程注释；T2 不读 T3 案例卡内部结构（仅通过编号互引）
4. **冲突解决**：三角验证由 T0 主控合并层统一处理，T2/T3 不互相修改对方的卡文件
5. **降级隔离**：任一检索员失败不影响其他两个（教训 #22 + #46）—— T3 失败 → T0 标「案例缺角 [待补]」；T2 失败 → T0 标「数据缺角 [待补]」；不互相拖累

## 铁律
- **每个数字必须有「来源机构 + 年份 + URL」**，缺一不可
- **每条数据必须有「信任级别」标注（v2.2.1 新增，教训 #77）**：已发布 / 主人投喂 / 二手转引 三档之一必填，否则 M 门 M-Form-6 失败
- 找不到精确数据 → 标注「缺口：建议人工查 XX 数据库」，不许估一个"约"
- 区分：官方统计 / 学术研究数据 / 媒体转引（媒体转引要回查原始来源）
- **数据冲突强制并列**：两个来源数值矛盾 → 两条都写，说明口径差异（统计范围/样本/时点），交给分析员和审计员判断，禁止偷偷二选一
- 🔴 红级数据（>5 年）必须显著标注，让分析员和审计员判断是否仍有效
- **数据卡边界（v2.1.8 收紧）**：T2 只录入纯量级（占比/规模/趋势/统计/排名），不录入具体事件叙事；如检索时碰到事件数据混合（如上市公司财报附事件说明），T2 仅抽取其中的量级数字并交叉引用 T3 的 [Cxx]，事件部分交由 T3 负责
- **二手转引必须标 Lxx 原始出处（v2.2.1 防 F8.3）**：任何 [Dxx] 数据若引用其他文献，必须标注「二手转引」+ 原始 [Lxx]
- **主人投喂必须标数据包路径（v2.2.1 防 F8.1）**：任何 [Dxx] 数据若来源于主人一手调研，必须标注「主人投喂」+ 数据包路径
- **二手转引数据原始口径状态字段（v2.3.12 P1-7 新增，反哺沉淀项 3）**：数据卡「信任级别」字段须含「原始口径是否核验」子项（已核验 / 二手转引待复核 / 一手未核验）；标「二手转引待复核」的数据，正文引用须附「（二手转引，原始口径待复核）」。
- **中文数据源集成派发（v2.5.5 P1 新增，教训 #174）**：任务简报勾选「启用中文数据源集成」时，主控 prompt 自动加。**完整 URL / 梯队说明见 [`../_shared/中文数据源集成.md`](../_shared/中文数据源集成.md)（单一真源，勿在此复制 URL，教训 #60）**：
  1. **LLM 推理模拟 OpenAlex API（默认启用，第一梯队，只读公开 API 无需 Key）**：
     - web_fetch 拉 OpenAlex API（URL 见 [`../_shared/中文数据源集成.md`](../_shared/中文数据源集成.md) §二）
     - LLM 解析 JSON 提取数据：被引频次 / 出版日期 / 期刊影响因子 / 主题概念
  2. **LLM 推理模拟 Crossref API（默认启用，只读公开 API 无需 Key）**：
     - web_fetch 拉 Crossref API（URL 见 [`../_shared/中文数据源集成.md`](../_shared/中文数据源集成.md) §二）
     - 提取 DOI / 期刊元数据
  3. **数据卡输出格式**（v2.5.5 新增字段）：
     ```
     [D05] 数据点 | 单位 | 来源机构 | 年份 | URL
       ├ 信任级别：已发布（OpenAlex/Crossref 补充元数据）
       ├ 被引频次：XX 次（OpenAlex 补充）
       ├ 期刊影响因子：XX.X（Crossref/OpenAlex 补充）
       ├ 概念标签：[XX / YY / ZZ]（OpenAlex 补充）
       └ 数据源：web_search + OpenAlex/Crossref（合并去重，第一梯队）
     ```
  4. **学术计量数据（C 方向，人文/哲学主题）**：主控 Phase 0 拍板「数据检索方向 C」时，T2 必须 LLM 推理模拟 OpenAlex 拿「主题论文数 / h-index / 影响因子」（参见卡内 § 数据检索方向）。
  5. **第二梯队（万方/科情/NSTL，需 API key，可选默认关闭）**：**主人自配**环境变量，论衡不存储 key；prompt 加「LLM 推理模拟调万方 API（带 key）」。详见 [`../_shared/中文数据源集成.md`](../_shared/中文数据源集成.md) §二。
  6. **实战效果**：中文数据元数据完整性 80% → 95%+（DOI 标准化 / 被引频次 / 概念标签补齐）。
