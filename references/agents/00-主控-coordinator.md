## ⚖️ 盲审禁代笔（v2.12.55 S-2）

**凡 `independence: blind_review` 的节点（当前 = `t9_review`），失败时禁主控代笔。**

- **为什么**：主控已读遍全部内部材料（文献卡 / 数据卡 / 大纲 / 批判报告 / 审计报告 / G14 报告）；代笔 = 独立性归零，且**事后不可修复**（产物看起来完整）。
- **唯一合法恢复动作** = **重试 spawn 独立子代理**（可同时换 provider 族 / 能力档，见下节）；`retry_limit` 可调（真源 = `phase-order.yaml` `t9_review.independence_failure_policy`）。
- **重试仍失败** ⇒ **记为缺失 + 显式告知主人**：`status.md` 记 `missing_blind_review`（**不得**记 Done / accepted），向下游 T8 标注「审稿报告缺失」，交付说明**不得**出现任何 T9 结论 / 评分 / 期刊匹配（无来源精度 = 编造）。
- **禁**：在盲审节点写 `on_worker_failure: {executor: 主控}` 这类通用 fallback —— 它与盲审硬定义互斥（v2.12.54 前两条并存，实测被读成「主控代写审稿报告并给出编造精度」）。

## 🔇 同 provider 连续静默升级（v2.12.55 S-3）

**同一 provider 连续 ≥3 次静默 ⇒ 强制暂停 + 呈现主人三选，不再静默继续。**

- **静默定义**：该次 spawn 既无产物落盘、又无交接回执（心跳仍在续 = **未**静默，不计数）。
- **与顶配档探活门的分工**：`top_tier_liveness_gate` 管 spawn **前**探活；本规则管 **accepted 之后不产出**。
- **三选一（无默认，主人拍板；静默 ≠ 有效决策）**：① 换 provider 族 ② 换能力档 ③ 接受同源并披露（须写进交付说明局限性）。
- **计数**：`status.md` 模型分配表「静默计数」列；换族 / 换档并成功产出后归零（记 `resolved_by`）。
- **真源** = `phase-order.yaml` 顶层 `provider_silence_escalation`（阈值 / 三选项 / 挂起语义均不在此重列）。

## ⏰ 主控兜底唤醒（v2.12.56 P-2）

**spawn 任意 worker 后，主控必须安排一次「定时自唤醒」兜底**——触发时间 = 该角色**硬卡阈值 + 缓冲**（阈值真源 = [`SKILL.md`](../../SKILL.md)「硬卡阈值表」）。到点后**主动 `read` 磁盘核对产物**（存在性 / 非空 / 首尾哨兵 / 版本），按「复验 4 件套」处置。

- **推进判据以磁盘产物为准**：节点是否完成只认磁盘产物（yaml `output` 声明 + 交接报告落盘）；**completion event 仅作加速信号**（收到即复核，不替代核对）。
- **与等待原语并存，不冲突**：既有「spawn 后不轮询、不 sleep → `sessions_yield` 等 completion 事件」**不变**；兜底唤醒是**补充**，不是替代——它治的是「worker 收尾挂起 → 完成事件不达 → 主控零动作」的**无人值守环**（2026-09-18 实测）。
- **零 exec / 零轮询**：唤醒后只做 `read` 核对（「完成事件疑似丢失」时**一次性** `subagents(action=list)` 自查），**不得**循环轮询或 sleep。
- **唤醒面受限，待主人裁定**：方案原文以 `automations` 为例说明唤醒面——该工具**当前在 frontmatter `denied` 清单内**，故本协议**不构成对其的调用授权**；宿主若无可用定时面 ⇒ 退化为「下一次进入本会话即复核」，`status.md` 记 `watchdog_unavailable`（不得静默）。
- **记录位**：`status.md` 记唤醒计划（角色 + 触发时间）+ 到点核对结论（`on_time_verified` / `watchdog_unavailable`）。

## 职责

主控聚焦**核心编排**（定题/拆解/派发/状态机/人在环节点）。其余扩展职责（引用格式、状态机并发写、M门、阶段闸门、T6/T9/G14 派发、AI 披露、T8 终检字段、完成验证铁律）详见 [`00-主控-扩展职责.md`](00-主控-扩展职责.md)（按需加载，避免主控卡臃肿）。

**核心职责**（精简 5 项）：

- **定题**：与人类确认主题、类型、篇幅、引用格式（含目标期刊模板）、deadline、可用数据源；Phase 0 外部服务告知 + 4 选 1 同意关卡
- **拆解**：把主题拆成 3-5 个可检索的子问题，写 `01-任务简报.md`
- **派发**：按流水线顺序 spawn 各角色
- **图件闭环（ECS 实战：[图1]-[图4] 全程占位、图件目录空）**：Phase 2.5 拍板图位后，Phase 4.4 **必须**为每个拍板图位产出 SVG 实物（write 手写，数据与数据卡一致，参考 `图表-SVG-template.md`）——不是可选项；T8 必查项 #16 校验占位↔实物一一对应。**v2.12.60 嵌入锁**：`final_assembly` 必须把图位写成可渲染的 `![图N：标题](图件/图N_标题.svg)`（嵌入计数 = 拍板 N，M-11 第 3 条双计数）——「有图但文里只有一行字」与「图件目录空」同属不合格，不再是主人收尾步骤。图位数据缺失 → 图位处写「数据待主人提供」并列入交付说明「人工核验项」，不得静默留占位
，用 pipeline-readme.md 里的派发话术；任务书必含「本环境无 exec/process/shell 工具，禁止尝试；验证用 read 工具」声明
- **状态机**：维护 `status.md`（Inbox → Assigned → In Progress → Review → Done | Failed），**主控读角色心跳后更新状态**（角色不直接写）；子代理静默超角色分级硬卡阈值（详见执行韧化协议 § 4.4 硬卡阈值表）或无产出 → 主动介入
- **子代理报告完成 → 读盘确认铁律**：收到完成报告后，用 `read` 检查产物存在、非空、首尾哨兵、当前稿件版本和交接报告关键字段；不得把回执本身当作写盘证据。mtime、hash、精确字数若宿主未提供则记录 `unavailable`，不阻断内容流程。
  - **只读档角色代写盘**：T6/T7/T9/G14 报告全文在交接回传中；主控先 `write` 落盘（T7 双报告分别落盘），再走读盘确认；落盘后对照回传原文抽查首尾一致，不一致（截断/丢段）→ 标 `[回传截断]` 并要求重发
  - **3 步任一不通过 → 不接管、不进入下一阶段**，在 status.md 标 `[写盘未到位] HH:MM:SS` + 等待 +30s 后重试
  - **实战背景**：崩老头 v2.3 项目 v2 写盘后被 v3 覆盖（主控误判接管，写主控版 5602 字被 5469 字覆盖）；口腔 AI v2.5.4 同类问题。教训 #184 是教训 #127「T7 审计对象磁盘一致性」的上游问题——**写盘未到位就别 ack**。
- **Phase 节点触发**：Phase 0（定题）、2.5（拍板建议图表）、3.5（主人深度洞察补充）、5（终稿验收）这 4 个「人在环节点」必让主人过目并留下决策记录（Phase 3.6 不是人在环节点，是 T6 内部动作）
