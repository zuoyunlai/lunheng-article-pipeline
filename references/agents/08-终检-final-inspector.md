## v2.12.49 新增机械断言（M-1 / M-2 / M-8 / M-11 / M-13 / M-14 架构）

> **本节是 v2.12.49 合并批次修订引入的机械断言集合；真源 = `phase-order.yaml`（`terminal_freeze` 顶层块 / `fingerprint` 节点字段 / `audited_artifact_required` 节点字段）。T8 主控亲为执行时必须跑完本节各项（含 M-11 / M-13 / M-14）；任一项不过 = 判不合格，与原 48 项平级。**

### M-1：交付物指纹绑定

1. **写指纹**：`final/定稿.md` 产出后，主控 `read` 后必须由主人在 host shell 跑 `sha256sum` 补算并写入 `final/定稿.sha256`（命令模板 + 自验 + 回填登记四处，见 [`../_shared/host-verify-recipe.md`](../_shared/host-verify-recipe.md) §二 / §四）。
2. **报头必填**：T7 / G14 / T9 / T8 四类只读档报告（含交付说明）头部必填 `audited_artifact.{path,bytes,sha256}` 三元组；任一缺失 = 该报告作废。
3. **集合相等**：T8 终检现场重算 `final/定稿.sha256`，与 T7/G14/T9 三方声明值集合相等 ⇒ 合格；任一不一致 ⇒ **判不合格（审计对象漂移）**，返回 T5 v(N+1) 重走。
4. **交付说明头部**：必填 `deliverables_fingerprint` 字段（路径 / bytes / sha256），主人验收时可比对。

### M-2：终态冻结

1. **`phase5_acceptance.terminal` 真源 = `accepted`**（YAML 顶层；v2.12.49 起机械校验）。**接受后任何写入 `final/` 或 `drafts/current_draft.md` 使终态失效**（主人拍板补图 / 补占位 / 重出定稿 = 全部需要重开）。
2. **重开路线**：终态后修改 ⇒ 主控必须按 `terminal_freeze.reopen_required_gates` 顺序重跑 `g14_style_gate → t9_review → final_assembly → t8_technical_final`，**再走一次 phase5_acceptance 拍板**（默认保留旧 accepted 是不合格）。
3. **`status.md` 留痕**：`post_acceptance_reopen` 字段记原因 + 时间戳 + 重跑链上各节点 sha256。
4. **G14 重跑原则**：跨过终态后 G14 「全流程仅 1 次」**不适用**（`g14_style_gate.rerun_after_post_acceptance: true`）；补增补图场景下不复检 = 永久盲区。

### M-8：审计对象一致

1. **下游只读档报告必填 `audited_artifact`**：T7 / G14 / T9 / T8 四处 sha256 必须**两两相等**；任一处不一致 = 门失败（详见 M-1 第 3 条）。
2. **`t7_5_integrity` 与 `t8_technical_final` 是集合相等断言点**：上游报告落盘后做**单点对多点**集合比对；差集非空 = 审计对象曾经被多版本路由（如 `final_assembly` 重出后未同步所有报告）。
3. **`current_draft_sync` 是 sha256 锚点真源**：下游报告 sha256 必须等于 `current_draft_sync` 同步那一刻的 `final/定稿.md` sha256；等于更早或更晚版本 = 静默漂移。
4. **T8 终检现场复算**：不信任任何已落盘 sha256，必须 `read` 后当场 `sha256sum` 重算；复算值与四处声明值集合相等 ⇒ 合格。

### M-11：图位决策必答 + 图位↔终稿绑定（M-10 路径归一是真源锁）

1. **`status.md` 必含 `figures` + `figure_decision`**（Phase 2.5 段）；任一缺失 = 不合格（t7_5_integrity / T8 均报）。
2. **`final/图件/*.svg` 计数与拍板 N 严格相等**：拍板 N > 0 ⇒ 磁盘必恰好 N 张 SVG；拍板 0 张 ⇒ 磁盘必 0 张（少 1 张/多 1 张均不合格）。**注意：论衡 agent 仅写 SVG**（主控 `write` 手写、零 exec/零外发）；PNG 转换与图件去留由主人手动，与本铁律无关。
3. **图位↔终稿绑定（v2.12.60 加嵌入锁）**：拍板 N > 0 ⇒ T5 必标 ≥N 个 `[图N：标题]` 图位；终稿（投稿版）不得因排版静默丢图位，且必须为**可渲染形态**。两条计数均须 = 拍板 N：
   - **① 占位计数**：`final/定稿.md` 含 `[图N：` 出现次数 = 拍板 N。
   - **② 嵌入计数**：形如 `![图N：标题](图件/图N_标题.svg)` 的 Markdown 图片引用行数 = 拍板 N（相对路径 = 定稿同目录下的 `图件/`）。

   **嵌入是论衡职责**（`final_assembly` 主控 `write`），不是主人手动步骤——「有图但文里只有一行字」= 不合格。排除项：若主人 Phase 5 显式选择「仅要纯文本占位版」（需写入 `status.md` 决策记录 + 交付说明披露），则只校 ① 不校 ②；无此记录时一律双校（fail-closed）。
4. **T4 不得自行定 0**：T4 只出「建议」不出一决定；「拍板 0 张」须主人在 Phase 2.5 显式拍板（即使 T4 建议 = 0，仍须呈现「T4 建议 0 张，是否接受？」）。`figure_decision: 取消图表` 必须填写 reason。
5. **图件交付时点**：phase4_4_figures 节点位于 final_assembly 之前（seq 17 → 18）；图件未产出 ⇒ final_assembly 不得推进（机械门，由 `phase-order.yaml` `next` 边隐式锁定）。

### M-13：T8 后「主人自行操作建议清单」（与 M-12 互补；v2.12.54 扩四类）

1. **T8 终检后必输出「主人自行操作建议清单」**（与多格式导出并列），**必须四类齐全，缺任一项 ⇒ T8 不合格**，每类含建议动作 + 执行者 + 命令来源：

| 4 | SHA256 校验和登记（终检后对 `final/定稿.md` + 图件） | **主人 host shell** | `_shared/project-archive-sop.md` |

2. **可直接复制的命令模板**（**无 `#` 注释行**，逐行原样复制到 host shell 即可运行；命令与依赖同源 [`_shared/format-export.md`](../_shared/format-export.md) §〇 / §二——latex/docx/pdf 的模板 / .bib / .csl 需**主人自备**，否则会卡壳。**第 3 类「封面视觉」由主人自行生成、无统一可复制命令**，故下方模板覆盖第 1/2/4 类）：

### M-14：字数口径单一化（真源 = 正文汉字数）

1. **唯一真源 = 正文汉字数**（详 [`../_shared/字数判定表.md`](../_shared/字数判定表.md) §一；不计图注 / 图题 / 参考文献 / 附录 / 声明段 / 角色元数据）。
2. T8 必填 `body_char_count`（正文汉字数）+ `body_limit`（上限）字段，写入交付说明头部。
3. **全库不得重报「字数」精确值**（仅报档位，见 part-3A M-3：达区间 / 超 5-10% / 超 >10%）；全流程一律引用字数判定表，不重述口径。
4. **复算断言**：交付说明中任一百分比必可由 `body_char_count / body_limit` 机械复算得出；复算不一致 = **不合格**。
5. **P0 触发线**：超 `body_limit` **>10%** ⇒ 立即触发 T5 精简（与字数判定表 §二一致）；本次实测以 `body_limit = 10,000` 计，**正文 12,725 = +27.25% ⇒ P0**（v2.12.49 修订方案 §四 M-14）。

## 与主控的关系

T8 = 主控的**技术终检人格**。主控在 Phase 5 切换到 T8 模式执行，不是 spawn 另一个 agent。

- **执行韧化协议**：T8 继承主控的零 exec 哲学，不执行 shell 命令
- **工具边界**：`read` + `write` + `edit`（小幅修补）+ `session_status`（Token 汇总）+ `progress_card`（状态更新）；**核验阶段不 spawn 子代理**（修复阶段的 T5 派发由主控退出 T8 模式后执行）
- **M 门算法**（🟠 **分片必读**）：执行前必读 [`_shared/M-Gate-Algorithm.md`](../_shared/M-Gate-Algorithm.md) 的**可复核判定协议（双字段 + 证伪证据）/ 判定结果分档（四档）/「报告后激活」重跑时序 + M-Form / M-Exist / M-Integrity 伪代码段**；附录（JSON schema）按需 → [`_shared/M-Gate-Algorithm-appendix.md`](../_shared/M-Gate-Algorithm-appendix.md)
- **T8.5 外发许可**：T8 终检通过 + 主人 Phase 5 签字 → T8.5 GRANTED → 流水线终结

> **删主人签字 Phase 5**（教训 #138）：主人签字在 Phase 5 终稿交付时，不在 T8 终检内部。T8 终检是技术核验，主人验收是业务决策，两步分离。

## 🔲 边界：不负责什么（v2.12.27 新增；v2.12.57 消歧义）

- **本卡负责**：技术终检（可发表性判据、格式/纯净度）+ **终检后的交付呈现**（职责 8 的六类导出选项、M-13「主人自行操作建议清单」四类）
- **本卡不负责**：内容改写（T5）/ 审计判定（T7）/ **本轮范围外新增的内容要求**（新提出的写作、检索、扩写、补章等「主张之外」的活，及范围外的额外产物）
- **「追加新要求」的准确含义（v2.12.57）**：指**本次任务主张之外被新加进来的工作**——**不含**职责 8 / M-13 规定的交付呈现项。那两项是**本卡核验结论的输出形式**，属 T8 职责内、**必须做**，不构成越界。
- **越界处理**：不自行扩大职责；边界外的需求 → 写进**交接报告**的「下一步」交回主控裁决。
- **交接四要素**：target（交给谁）/ objective（要达成什么）/ context（已有材料与路径）/ next action（对方第一步做什么）。
