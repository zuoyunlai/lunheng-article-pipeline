## 主人深度洞察素材

主人在 Phase 3.5 提供的亲身经历/观察，可作为案例素材以 `[C-主xx]` 编号进入正文。每个洞察独占一行，注明出处 + **类型**（必须二选一）：

- **[C-主01]**：（主人原话/观察描述） ｜ **类型**：[观点来源 / 理论贡献]
- **[C-主02]**：（主人原话/观察描述） ｜ **类型**：[观点来源 / 理论贡献]
- ...

**两种类型的区别**（明示化）：

| 类型 | 定义 | 写手引用策略 | 示例 |
|------|------|-------------|------|
| **观点来源** | 主人亲身观察 / 业内判断 / 从业经验 | 作为「业内观察」引用，写明「据主人从业观察/业内经验」，不当作实证数据用 | 「主人『我接触过的教师很市例精明』」 |
| **理论贡献** | 主人的原创框架 / 结构性判断 / 新提法 | 作为「本文提出的框架」引用，**不是论据是论点**，写手需发展论据支撑 | 主人「五方合谋」框架 → 写手需展开五方各自实证支撑 |

**注意**：① [C-主xx] 不进入 cases/案例卡.md（独立编号空间）；② 终稿文末「案例来源」节需为每个 [C-主xx] 留 1 条「主人深度洞察」说明（含任务简报第 X 行出处 + 类型）；③ 主控融合时需按写手卡「主体声音 ≠ 第一人称经历」铁律客观化处理（详见设计文档 原创性保证 + 写手卡视角与精度铁律）；④ **类型必须在 Phase 3.5 由主人明确标注**——主控不可默认推断，因为「理论贡献」+「观点来源」的边界很微妙，主人最清楚。

**洞察-数据一致性预检（教训 #280）**：主人洞察里若引用了具体数据（如「中国 61% 监管信任」），主控在 Phase 1 检索后必须**回查该数据是否可被检索到**——若不可检索/不可验证 → 标 🔴，T4 分析员准备替换为可检索数据（或让主人补充数据出处）。**防止主人洞察里的「引文锚」是不可验证数据 → 写手误当硬数据引用 → T6 攻击「数据无源」**。

## 心跳要求（写到任务简报后由主控+角色同步执行）

每个角色启动 30 秒内写自己的心跳文件 `run/<项目名>/.tmp/<两位角色号>-<角色名>-heartbeat.md`（状态=`🔄 In Progress` + 启动时间 + 当前模型）；**status.md 由主控独占更新，子代理不直接写**。5-15 分钟任务必走 4 段 ack（25%+50%+75%+100%），写手/审计员尤其重要。模型降级/主控介入/失败必须写明时间+原因。

**主控介入标准动作（6 步）**：
1. 查 status.md 是否含心跳/ack（缺失 = 没遵循协议 → 拍醒子代理）
2. 用 sessions_history 看子代理最近输出（判断真卡还是模型思考中）
3. LLM 可用性问题 → 手动 kill 会话，手动 spawn 新子代理（指定下一档 fallback 模型）
4. 产生物到中途中断（partial output 存在）→ 接受现有产出，手动补齐缺失部分
5. 在 status.md 阶段行写明介入记录：`[介入 HH:MM] 主控介入, session-kill, 重派 model=fallback1`
6. 同场景「换档」重派 ≤2 次（**非**「重跑同一任务」），仍卡 → 升级主人决定
