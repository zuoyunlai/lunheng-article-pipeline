# 检索覆盖矩阵（Coverage Matrix）

> **用途**：解决三个并行检索员「各查各的」导致的子问题集体漏检问题。Phase 0 主控与主人拍板时，把主题拆解为 3-5 个**核心子问题**，并标注每个子问题需要哪类证据支撑。T1/T2/T3 按矩阵分工检索，产卡完成后主控按矩阵对账，未覆盖格位显式标注。

> **位置**：`run/<项目名>/analysis/检索覆盖矩阵.md`

> **初始化时机**：Phase 0（主控拆题后、spawn T1/T2/T3 之前）

> **对账时机**：Phase 1 三方交接完成后（主控执行）

## 矩阵结构

| 子问题 | 需文献 [L] | 需数据 [D] | 需案例 [C] | 最低条数 | 文献缺口 | 数据缺口 | 案例缺口 |
|---|---|---|---|---|---|---|---|
| SQ1（例：AI 对中层管理者的替代效应） | 是 | 是 | 是 | L≥3 / D≥2 / C≥2 | — | — | — |
| SQ2（例：工作流重构对组织层级的影响） | 是 | 是 | 否 | L≥3 / D≥1 | — | — | — |
| SQ3（例：中国企业实践与全球差异） | 是 | 是 | 是 | L≥3 / D≥3 / C≥2 | — | — | — |

## 填写规则

1. **拆题规则**：子问题数量 3-5 个。少于 3 个说明拆题太粗（无法检验覆盖）；多于 5 个说明太细（检索成本失控）。
2. **最低条数**：每个「是」格位须标最低条数（推荐 L≥2、D≥1、C≥1，主题需要强证据链时上调）。主控 spawn 时把对应格位要求写入各检索员的任务简报。
3. **否格位**：标「否」的格位不要求检索；若检索员仍检索到相关素材，属超额素材，登记但不强制引用。
4. **对账规则**：三方交接后，主控逐格核对：实际条数 ≥ 最低条数 → 标 ✅；低于最低条数 → 标「缺口：<原因>」。缺口原因分两类：
   - **客观缺口**（该证据确实不存在 / 数据库无此数据）→ 标「缺口：未检索到」并写入局限性章节。
   - **检索缺口**（换关键词/换数据库可补）→ 触发 **T1b 定向回查**补充检索。
5. **冲突仲裁**：对账时同步检查同指标多来源矛盾。对矛盾来源按 `数据冲突强制并列` 规则处理，不擅自二选一。
6. **矩阵冻结**：Phase 1 对账完成、缺口处置完毕后矩阵冻结，不再增删子问题。修订轮（Phase 4+）如需新增子问题，视为范围变更，须主控重新对账并留痕。

## 与既有机制的关系

- **与先行者清单**：先行者清单查「有没有人写过类似文章」，覆盖矩阵查「本文每个论点是否有证据」，两者互补不重复。
- **与三角验证**：三角验证是「论证时」的质量要求，覆盖矩阵是「检索时」的分工与验收基线，矩阵是三角验证的**事前合同**。
- **与 T1b 定向回查**：检索缺口（可补）时由主控派 T1b 补检索；客观缺口登记进局限性，不走 T1b。

## 主控操作步骤

1. Phase 0 拆题后，填写矩阵的「子问题 / 需 L/D/C / 最低条数」列。
2. spawn T1/T2/T3 时，把各自负责的格位写入任务简报（T1 只管 L 列、T2 只管 D 列、T3 只管 C 列）。
3. Phase 1 三方交接完成后，读取三张卡，逐格对账，填「缺口」列。
4. 有检索缺口 → 派 T1b 补检索（每子问题 ≤1 轮）；仍缺 → 客观缺口，写入局限性。
5. 冻结矩阵，进入 Phase 2。
