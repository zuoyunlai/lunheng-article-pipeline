# 论衡模板系统

> **定位**：论衡模板（`references/templates/`）按「精简版 + 完整版」两套分层，按场景按需加载。
> **本文件不复述模板数量**——模板清单以目录自证（`ls references/templates/*.md`），避免枚举式过时（历史上本文件曾写死「7 个模板」，实际已增至 21 个）。

---

## 一、模板分层原则

论衡模板按**两轴**分层：

| 轴 | 命名 | 用途 | 何时加载 |
|---|---|---|---|
| **详略** | `*-lite.md`（精简版） | 实战骨架 + 必填字段 | 每次项目必读 |
| | `*-template.md` / `*-full.md`（完整版） | 含字段详解 + 实战案例 + 错误模式 | 培训 / 审计 / 调试时按需读 |
| **职能** | 任务简报 / 数据卡 / 文献卡 / 案例卡 / 交接报告 / status / 先行者清单 / 审稿报告 / G14 检测报告 / 投稿就绪检查表 / 图表 SVG / checkpoint 卡 / 修订说明 | 各角色对应产物模板 | 由派发话术 / 角色卡指向 |

**实战中**：精简版必读 + 完整版按需（主人问「为什么这样」时读）。

> **目录自证**：上表「职能」列只是**命名约定示意，不是清单**。当前实际模板文件数 = `references/templates/` 下 `*.md` 的数量（含本说明文件）；新增 / 删除模板后无需改本文件。

## 二、精简版模板设计原则

### 2.1 只保留 3 类内容

1. **骨架结构**：markdown 标题层级（## / ### / ####）
2. **必填字段**：只列字段名 + 一句话说明（如「**主题**：xxx」）
3. **关键约束**：硬规则（如信任级别必填）

### 2.2 移除 4 类内容

1. ❌ **字段详解**：完整版有（如「什么是信任级别」）
2. ❌ **实战反馈**：完整版有（如「实战 2 中 14 条数据无信任级别」）
3. ❌ **错误案例**：完整版有
4. ❌ **历史版本说明**：完整版有

### 2.3 注释简洁

精简版的注释 ≤5 字（如「必填」「可选」「v2.2.1 新增」），让主控一眼看到结构。

## 三、完整版 vs 精简版 选择 SOP

### 何时用精简版（默认）

- ✅ 实战项目（Phase 1/2/3/4 任意阶段）
- ✅ 子代理 spawn 时的 task prompt
- ✅ 培训新人「先看精简版理解结构」

### 何时用完整版

- 🔍 主人问「为什么这里要填这个字段」
- 🔍 审计发现字段问题（如数据卡无信任级别 → 主控查完整版找原因）
- 🔍 模板维护（修改字段 / 加新字段）

## 四、token 节省口径

> **本文件不复述具体 KB / 节省比例**：模板数量与体积随内容演进，写死数字必然过时（本文件历史上就因此漂移）。需要量化时**现场实测**：

```
wc -c references/templates/*-lite.md          # 精简版总体积
wc -c references/templates/*-template.md      # 完整版总体积
```

节省量 = 完整版总体积 − 精简版总体积（按项目读取次数折算）。量化结论由 `pipeline-readme.md`「模板加载策略」段引用，不在此复制。

## 五、生成 SOP（新增精简版时）

1. 复制 `*-template.md` 为 `*-template-lite.md`
2. 删除「实战反馈」「错误案例」「历史版本」段
3. 字段注释压缩到 ≤5 字
4. 在精简版顶部加「> **精简版**：只保留骨架 + 必填字段，详细说明见完整版 `*-template.md`」
5. 在完整版顶部加「> **完整版**：含字段详解 + 实战案例。日常实战用精简版即可」
