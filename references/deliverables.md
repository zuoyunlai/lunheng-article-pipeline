## 交付边界（教训 #270，借鉴 vincentjiang06 paper-writer）

论衡的交付物分两类，二者**独立**：

1. **论文交付物**：`final/定稿.md` + `final/图件/`（可选，**T8 必查 SVG 嵌入文本孤儿**，见判定表 § 维度 5.4）+ `final/证据包/`
2. **操作员报告**：`final/交付说明.md` + `audits/审计报告-vN.md` + `audits/反哺报告-vN.md` + `audits/审稿报告-vN.md`（T9 启用时）

**核心原则**：

- 论文交付物 = **给读者的**（学术发表 / 投稿 / 公众号草稿）
- 操作员报告 = **给主人的**（质量复核 / 局限性告知 / 建议人工核验项）
- 操作员报告**不进入**论文交付物
- 反哺报告**不自动 commit**到角色卡

**论衡哲学化**：「论文是给读者的，报告是给主人的。混淆两者 = 失去信任」—— 借鉴 vincentjiang06 「A course paper carrying a ## 合规报告 section is no longer a course paper」论衡化表述。

## 定稿文末纯净规范（教训 #276）

> **背景**：v2.3.0 首次实战（ai-pilled vs agi-pilled）定稿文末混入「图表清单」「引用规范（四节闭环）」「主控签字（T8 终检）」三段操作员报告内容，且缺「先行者文献」节——「论文交付物 vs 操作员报告」边界混淆的实战案例。

**定稿文末白名单**（`final/定稿.md` 文末只允许以下 **6** 节，顺序固定）：

| 顺序 | 节 | 内容 |
|------|-----|------|
| 1 | `## 参考文献` | [Lxx] 学术文献 + 权威报告 |
| 2 | `## 数据来源` | [Dxx] 数据 + 可信度标注 |
| 3 | `## 案例来源` | [Cxx] 案例 + [C-主xx] 主人洞察 |
| 4 | `## 先行者文献` | [先xx] 原创性差异点声明 |
| 5 | `## 致谢` | 致敬理论奠基 + 制度实践 + 数据源（**可发表性 F 选项启用时必含**） |
| 6 | `## AI 使用声明` | 学术伦理披露（学术投稿必加） |

> **v2.12.32 修正（回应实测 P1）**：白名单**补入「致谢」**—— 可发表性 F 选项（默认启用）**强制要求** `## 致谢`，而旧白名单不含它 ⇒ **字面上必判 M-Form-7 违规**（自相矛盾）。`## 方法论附录`仍为可选（主人 Phase 5 勾选），属白名单外但**不判违规**的例外项（见 `M-Gate-Algorithm.md` 白名单数组注释）。

**禁止出现在定稿文末**（属操作员报告，移入 `final/交付说明.md`）：
- ❌ `## 图表清单` → 交付说明「图件清单」节
- ❌ `## 主控签字（T8 终检）」 → 交付说明「终检结论」节
- ❌ `## 引用规范（四节闭环）」等元说明 → 删除（是说明规范本身，非给读者的内容）
- ❌ 内部流水线信息（内部条目编号 / 模型 fallback 记录 / spawn 细节 / 审计过程）→ 交付说明

**M-Form-7 交付白名单门（教训 #139）**：本白名单规范是**规则硬性、判定由 LLM 执行**的必查项——T8 签字前必按 `_shared/M-Gate-Algorithm.md` **M-Form-7** 提取文末所有 `^## ` 节标题，白名单外任何一节即 P0 fail（用 read + 逐项比对完成，非机器强制）。**禁止在 M-Form-7 全过之前签「交付边界纯净」**（教训 #139：T8 签字走形式，文档层规范到执行层断链）。

**AI 使用披露双通道**：
- `final/交付说明.md` → 「AI 使用披露」**完整版**（给主人：AI 生成段 + 主人洞察出处 + 检索证据 + 模型 fallback 记录 + 教训沉淀）
- `final/定稿.md` → 「AI 使用声明」**精简版**（给读者：诚实透明声明，**不含**模型 fallback 记录、内部条目编号等内部信息）

**先行者声明闭环**：T1 **必产** `literature/先行者清单.md`（原创性保证机制，实战曾被跳过）；定稿文末**必含** `## 先行者文献` 节；正文 [先xx] ↔ 文末清单双向 diff。缺先行者 = 原创性保证失效（学术不端风险）。

**数据溯源 check-list（本机实战 5/6 待办为溯源）**：交付说明**必须**自动列出所有「待回查」条目，T8 终检时机械填充，**不靠主人手动跟进**：
- 付费墙文献（仅核验摘要，待回查全文）
- 二手转引（待回查原始 [Lxx] 出处）
- 🔴 红级数据（>5 年，待核时效）
- 待核原刊信息（DOI/卷期/页码待补）

**「接受脆弱」→ 遗留风险 自动映射（主人实测）**：主控/分析员「接受脆弱」决策（方案 2）**必须自动写入**交付说明「遗留风险」段（固化字段，非自由发挥）——接受脆弱的论点 + 原因 + 剩余风险一条条列出，供主人判断是否接受交付。

**成本指标（T8 终检强制字段）**：交付说明**必须**记录 token 数（精确） / 时长 / 模型组合（各 T 角色实际用哪个模型，含 fallback 兑底）——否则无法判断「优化到底省没省」。T8 终检时从 status.md「4.7 token 消耗记录」表机械汇总 Σ 填入，**并在对话中主动向主人呈现下方代码块**（硬动作，非可选）；**交付说明缺「成本指标」字段 = T8 终检不过**。子代理 token 数据源 = 完成事件末尾 Stats line 的 `Token usage`（input/output/total），**无 cache 字段**：

```
## 本轮 token 成本（精确）
- 总计：<Σ> tokens（in <N_in> / out <N_out>）
- 子代理 Σ：<Σ_sub> tokens（各子代理完成事件 Stats line 的 Token usage 汇总）
- 主控自身：<session_status 主会话值> tokens（含 cost $<cost>）
- 主要消耗：T5 写手 <N> / T7 审计 <N> / T9 评审 <N>
- 数据源：子代理完成事件 Stats line（Token usage input/output/total）+ session_status 工具（OpenClaw 9.1+）
```

**v2.6.1 重写根因**（教训 #192）：OpenClaw 9.1 提供精确 API（子代理完成事件末尾 Stats line + session_status 工具），**v2.5.18 三级降级机制是设计偏慎**，原「宿主无关」表述隐含「拿不到精确值」的错误前提。仅精确统计，Stats line 缺失 = 平台异常（标告警，不是填「未配置」/「N/A」）。**教训 #256**：早前文档把 token 来源误写为「sessions_spawn 返回值 stats」，实测 spawn 返回值无 stats 字段，真实来源是子代理完成事件末尾的 Stats line（`Token usage` input/output/total）。

**待 merge 反哺清单（主人实测）**：交付说明加「待 merge 反哺清单」checklist，固化为 T8 模板动作——列出 T7 反哺报告建议的规则 + merge 目标角色卡，等主人人工 review 后手动 merge（**不自动 commit**）。

## F 失败模式防御段（教训 #270，借鉴 ARS M1-M7 + 补漏 4 个新模式）

论衡按「失败模式」组织防御能力（F1-F9），不替换内部 G 体系（G0-G14 是 15 项内部检查）—— F 体系是 G 体系的**对外叙述**，让主人理解论衡怎么防 AI 失败。借鉴 ARS Lu et al. *Nature* 2026 论文的 M1-M7 失败模式组织。

| F 模式 | 定义 | 论衡 G 项映射 | 状态 |
|------|------|-------------|------|
| **F1 幻觉引用** | 引用真实但用错语境 / 引用完全捏造 | G1 分级抽验 + G0.5 视角一致性 + M-Exist-1 双向 diff | 已有（强）|
| **F2 幻觉数据** | 数字真实但过期 / 数字完全捏造 | G2 数据溯源 + G11 时效告警 | 已有（强）|
| **F3 早期框架锁定**（**新增**）| 分析大纲先入为主，写手被锁死 | G0.5 + Phase 3.5 主人洞察补充窗口 + **新增「反方论证覆盖必查」**| 补强 |
| **F4 论证自洽陷阱**（**新增**）| 论据与论点逻辑脱节，读者无法验证 | G3 逻辑核验 + **新增「论点-论据一对一验证」**| 补强 |
| **F5 拼凑式章节断裂** | 章节间无过渡 / 章节顺序违反读者认知 | G4 结构 + G8 #7 段落结构过度对称 | 已有（强）|
| **F6 过度防御口吻** | 写手代入「过度保护」语气，破坏客观分析视角 | G0.5 + G6 论据类型自标 + 「据行业经验估算」限定 | 已有（强）|
| **F7 主人风格模仿失真**（**新增**）| 写手把主人洞察当「作者声音」，混入正文 | G0.5 + 主人深度洞察融合协议 | 补强 |
| **F8 数据信任失败**| 已发布 vs 主人投喂 vs 二手转引 来源混入 + 公众号版不同步 + 转引未标注 + 信任级别遗漏 | M-Form-6 + M-Exist-3 + G12 + T2.5 + **T7.5** | 补强 |
| **F9 论证强度不足**| 论据单一 / 因果倒置 / 以偏概全 / 回避反方 / 反方走过场 | **T6** 批判伙伴 C1-C7（独立反方攻击） | 补强 |

**F8 数据信任失败 4 子项**：

- **F8.1 来源混入**：已发布数据 vs 主人投喂数据没区分 → 数据卡必填「信任级别」段
- **F8.2 公众号版不同步**：run/ vs outputs/ 数据不一致 → M-Exist-3 强制 diff + **T7.5** 闸门
- **F8.3 转引未标注**：论文中转引未标 [二手] → 数据卡 [二手] 字段必填 + G12 信任级别一致性扫描
- **F8.4 信任级别遗漏**：数据卡无信任级别标注 → M-Form-6 必查 + T2.5 闸门

**F9 论证强度不足 5 种表现**：

- ① 论据单一（单一来源支撑核心论点）② 因果倒置 ③ 以偏概全 ④ 回避反方 ⑤ 反方走过场
- **防御**：**T6** 批判伙伴（独立反方角色，不依赖写手/审计员自我认知）

**借鉴出处**：vincentjiang06 paper-writer Trust Boundary 论衡化。

## M 门控段（LLM 结构化自评，非机器强制）

- **M-Form 形式合规门**（共 **8 项**）：引用标注完整性 / 文末四节存在性 / 临时编号残留 / 角色元数据泄露 / 过程语言残留 / **信任级别标注完整性（M-Form-6，双格式升级 #292+#293）** / **定稿文末节标题白名单纯净（M-Form-7，教训 #139，P0 优先级）** / **三角验证覆盖率检查（M-Form-8）**
- **M-Exist 存在性合规门**（共 **3 项**）：文末四节双向 diff（由 M-Exist-1 的「逐节双向比对规则」核验，主控用 `read` 读文件 + 逐项判定）/ **证据包完整性校验（M-Exist-2）**——LLM 推理判定「文件存在+字节数+章节结构」，sha256 改人类可选回填 [教训 #169] / **信任级别一致性 diff（M-Exist-3）**
- **M-Integrity 阶段闸门**：**T2.5（M-Integrity-1，T2 → T4 前主控 checkpoint，含 9 步检查——数据条目数、信任级别完整、信任级别一致性、头部计数一致性，**sha256 占位可选**）+ T7.5（M-Integrity-2，T7 → T8 前主控 checkpoint，含 8 步检查——审计最新版、P0/P1 清单、M 门全 exit 0、论文 vs 报告隔离、修订轮独立写手，**sha256 占位可选**）**
- **T7 必跑**，exit 0 才能返回
- 借鉴 vincentjiang06 objective/verify gate 硬约束理念的论衡化实现——「**形式合规 ≠ 存在性合规 ≠ 信任一致**」

## 常规修订 ≤2 轮硬约束（教训 #270，+ #276）

> **v2.3.1 定义细化（教训 #276）**：v2.2.0 立「≤2 轮」铁律时**没区分「什么算一轮」**——v2.3.0 首次实战中 T6 一轮=出 v2，T8 想再启 T5=第二轮，若 T7 的 P1 都需启 T5 就超 2 轮。v2.3.1 重新定义「轮」+ 引入「P1 分级」+ T8 小幅修补权限。

**「轮」的定义（以 [`pipeline-overview.md`](_shared/pipeline-overview.md)「修订回环仲裁」为单一真源）**：
- **0 轮** = 主控启动，T5 写手出 v1（Phase 3 产出）
- **1 轮** = v1→v2：融入主人洞察（Phase 3.5）+ T6 批判 / G14 反馈
- **2 轮** = v2→v3：T7 打回修订或 T8 亲修（批判反馈轮）
- **常规 2 轮之外（独立计数）**：v3 后 minor cosmetic（≤5% 字 / 引用格式 / 拼写）由 T8 inline 亲修，走 minor 修补通道并在交付说明登记（不占用常规 2 轮预算）；结构性 P1（P1-A/B/C）+ P0 必须经主人拍板启 T5 v4 独立写手 + Acknowledged Limitations 模式（例外通道，单独计数）——**无静默无限修订**

**T8 小幅修补权限（教训 #276）**：T8 从「只做签字」升级为「可做小幅修补」——
- ✅ 可修：≤字数 5% 改动 / AI 披露修正 / 元叙事清理 / P1-D 事实错误（引用格式/元数据/漏引/拼写）
- ❌ 不可修：结构性改动（论证补强/结构缺失/反方缺失 = P1-A/B/C）+ P0 → 必须启 T5 独立写手

**P1 分级细分（教训 #276）**：
- **P1-A/B/C（结构性）**：论证补强 / 结构缺失 / 反方缺失 → **T5 重启**（独立写手，保留防自我说服哲学）
- **P1-D（事实错误）**：引用格式 / 元数据 / 漏引 / 拼写 → **T8 亲修**（慢活快改，不涉论证独立性）

**第 3 轮触发 → Acknowledged Limitations 模式**：未关闭 P0/P1 搬入 `final/局限性.md`，T7 通过 ≠ 完美
- 「不要无限循环。无限循环是 LLM 的舒适区陷阱」—— 论衡主人口吻

## 阶段闸门 T2.5 + **T7.5** 硬约束（教训 #271）
