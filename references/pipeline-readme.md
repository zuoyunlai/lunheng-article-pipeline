## 🚫 不适用场景（边界明示 — v2.1.5 新增，v2.1.5.1 修正表述）

论衡是「论文/深度文章」**写作流水线**，**擅长主动检索已发布证据 + 整合主人投喂的证据**。

**论衡能主动采集**（T1 文献检索 / T2 数据检索 / T6 案例检索 sub-agent）：
- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

**论衡不能主动采集**（需要主人提前准备素材投喂）：
- ❌ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 → 需要主人亲自调研，原始数据投喂为「数据源」
- ❌ **统计分析**（SPSS/R/Python 跑模型）：论衡可以引用统计结果，但**不执行统计计算**。如需跑回归/聚类/因子分析，请主人用专门工具，结论以「数据 + 方法描述 + 结果」形式投喂
- ❌ **图表原始数据采集**：论衡生成的是**数据可视化**（matplotlib/SVG），数据本身需主人提供。如需爬虫/OCR/语音转文字，请主人用专门工具，原始数据投喂后论衡制作图表
- ❌ **原创图片 / 视频生成**：论衡有 `image_generate` 工具生成封面/插图，但**不能拍摄实物照片 / 录制视频**。如需实物素材，请主人拍摄后投喂文件路径，论衡可在文末引用
- ❌ **代码执行**：`exec` 工具不在 15 项白名单内（denied）。如需跑代码验证论据，请主人用专门环境执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」——是，论衡主动采集；不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用。

## 快速开始

```
1. 主控确认主题（Phase 0）→ 写 01-任务简报.md + 初始化 status.md
2. 主控记录 cases 需求（含 0 条场景的显式声明），写入 status.md（v2.1.8 取消三档决策，教训 #56）
3. 主控调度模型健康度预检（v2.3 新增，详见下节）→ 决定该次 T 派发用哪个模型
4. 并行 spawn 文献检索员 + 数据检索员（用下面的派发话术）
5. sessions_yield 等两者完成
6. spawn 分析员 → 分析大纲产出 → Phase 2.5 送主人确认 → 通过后 spawn 写手
7. spawn 审计员 → 审计不过 → 写手交修订说明 + 修订稿（≤2 轮）→ 终检交付（含证据包）
```

## 调度模型健康度预检（v2.3 新增，教训 #35）

> 实战中 T3 连续 3 个模型（deepseek-v4-pro / minimax-m3 / claude-opus-5）全部超时，论衡主控亲自产出大纲。本机制旨在预判 + 降级 + 硬卡超时。

**主控 T 派发前必须执行 3 步**：

1. **健康度预检**（避免一上来派发到已知慢模型）：
   - deepseek-v4-flash：轻量检索默认，置信度高
   - deepseek-v4-pro：推理/分析默认，但有过超时历史（教训 #35）
   - minimax-m3：推理/分析 fallback，但近期 T3 三连超时主要责任方
   - claude-opus-5：审计顶配，但成本高
   - **主控派发前查 status.md 顶部「论衡本轮可用模型」表**（论衡会话启动时自动填）

2. **超时硬卡 8 分钟**（实战中旧阈值过宽，介入太晚）：
   - T 派发后 8 分钟内未出产物 → 判定超时，主控介入
   - 不允许「静默等 10 分钟」

3. **主控兜底产物明确标注**（v2.0 机制没标 → 写手不知道这是主控产物不是 T 产物）：
   - 任何 T 阶段主控亲自产出 → 必须在文件头标注「主控兜底 v1.0」+ 注明失败原因
   - 写手收到时能识别这是非 T 产物，调整引用对齐策略

## status.md 状态机（主控维护，角色交接时更新）

每个任务状态：`Inbox → Assigned → In Progress → Review → Done | Failed`
- 每个角色交接时必须更新 `status.md` 对应行
- 失败要留原因；任一行停留 >8 分钟无进展 → 主控介入（v2.3 从 10 分钟收紧为 8 分钟）
- 模板：`templates/status-template.md`

## 派发话术（主控复制即用）

### 文献检索员（并行①）

```
你是「文献检索员」。任务编号 T1。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress

1. 用 web_search / tavily_search 检索主题相关文献（中英文；知网/万方/Google Scholar/期刊官网/SSRN 等）

4. 每条标可信度等级：A（核心期刊/权威机构）/ B（一般期刊/预印本）/ C（网络/二手转引）——C 级必须诚实标注
```

### 定稿引用规范（主人 2026-08-12 确立，水与麦单修正 + v2.1.4 四节闭环，教训 #47）
1. **正文必须带来源标注**：每个数据/观点后标 `（机构，年份）` 内联标注（公众号风格），或保留 [Dxx]/[Lxx] 编号并在文末附「引用来源」清单（编号→机构→年份→标题→URL）。**禁止把引用删成无标注裸文**——删掉引用即删掉可信度。
2. **文末引用清单（四节，v2.1.4 起强制）**：按引用编号类型分四节组织：
   - `## 数据来源` —— [Dxx] 系列，每条含编号+机构+年份+标题+URL
   - `## 案例来源` —— [Cxx] 系列 + [C-主xx] 主人洞察系列；主人洞察照写 1 条「主人深度洞察」说明并注明出处（任务简报第 X 行）
   - `## 参考文献` —— [Lxx] 系列，每条按任务简报指定格式（默认 GB/T 7714）
   - `## 先行者文献（与本文概念部分重叠，特此说明差异）` —— [先xx] 系列，每条含机构+年份+标题+URL + 与本文差异点简述
   
   **测算值/综合判断条目（如 [D03 测算值] [D105 综合判断]）**如实标注"测算值/综合判断（基于 Dxx/Dxx）"，**不伪称有第三方来源**。
3. **编号残留检查 + 四节双向 diff（v2.1.4 机械化校验，教训 #47）**：交付前主控 + T5 审计必走：
   ```bash
   # 拿正文所有编号
   grep -oE "\[D[0-9]+\]|\[C[0-9]+\]|\[C-主[0-9]+\]|\[L[0-9]+\]|\[先[0-9]+\]" final/定稿.md | sort -u > /tmp/intext.txt
   # 拿文末四节条目编号
   awk '/^## 数据来源/,/^## 案例来源/' final/定稿.md | grep -oE "\[D[0-9]+\]" | sort -u > /tmp/data.txt
   awk '/^## 案例来源/,/^## 参考文献/' final/定稿.md | grep -oE "\[C[0-9]+\]|\[C-主[0-9]+\]" | sort -u > /tmp/case.txt
   awk '/^## 参考文献/,/^## 先行者/' final/定稿.md | grep -oE "\[L[0-9]+\]" | sort -u > /tmp/ref.txt
   awk '/^## 先行者/{flag=1;next} /^## /{flag=0} flag' final/定稿.md | grep -oE "\[先[0-9]+\]" | sort -u > /tmp/xian.txt
   # diff
   comm -23 /tmp/intext.txt <(cat /tmp/data.txt /tmp/case.txt /tmp/ref.txt /tmp/xian.txt) # 漏引（正文有但文末无）→ P1
   comm -13 /tmp/intext.txt <(cat /tmp/data.txt /tmp/case.txt /tmp/ref.txt /tmp/xian.txt) # 孤儿（文末有但正文无）→ P1
   ```
   不通过 → 写手必须补/删，主控必须 grep 复核，**不通过不交付**。详细规范见写手卡铁律 #9 + 主控卡终检必查项 ⑨ + 审计卡 G4。

## 模型配置与更换指南（v2.3）

> 本流水线的模型是**能力分层**，不是**模型锁定**。上表模型名是本机默认，任何 OpenClaw 兼容模型（OpenAI 兼容 API）都可替换。

### 三层模型配置（从外到内）

| 层 | 配置位置 | 更换方式 |
|----|---------|----------|
| **1. 主控 agent 本体** | OpenClaw 配置 `agents.list[<agent>].model` | `primary` 主模型 + `fallbacks` 降级列表，改配置后重启 gateway |
| **2. 各角色 spawn 模型** | `sessions_spawn` 的 `model` 参数 | 主控派发话术里直接指定每个 T 角色用哪个模型 |
| **3. 角色卡「模型建议」表** | 本 README「成本与模型建议」表 | 只作建议，实际 spawn 时以主控派发为准 |

### 更换的自由、途径、权限

- **自由**：检索/分析/写作/审计/主控每个角色都能独立换模型，按「能力分层」原则自由搭配
- **途径**：① 改 OpenClaw `openclaw.json` 的 `agents.list[<agent>].model` ② 改 `sessions_spawn` 的 `model` 参数 ③ 改角色卡「模型建议」表
- **权限**：任何有对应 provider 配置的 OpenClaw 兼容模型都能用，无需改流水线代码，只需改配置

### 能力分层原则（换模型时遵循）

| 角色 | 能力要求 | 选模型标准 |
|------|---------|-----------|
| 检索 | 便宜 + 快 | 低单价 + 短延迟，1M 上下文优先 |
| 分析/写作 | 强推理 + 中文长文 | 高质量中文输出 + 大上下文（证据包可达 50-70 条） |
| 审计 | 顶配 + 专抓错 | 最强模型，宁可贵不可漏 |
| 主控 | 判断 + 路由 | 强推理 + 稳定（避免频繁超时的模型） |
