## 模型配置与更换指南

> **背景**（主人 2026-08-22 指出）：operations.md 引用「模型配置与更换指南」段，但 v2.3.0 重构时 TOC 加入了三个子标题（`三层模型配置`/`更换的自由、途径、权限`/`能力分层原则`），**正文未补**——造成文档漂移（教训 #269，双形式同步漂移反模式）。本节为 v2.3.10 补全。

### 三层模型配置（从外到内）

v2.3.13 起模型不再硬编码，模型解析分**三层**（从唯一真源到兑底兜底）：

1. **`references/_shared/模型候选池.md`**（能力档 + 候选池，**唯一真源**）
   - 检索=便宜快 / 分析写作=强推理 / 批判审计=顶配 / 主控=稳定路由
   - 每个能力档的候选池按优先级排列，换系统/换模型改这一处即可

2. **Phase 0 静态映射**（读取当前会话已提供的模型元数据，非探测）
   - 主控依据当前 OpenClaw 会话可见的模型元数据（`session_status` 等只读信息），每个能力档从候选池选第一个可用模型；这不是读取 `openclaw.json` 或核验宿主权限配置
   - 顶配档候选池全不可用 → 显式告知主人，禁止静默降级

3. **openclaw.json 模型**（仅兑底兜底，非硬配置；属宿主侧配置，论衡 agent 不读不写）
   - `agents.list[].model.primary + fallbacks` 仅作 Phase 0 自检失败时的最后兜底
   - 不再需要为论衡单独建 agent 或手动配模型

### 更换的自由、途径、权限

| 层面 | 谁能改 | 怎么改 | 生效时机 |
|---|---|---|---|
| OpenClaw 宿主配置（**宿主侧，非本技能写入范围**）| **主人本人**（在宿主侧手动 edit `openclaw.json`，或主人自己调用 gateway 工具）| 属宿主运维操作：**论衡 agent 不读、不写、不修改宿主配置，也不发起或参与此操作**（列出的工具名仅用于说明主人的自助路径，非 agent 可用动作）；需 backup 后改，gateway 重启生效 | 重启后 |
| 角色卡推荐模型 | 主人 / 主控（经主人同意） | edit 角色卡顶部；版本戳同步由维护者手工完成（净化版无脚本） | 下一轮会话 |
| 本轮可用模型 | 主控在 status.md 顶部填 | write status.md 头部「本轮可用模型」表 | 即时生效 |

**主人的自由度**：
- ✅ 任意层都可改，无需经过论衡批准
- ✅ OpenClaw 兼容的任何模型都可接入（含 Ollama 本地）
- ✅ fallback 顺序可自由调整
- ⚠️ 改完需**重跑论衡首单测试**，验证模型组合不超时/不崩

### 模型能力抽象 + 静态映射 + 运行时降级

> **背景**：v2.3.12 前模型名硬编码在角色卡/SKILL.md，换系统即失效；且主控无「余额不足」预检，claude-opus-5 余额不足时顶配审计**静默降级**（本机测试 T6/T7 全兑底 minimax-m3，A 级抽验仅 17%）。

- **能力抽象（P0-2）**：模型名 → **能力需求 + 候选池**（检索=便宜快 / 分析写作=强推理 / 批判审计=顶配 / 主控=稳定路由），候选池见 `references/_shared/模型候选池.md`。
- **Phase 0 静态映射（P0-3，v2.12.42 重做）**：主控启动时读取当前会话已提供的模型元数据（`session_status`，非探测、不查余额、不读取宿主配置文件），每个能力档从候选池按优先级选第一个可用模型，写入 status.md「本轮可用模型」表；顶配档候选池全不可用 → **显式告知主人**「当前会话无顶配审计模型，审计/批判深度将降级，是否继续」。
- **运行时降级（v2.12.42，取代预算闸门）**：不做派发前预检；首次调用失败 → 下一档重派；配额耗尽 → 等主人拍板；同项目已确认失败 → 直接降档。真源 = [`_shared/模型候选池.md`](_shared/模型候选池.md) §三。

### 能力分层原则（换模型时遵循）

> **v2.3.12 P0-2 升级**：模型名不再硬编码，抽象为「**能力档 + 候选池**」——角色卡只写能力需求，具体模型由主控 Phase 0 自检后按本机可用模型池映射（候选池见 `references/_shared/模型候选池.md`）。下表「候选池」= **本机默认映射示例（非硬编码）**，换系统/换模型按候选池自动适配。

按角色能力需求分层选模型，**避免「T7 审计用便宜快模型」「T1 检索用顶配」错配**：

| 能力档 | 角色 | 能力需求 | 候选池 | 错配后果 |
|---|---|---|---|---|
| 检索 | **T1/T2/T3** | 便宜快（抽取+分类） | 见 `references/_shared/模型候选池.md` | 用顶配 = 浪费 + 慢；用太弱 = 信息丢失 |
| 分析写作 | **T4/T5** | 强推理 | 见 `references/_shared/模型候选池.md` | 用 flash = 大纲粗糙 / 文章失味 |
| 批判审计 | **T6/T7** | **顶配防漏判** | 见 `references/_shared/模型候选池.md` | 用弱模型兑底 = 批判无刃 / 审计降级 |
| 主控 | **T0** | 稳定路由 | 见 `references/_shared/模型候选池.md` | 主控崩 = 全流水线停 |

**核心原则**：
- **审计顶配不省**：T7 是最后一道防线，论文质量全压这——宁可其他地方慢
- **检索不奢侈**：T1/T2/T3 是流水线批量检索，便宜快模型够用
- **写手分场景**：内联引用 / 学术编号 = deepseek-v4-pro；公众号短文 = flash 够
- **本地 Ollama 可用**：涉敏 / 零外发场景用 gemma4:31b / qwen3-coder:30b

**见** `references/operations.md` 成本与模型段（示例表与 fallback 链）

### T9 评分必汇报（主人实测教训）

**T9 完成后主控必须在对话里向主人呈现评分**（不只写文件）。人对话中必须在 Phase 4.5 报告 T9 结果：

```
## T9 同行评审结果

**总评分**：XX / 30
**建议**：accept / minor / major / reject

**6 维度评分**：
- 原创性：X/5
- 方法论：X/5
- 证据强度：X/5
- 论证结构：X/5
- 写作质量：X/5
- 引文规范：X/5

**Top 3 期刊推荐**（学术模式）：
1. 《期刊名》（匹配度 X%，适合 XXX 方向）
2. 《期刊名》（匹配度 X%）
3. 《期刊名》（匹配度 X%）

报告文件路径：`audits/审稿报告-v{N}.md`

**主人决策**：
□ A. 接受定稿，进入 Phase 5 终检
□ B. 继续修订（T5 v3+ → T7 R2 → T9 再跑）
□ C. 其他调整
```

### 图位编号规则（教训 #157）

**图位编号 = 章节出现顺序，不是任意编号**：

1. Phase 2.5 拍板时，**图位标题先留空**，只拍板图位数量 N（如 N=3）
2. T5 写手按章节出现顺序编号：[图1] → [图2] → [图3]（**不允许断号**）
3. **不允许 [图1][图3][图4] 出现**——这是 bug，不是图位缺失
4. 主控 Phase 4.4 SVG 生成时：
   - 先 grep `\[图N\]` 全集，按章节顺序排列
   - 章节内出现顺序 = SVG 文件命名顺序
5. T7 审计员 P1 检查 `[图N：标题]` 出现次数 ≥ 拍板图位数量 + 编号连续

**实战背景**：v3 正文出现 [图1][图3][图4] 断号 = 缺编号规则约束。T5 写手按拍板数量拍，但编号任意。
