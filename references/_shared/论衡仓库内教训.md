## #R001 — 测试入口双轨（裸 `python tests/X.py` 与 `pytest`）漂 2 版未被发现

> 📋 **元数据** | 分类 **A 流程规范**（仓库内工程工具链）| 严重度 **P1**
> 触发：v2.12.42 发版后 push `ff4ae99`，CI run 34918738996 红点
> 处所：`.github/workflows/ci-test.yml` + `tests/test_rules_consistency.py`

### 触发

CI 跑 `python tests/test_rules_consistency.py` 直接执行测试文件（绕开 pytest 收集），
触发文件末尾 `__main__` 块。`__main__` 块引用了 `test_wordcount_dual_caliber`，
但该函数在 v2.12.40（把 `dual_caliber` 改名为 `single_caliber`）时漏改 → NameError → 步失败。

### 为什么本机没发现

`pytest tests/test_rules_consistency.py` → pytest 收集阶段**不执行 `__main__`** → 文件 import 成功 → 8/8
`python tests/test_rules_consistency.py`（CI workflow 用的）→ 直接跑 `__main__` → NameError → 失败

**本仓库的 CI workflow 是项目里唯一一条绕开 pytest 的测试入口**（其他三个 step 全走 pytest），
所以漂了 2 版没被任何信号拦下。

### 正解（三件）

1. **测试文件不写 `__main__` 块**——或只留 `raise SystemExit("请通过 pytest 跑")` 引导
2. **CI workflow 所有测试 step 走 `python -m pytest tests/X -q`**——与项目其他入口统一
3. 在被删的 `__main__` 位置留**根因注释**（写明"为什么不能加回 __main__"），防再有人加回

### 教训

- **测试入口必须统一**：`pytest` 之外有第二条跑法 = 漂移温床
- **本机过 ≠ CI 过**：CI 环境的 PYTHONPATH / `python` vs `python3` / `-m` 行为差异都会触发本机漏检
- **本文件适用**：所有仓库内工程工具链类教训（CI / 净化链 / YAML / 净化包脚本）—— 落 `references/_shared/论衡仓库内教训.md`，不复用主真源编号
