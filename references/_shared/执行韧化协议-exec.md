## 执行韧化协议

每个角色 prompt 头部必须执行 5 条：

1. **心跳信号**（启动 30 秒内 + 每 5 分钟一次）：**写自己的心跳文件** `run/<项目>/.tmp/<角色>-heartbeat.md`，写明「启动时间 + 当前模型 + 状态=🔄 In Progress」，后续每 5 分钟追加 `[心跳 HH:MM] model=<model-id>`；**子代理不直接写 status.md**——status.md 由主控收到心跳信号后独占更新（子代理只读 status.md）。**写文件任务硬卡比读放宽 2 分钟**。

2. **分阶段 ack**：< 2 分钟启动 ack 即可；2-5 分钟启动 + 完成；5-15 分钟五段（25/50/75/100%）；> 15 分钟**禁止**——必须拆任务。完成 ack 的 token 消耗由**主控**从 completion event Stats 记录（子代理无需回传，教训 #256）。

3. **降级自报**：遇 provider 401 / 配额耗尽，在 final message 返回 `{"status": "degraded", "reason": "<错误摘要>"}` 后立即结束，**禁止 0 tokens 静默退出**（主控凭此触发 fallback 标注）。配额 vs ping 超时区别：主控 LLM 推理判定。

4. **超时硬卡**：T1-T3 10 / T4 12 / T5 15 / T6 15 / T7 12 / T9 10 / G14 8 分钟。提前 2 分钟写 `[警告] 已耗时 X 分钟`；提前 1 分钟必须 partial output；到点主控 kill + 接受 partial。

5. **禁止假装在线**：心跳 ack 必须真实反映进度；过程语言残留自检（M-Form-5）：完成后 检查「v2 稿/初稿/草稿/修订说明/主人结构性观察/据行业经验估算/论据类型」有命中立即删除。

6. **报告长度上限 + 超限分块（回应实测 #4）**：报告类产出（T4 分析大纲 / T6 批判 / G14 检测 / T7 审计 / T9 审稿 / T8 终检）回传前自查长度（read 估行数/字符量级，零 exec 不跑 wc），**硬上限见 phase-order.yaml 各节点 `output_chars_max`**（T4/T6 ≤12k、T7 ≤10k、G14 ≤6k、T9 ≤15k、T8 ≤10k 字符）。超限**禁止一次性全量回传**——主动按结构分块回传（每块 ≤上限，主控逐块落盘拼接）；单块仍超 = 砍细节保结论（各维度结论 + 证据编号必留，展开论述可省）。全程禁止「先全量发出赌截断」：截断后主控侧拼接的段要标 `[主控拼接]`，属 fallback B 级（见 design 版分级）。

## 编排循环三防（交接点）

**spawn 后** 立即 `subagents(action=list)` 确认 runId 在 active runs；不在 = 重试 ≤2 次。
**yield 超时** 3 分钟无事件 = 查 subagent 状态 + sessions_history；状态正常继续 yield，状态异常补 spawn。
**完成事件幂等** 收到 Done 先查 status.md 是否已 Done，是 = duplicate 忽略。
