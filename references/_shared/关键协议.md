#### 确定性同意门（fail-closed，逐调用过）

> **同意记录是「授权输入」，不是文档。** 每次外发 / opt-in 调用前，主控与子代理都**必须**过下表；判据不满足 = **阻断该调用**，不得按 prose 推定「应该已同意」。

| 调用类别 | 放行判据（**全部**满足） | 不满足时的动作 |
|---|---|---|
| 检索层（web_search / web_fetch / tavily_search / tavily_extract） | 记录存在 ∧ mode ∈ {①,②,③} ∧ 轴 A 含「检索关键词」 | **阻断**，改用主人自带材料 + 本地推理 |
| 学术元数据（OpenAlex / Crossref） | 上式 ∧ 轴 B 含「学术元数据」 | **阻断** |
| **大模型推理全文**（文献卡/数据卡/案例卡/草稿/大纲/正文 → 模型 provider） | mode=① ∨（mode=③ ∧ 轴 A 含「大模型推理全文」） | **阻断全文外发**；mode=② 时必须**脱敏 + 本地 Ollama** |
| 抓取层（Firecrawl / paper.edu.cn） | mode=① ∨（mode=③ ∧ 轴 B 含「抓取层」） | **阻断** |
| **mode=④ 全部拒绝** | 上表全部阻断 | 纯本地；出网工具**一次都不调** |

**⚠️ v2.12.52 能力移除登记（非口径削弱）**：原「封面（`image_generate`）」调用类别与轴 A「图像 prompt」项**已随封面能力一并移除**——论衡 agent **不再调用** `image_generate`，该外发路径**客观不存在**，故同意轴相应收敛。**这是能力删除导致的条目消失，不是同意口径放宽**（与教训 #339「原有项计数不得减少」不冲突：该条针对**能力仍在**时的清单归并丢失）。**任何后续版本不得在未恢复 `image_generate` 调用能力的前提下重新出现「封面」同意项。**

**三条确定性规则**：
1. **两轴都必须有明确取值** —— 轴 A（数据形态）/ 轴 B（服务类别）任一为空、写「待定」或含糊 ⇒ 整条记录判为**无效** ⇒ 全部阻断。
2. **不一致即阻断 + 披露** —— 记录与实际调用类别不一致（如记③但轴 B 未勾某类却仍调用）⇒ 阻断，并写入 `final/交付说明.md`。
3. **缺失/不可读 ⇒ 按「全部拒绝」处理**（fail-closed），停止并回报主控。

### 叶子纪律（子代理不再委托，v2.12.8 新增）

**背景**：平台可能默认开启有界递归委派——子代理因而**拿得到** `sessions_spawn` / `subagents` / `sessions_list` / `sessions_history`。论衡架构假设「角色卡 = 叶子 worker」（主控只等**直接**子级；announce 链逐级上传），故角色卡一律按叶子纪律执行。

**规则（所有非主控角色适用）**：
- **不得**调用 `sessions_spawn` 派生任何子代理——需要额外检索/额外人手时，在**交接报告**写「需求回执」（缺什么、为什么缺、建议派谁），由主控决定是否 spawn
- **不得**调用 `subagents` / `sessions_list` / `sessions_history` 查看或管理其他会话（该能力属主控；叶子拿到是平台默认，不是授权）
- 子代理之间**不直接通信**（不调 `sessions_send`）——回传路径只有「交接报告 → 主控」一条
- 「未被平台剥夺」≠「被授权」：遵论衡纪律层，不因工具可得而扩大行为面

**三层冗余落地（第三层 = `dispatch-header.md` 公共头部）**（全部为纪律层，已内置）：
| 层 | 位置 | 宿主需做 |
|---|---|---|
| 纪律·角色卡 | `agents/0X-*.md` 头部声明 | 无（已内置）|
| 纪律·任务书 | 主控每次 spawn 必含叶子声明（见 `00-主控-扩展职责.md` §三）| 无（已内置）|

**代价（为何必须锁）**：子代理自行再 spawn 时，孙辈完成事件**不上传到主控**（announce 链逐级上传，主控只收直接子级）——主控看不到孙辈产物，等于「产出静默丢失 + token 已花」。

### 修订回环 ≤2 轮降级（教训 #270，+ #276）

- **超限例外通道**：结构性 P1（A/B/C）+ P0 → spawn T5 独立写手 + Acknowledged Limitations（须主人拍板）。

**降级原因**：
- 防止无限循环（教训 #270）

### 二、三方对账（T7 审计必做）

T7 审计开始前必须先做一次**三方一致性核对**，任一不符即列为审计发现（P1）：

| 项 | 取数处 |
|---|---|

### 三、判定输入指纹

每条门结论必须写 `判定输入`（路径 / 版本标识 / 首行原文 / 末行原文 / 字节数），缺项 = 报告不完整。这是「报告后激活」的**可核查痕迹**：主人比对首末行与字节数即可识破「预跑结果冒充报告后判定」。

## 上下文压缩与引用标识符保全（v2.12.27 新增）

> **为什么论衡必须写这一条**：论衡的引用体系（`[Lxx]` / `[Dxx]` / `[Cxx]` / `[图N]`）是**不透明标识符**，而 M 门 / G 项**全部靠"读文本对账"**。长流水线（多 Phase + 修订回环 + 大卡片）**必然触发平台的自动压缩（auto-compaction）**——若压缩把标识符摘要掉，**对账会静默失败**（不报错，只是对不上）。

**平台事实**：压缩默认保全不透明标识符（`identifierPolicy: "strict"`），**但可被关闭**，且**自定义压缩 provider 必须自行实现保全**。

**论衡的立场与动作**：
1. **依赖默认保全**：论衡依赖 `identifierPolicy: "strict"`（平台默认值）——**请勿改为 `off`**。
2. **自定义 provider 须自证**：若宿主使用自定义压缩 provider，**必须**在其 `summarize()` 中保全 `[Lxx]/[Dxx]/[Cxx]/[图N]` 等不透明标识符；论衡**不校验**此点（宿主责任）。
3. **落盘即抗压缩**：所有关键状态（卡片、大纲、草稿、审计报告、决策记录）**一律落盘**——落盘产物**不受压缩影响**，这正 `status.md` / `run/<项目名>/` 设计的原因。**上下文里的引用编号可能被压缩，磁盘上的不会**。
4. **对账以磁盘为准**：M 门 / G 项对账**读磁盘产物**，不依赖对话历史里的引用编号。

**补充（平台事实）**：**上下文溢出错误不走模型 fallback**（`request_too_large` / `input exceeds the maximum number of tokens` / context length exceeded 等）——它们**留在压缩/重试逻辑内**处理；把它当 fallback 触发器是错的。真正的 fallback 触发项是：认证失败 / 限流耗尽 / 过载 / 超时型 / 计费禁用 / `model_not_found`。
**provider 拒答（refusal）是终态** —— 平台**不做**自动恢复、压缩重试或切到无关模型；下一轮用户消息才开启新 turn。论衡对此应**直接呈报主人**，不要期待自动兜底。

## 非节点期间的输入处理（主人中途插话 / steer）（v2.12.27 新增）

论衡的**4 个节点**（Phase 0 / 2.5 / 3.5 / 5）是**必须**停下来请示的时刻；但**平台允许主人在任何时刻插话**（队列模式 `steer` / `followup` / `collect` / `interrupt`，由宿主配置决定）。因此必须明确**非节点期间收到输入怎么处理**：

| 输入类型 | 处理 |
|---|---|
| 补充材料 / 事实纠正（不改变方向） | **吸收**进当前阶段产物；记 `status.md`「人在环决策记录」段并标注「**非节点输入**」 |
| 改变方向（换题目 / 换结构 / 换体裁） | **不擅自改**：暂停当前阶段 → 向主人确认（等同**提前触发**最近的节点）→ 记录 |
| 纯提问 / 进度询问 | 直接答；不动产物、不记决策 |
| 紧急停止 | 立刻停（平台 `interrupt` 会中止运行）；产物留在磁盘，记 `status.md` |

**三条纪律**：

1. **记录即生效** —— 任何非节点输入都要落 `status.md`（时间 + 原文摘要）；**口头吸收不落盘 = 无法追溯**（同「无明确决策 = 未通过」）。
2. **不因插话跳过节点** —— 插话**不能**替代 Phase 2.5 / Phase 3.5 的正式拍板。
3. **权威记录在 `status.md`** —— 对话历史可能被压缩吞掉（见上节）。

## 长文交付与渠道分块（v2.12.27 新增）

论文/长文远超单条消息上限：**平台按渠道对出站文本分块**（不同渠道上限不同，实测约 **2000–5000 字符**）。因此：

- **交付说明写清路径**：`final/交付说明.md` 必须给出**文件路径**（而不是让主人在聊天记录里找拼块）。
- **不因分块丢结构**：若主人要求「发到聊天」，先说明会被分块，并附文件路径。

## 机制保护：机制面改动一律人工 approve（v2.12.40 新增）

> **一句话**：反哺报告、角色卡、机制文件（技能定义 / 脚本 / 补丁配置）的任何改动**一律需人工 approve，禁止自动合并**。

**保护面（「机制面」）**：

| 对象 | 例子 |
|---|---|
| 反哺报告 | `audits/反哺报告-vN.md`（及主控在交付说明里「建议 merge 的反哺规则」清单） |
| 角色卡 | `references/agents/*.md`、`references/dispatch/*.md` |
| 机制文件 | 技能定义（`SKILL.md` 及 `references/` 下的规则文件）/ 脚本 / 补丁配置 |

**纪律（三条）**：

1. **只产出、不合并** —— agent 在项目内可以**写草稿**（`run/<项目名>/audit-lessons.md`、反哺报告、建议清单），但**不得**调用 `write`/`edit` 改角色卡或机制文件；跨仓同步由主人手工完成。
2. **无 approve 记录 = 未生效** —— 机制面改动的生效判据是**主人显式同意**（对话内的 approve / 明确的「改吧」），不是「agent 认为应该改」。**未获同意即改动 = 违规**。
3. **违规等级** —— 违反本条与「改动即最严重违规」同级：产出一律作废、当轮结论不得采信，并按人在环上报主人。

**诚实边界（不可省的一环）**：

- 本层是**流程层约束**，**不是**工具层拦截 —— 对等实现里那道「工具调用守卫」只看**工具调用**，**命令行与子进程不经这道门**；而本技能侧连工具层的通用拦截都不存在。
- 因此：**人工确认这一环不可省**。任何「已自动保护」的表述都不成立 —— 保护靠**流程 + 人工 approve**，不靠平台强制。
- 配套观测：主控在 `status.md` 记「机制面改动候选」与 approve 结果；无记录 = 未发生。

> **与门 M.3 一致**：跨项目共享文件（教训真源 / 案例库 / 技能自身文件）**零强制写入**——只允许项目内草稿 + 待主人 review / 人工 merge。



会话 / 运行中断后，**不凭印象接续** —— 按四步从磁盘恢复：

1. **读断点**：`read run/<项目名>/status.md` → 取「当前阶段」与 Phase 进度表**最后一个 ✅ Done 的节点**；
2. **核产物**（**不可跳过**）：按 `phase-order.yaml` 该节点的 `output` 声明，逐条确认产物**在磁盘存在**（语义核对）；缺 → 该节点**未真正完成** → **从该节点重跑**。
   - `output` 有两种形式：**字符串**（单产物；多产物用 `A.md + B.md` 写法，如 `t4_analysis`）或 **`角色: 路径` 映射**（如 `t6_g14` 的 T6/G14 双产物）——**每个值都要逐条核对**，只核一个 = 漏核；
   - `drafts/current_draft.md` 的**唯一生产者 = 节点 `current_draft_sync`**（Phase 3.6 前置；**Phase 3.7 `t5_feedback_revision.after_each`** 与 `audit_revision.after_each` 每轮重跑）——它是 T6/G14/T7/T9 的统一输入，**缺失或版本不符即停在人环**，不得凭 status.md 文字推进；
3. **取下一步**：读该节点的 `next`（**唯一真源 = `phase-order.yaml`**）→ 得下一节点 id → 按**别名表**映射为文档层 Phase 标签（**不得自创标签**）；
4. **校验入参**：读下一节点的 `input` 声明 → 逐条确认上游产物齐备；不齐 → **停在人环告知主人**（不得凭「应该有了」推进）。

**禁止**：跳过第 2 步直接按 `status.md` 的文字继续 —— status 可能滞后或误记（实测已发生「配图声称 5 张、实际 3 张」与「T7 被跳过却记为完整交付」）。

**为何必须**：`status.md` 是**断点载体**，但**不是真相**；真相在**磁盘产物 + yaml 图结构**。
