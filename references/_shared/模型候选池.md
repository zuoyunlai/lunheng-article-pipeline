> **定位**：论衡模型能力档 + 候选池的**单一真源**。SKILL.md / 各角色卡 / pipeline-readme.md 只引用本文件，不重复定义。

## 一、能力档定义（5 档）

| 能力档 | 角色 | 能力需求 | OpenAI 兼容候选池描述 | 实战选型建议 |
|--------|------|---------|---------------------|------------|
| **检索** | T1 / T2 / T3 | 便宜快（响应快 / token 便宜） | 小参数模型 + 高 token/秒（如 gpt-4o-mini / claude-haiku / 本地 Ollama） | 默认：本地 Ollama + 远程兜底 |
| **分析写作** | T4 / T5 | 强推理（逻辑链 / 长上下文） | 中大参数推理模型（如 gpt-4o / claude-sonnet / deepseek-reasoner） | 默认：远程强推理 |
| **批判审计** | T6 / T7 | 顶配防漏判（严格审计 / 不放水） | 顶级推理模型（如 claude-opus / gpt-4-turbo） | 默认：远程顶配 |
| **主控** | T0 | 稳定路由（多角色协调 / 不崩溃） | 中参数稳定模型（如 gpt-4o / claude-sonnet） | 默认：远程稳定 |
| **终检** | T8 | 主控亲完成（不 spawn 子代理） | 不适用（主控代） | 不适用 |

## 二、映射规则（Phase 0 模型自检）

主控启动时（Phase 0）扫本机可用模型（`models list`），按以下规则映射：

```
1. 扫描本机可用模型（如 deepseek-v4-flash / claude-opus-5 / 本地 ollama:qwen3 等）
2. 对每个能力档，按「能力需求」描述从可用模型池选第一个可用
3. 写入 status.md「本轮可用模型」表

例（DSH 平台）：
- 检索 → deepseek-v4-flash
- 分析写作 → deepseek-v4-pro
- 批判审计 → claude-opus-5
- 主控 → deepseek-v4-pro

例（非 DSH/Ollama 平台）：
- 检索 → 本地 qwen2.5-coder:7b
- 分析写作 → claude-sonnet-4
- 批判审计 → claude-opus-4
- 主控 → claude-sonnet-4
```

**自动适配**：换 OpenClaw runtime 后 Phase 0 自检自动映射，**无需手动改 SKILL.md / 角色卡**。

## 三、预算闸门（P0-1 新增）

派发 T6/T7 前查顶配模型余额：
- 余额 < $0.1 → 走候选池下一档并告知主人「深度降级」
- 同一项目已发现余额不足 → 后续顶配角色直接降级（不重复试错）

## 四、降级提示规则

- 顶配档（批判审计）候选池**全不可用** → 主控**必须显式告知主人**「本机无顶配审计模型，审计/批判深度将降级，是否继续」
- **禁止静默降级**
