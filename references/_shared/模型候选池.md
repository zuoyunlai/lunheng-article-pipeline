# 论衡模型候选池（第三方独立审查建议 #5）

> **定位**：论衡模型能力档 + 候选池的**单一真源**。SKILL.md / 各角色卡 / pipeline-readme.md 只引用本文件，不重复定义。
>
> **设计哲学**（教训 #176）：候选池**仅描述能力**，不绑定具体模型 ID。具体模型由 Phase 0 模型自检按宿主元数据（`session_status` 等只读工具）自动映射。换 OpenClaw runtime（如非 DSH 套餐）自动适配。
>
> **零 exec 哲学**：候选池是描述性映射，论衡 LLM **不跑任何 shell 命令、不直连任何 provider 计费/配额 API**——主控读本文件 + **宿主可见元数据**（`session_status` 等只读工具）推理映射。

> ⚠️ **顶配档不可用时禁止静默降级（v2.12.28 加严）**：批判审计档（T6 / T7 / T9 / G14）候选**全不可用** → **必须显式呈报主人并获确认**后才可降级到次级模型；**不得静默 fallback**。
>
> **实测反例（2026-09-11）**：批判审计档配 `claude-opus-5`(kkaiapi) 在列，但运行中**全部落到 fallback `MiniMax-M3`** —— 主人直到读 `status.md` 才得知审计深度已降级（审计/批判是论衡的核心质量门，**静默降级等于悄悄降低成品标准**）。
>
> 执行：派发 T6/T7/T9/G14 前按宿主可见信息确认顶配档可用性；不可用 → **暂停并呈报主人 3 选 1**（换 provider / 接受降级 / 改单主控模式）。

## 二、映射规则（Phase 0 模型自检）

主控启动时（Phase 0）扫宿主可见模型元数据（`session_status` 等只读工具，**不是 shell 命令**），按以下规则映射：

```
1. 扫宿主元数据（session_status，如 deepseek-v4-flash / claude-opus-5 / 本地 ollama:qwen3 等）
2. 对每个能力档，按「能力需求」描述从可用模型池选第一个可用
3. 写入 status.md「本轮可用模型」表

例（DSH 平台）：
- 检索 → deepseek-v4-flash
- 分析写作 → deepseek-v4-pro
- 批判审计 → claude-opus-5
- 主控 → deepseek-v4-pro

例（非 DSH/Ollama 平台）：
- 检索 → 本地 qwen2.5-coder:7b
- 分析写作 → claude-sonnet-4
- 批判审计 → claude-opus-4
- 主控 → claude-sonnet-4
```

**自动适配**：换 OpenClaw runtime 后 Phase 0 自检自动映射，**无需手动改 SKILL.md / 角色卡**。

## 三、预算闸门（P0-1 新增）

派发 T6/T7 前按**宿主可见信息**确认顶配档是否可用（读 `session_status` / 宿主显示的成本与配额；**不直连 provider 计费 API**）：
- 宿主可见余额或配额不足 → 走候选池下一档并告知主人「深度降级」
- 同一项目已确认不可用 → 后续顶配角色直接降级（不重复试错）

## 四、降级提示规则

- 顶配档（批判审计）候选池**全不可用** → 主控**必须显式告知主人**「本机无顶配审计模型，审计/批判深度将降级，是否继续」
- **禁止静默降级**
