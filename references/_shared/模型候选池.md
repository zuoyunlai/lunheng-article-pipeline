# 论衡模型候选池（第三方独立审查建议 #5）

> **定位**：论衡模型能力档 + 候选池的**单一真源**。SKILL.md / 各角色卡 / pipeline-readme.md 只引用本文件，不重复定义。
>
> **设计哲学**（教训 #176）：候选池**仅描述能力**，不绑定具体模型 ID。具体模型由 Phase 0 静态映射（读一次 `session_status` 配置清单，**非逐模型探测、不查余额**）自动映射。换 OpenClaw runtime（如非 DSH 套餐）自动适配。
>
> **零 exec 哲学**：候选池是描述性映射，论衡 LLM **不跑任何 shell 命令、不直连任何 provider 计费/配额 API**——主控读本文件 + **宿主可见元数据**（`session_status` 等只读工具）推理映射。

> ⚠️ **顶配档不可用时禁止静默降级（v2.12.28 加严）**：批判审计档（T6 / T7 / T9 / G14）候选**全不可用** → **必须显式呈报主人并获确认**后才可降级到次级模型；**不得静默 fallback**。
>
> **实测反例（2026-09-11）**：批判审计档配 `claude-opus-5`(kkaiapi) 在列，但运行中**全部落到 fallback `MiniMax-M3`** —— 主人直到读 `status.md` 才得知审计深度已降级（审计/批判是论衡的核心质量门，**静默降级等于悄悄降低成品标准**）。
>
> 执行：派发 T6/T7/T9/G14 前按宿主可见信息确认顶配档可用性；不可用 → **暂停并呈报主人 3 选 1**（换 provider / 接受降级 / 主控接管该节点并披露）。

## 二、映射规则（Phase 0 静态映射）

主控启动时（Phase 0）读一次宿主**已配置模型清单**（`session_status` 只读元数据，**不是 shell 命令、不做逐模型探测、不查余额**），按以下规则映射：

```
1. 扫宿主元数据（session_status，如 deepseek-v4-flash / claude-opus-5 / 本地 ollama:qwen3 等）
2. 对每个能力档，按「能力需求」描述从可用模型池选第一个可用
3. 写入 status.md「本轮可用模型」表

例（DSH 平台）：
- 检索 → deepseek-v4-flash
- 分析写作 → deepseek-v4-pro
- 批判审计 → claude-opus-5
- 主控 → deepseek-v4-pro

例（非 DSH/Ollama 平台）：
- 检索 → 本地 qwen2.5-coder:7b
- 分析写作 → claude-sonnet-4
- 批判审计 → claude-opus-4
- 主控 → claude-sonnet-4
```

**自动适配**：换 OpenClaw runtime 后 Phase 0 自检自动映射，**无需手动改 SKILL.md / 角色卡**。

### 二·补、顶配档探活门（v2.12.49 T-3）

> **背景**：实测「前一天探活、当轮无探活」⇒ 14:28 拍板、18:51 才撞 401，**白烧 4h23m + 一次 spawn**。⇒ 顶配档可用性必须在 **Phase 0 当场**暴露。

- **位置**：Phase 0 后置（`pre_spawn_enforcement`，spawn 前核验）—— **在任何 worker spawn 之前**；顶配不可用 ⇒ Phase 0 当场暴露，**不消耗任何 worker spawn**
- **探活口径**：顶配档探活 **≤3 次、间隔 ≥10s**；**不查余额、不做逐模型探测**（只核实「顶配档本轮是否可调用」）
- **失败处置**：任一探活失败 ⇒ **当场与主人确认降档（含换族）**，走三选一（换 provider 族 / 换能力档 / 接受同源 + 披露）
- **留痕**：探活结果（含**时间戳**）写入任务简报「§模型映射」；**时间戳超过 1 小时需重探**（防「探活后久拖才派发」重演原故障）
- **与 §三 的关系**：§三 管的是**日常反应式降档**（不逐模型探测、不查余额）；本门是 **Phase 0 一次性**顶配档探活，两者不冲突

## 三、运行时降级（v2.12.42 引入；**v2.12.49 T-2 加严：换族优先 + 族级独立性 + 断路器**）

**不再做**逐模型探测 / 余额 / 可用性**预检**（原「预算闸门」已删——回应外部扫描「主动探测与余额采集超出写作流水线必要范围」）。改为运行时反应式降级。**唯一例外 = §二·补 的「顶配档探活门」（v2.12.49 T-3）**，那是 Phase 0 一次性核验，不是 per-dispatch 预检。

- 首次实际调用失败（401 / 403 / 429 / 配额 / billing）→ 子代理 `degraded` 自报 → 按本节规则重派（零产物决策树：同档 ≤2 次 → 降档）
- **降档优先换 provider 族**（v2.12.49 T-2）：降档时**必须优先选与当前模型 `model_family` 不同**的候选；**仅当所有异源候选均已失败**才允许同源降档，且**必须显式披露「模型独立性不成立」**（写入 `status.md` + 交付说明）
- **独立性判据 = 模型族不同**（v2.12.49 T-2）：旧的「角色不同即独立」是**假独立**（八角色可能全收敛同一模型）。**族级判据**：T6 / T7 / T9 三者的 `model_family` **两两不同**才可称「独立性达成」；不满足只能写「**信息独立达成 / 模型独立性不成立**」
- **断路器**（v2.12.49 T-2）：顶配档**连续 2 次失败** ⇒ 主控**不得自行全量降档**，必须在该节点**暂停呈报主人三选一**：① 换 provider 族 ② 换能力档 ③ 接受同源（+ 披露独立性不成立）
- **配额耗尽类失败 → 暂停等主人拍板**（行为预授权，fail-closed；预授权已给则按预授权执行）
- 同一项目内已确认失败 → 后续顶配角色**不重复撞同一模型**（**换族**后重试）；**本项不豁免断路器**（连续 2 次失败仍触发暂停）

## 四、降级提示规则

- 顶配档（批判审计）候选池**全不可用** → 主控**必须显式告知主人**「本机无顶配审计模型，审计/批判深度将降级，是否继续」
- **禁止静默降级**
- **断路器触发的披露（v2.12.49 T-2）**：顶配档连续 2 次失败时，主控**不得**静默全量降档，必须在暂停呈报中给出三选一（换 provider 族 / 换能力档 / 接受同源）；选「接受同源」时**必须**在交付说明写明「**模型独立性不成立**」
- **族级独立性披露（v2.12.49 T-2 / T-4）**：若 T6 / T7 / T9 的 `model_family` 存在相同 ⇒ 相关报告**不得**写「独立性达成」，只能写「**信息独立达成 / 模型独立性不成立**」
