> **字段口径（v2.12.40）**：
> - **不再有「退出码」字段** —— 退出码是进程级概念，本门是 LLM 结构化判定（无进程 / 无返回值）；历史写法 `"退出码": 0 | 1` 一律按上表四档读。
> - `判定` 旧字段若保留，取值必须能映射到四档（`✅ 通过` → 「通过」；`❌ 失败` → 「不通过」），**且不得用于表达「无法判定」与「路径或参数错误」** —— 后两档必须显式写出，防止「非内容失败」被并进「失败」再触发修订。
> - `判定记录_双字段` 中每个条目若无「证伪依据」三项、且通过档**无枚举清单** → **视为伪造报告**（P0，T8 不得签字）。
> - `判定输入` 四项缺任何一项 → 报告不完整；它同时是「报告后激活」的**可核查痕迹**（主人比首末行与字节数即可识破「预跑结果冒充报告后判定」）。
> - `闸门第0步_输入新鲜度` 不满足 → 落「路径或参数错误」档，**不得**触发内容修订轮。
> - **【v2.12.56】伪代码出口与本 schema 对齐**：13 项 M 门伪代码统一经（主文档 §统一抽取规则真源 C）的 `verdict_pass` / `verdict_fail` / `verdict_undecidable` / `verdict_path_error` 返回，其 `档位` 取值与上文 `判定记录_双字段` 的 `档位` 枚举**逐字一致**。
> - **【v2.12.56】抽取规则唯一真源**：文末节集合（必需 4 节 / 白名单 7 节 / 非标准节）与引用编号正则（标准 / 基线 / 表格三类）唯一真源 = 主文档 §统一抽取规则真源 A、B；**本附录不再另立一份**。

## 论衡哲学化（4 版本合并）

- **「M 门是论衡的「返璞归真」** —— 不引入 Python 脚本，不扩大 exec 白名单，由 LLM 推理执行规则化校验」
- **「形式合规 ≠ 存在性合规**」—— vincentjiang06 核心洞察论衡化
- **「**M 门由 LLM 兜底**」** —— 主控用 read 工具读本规约 + final/ 文件，按伪代码推理
- **「**数据信任级别是论衡防御 prompt injection 的核心机制**」** —— vincentjiang06 paper-writer Trust Boundary 论衡化
- **「**阶段闸门是论衡主控纪律**」** —— 不引入新 agent，主控用 progress_card + read 实现；ARS Stage 2.5/4.5 论衡化
- **「**形式合规 ≠ 存在性合规 ≠ 信任一致**」** —— v2.2.0 → v2.2.1 M 门体系三层验证
- **「**M 门算法的实战有效 = 论衡哲学最纯粹的版本（M 门零 exec 依赖）的实战验证**」** —— v2.2.1.2 是 v2.2.0/v2.2.1 算法 bug 的实战修正
- **「**实战反馈驱动升级**」** —— v2.2.1.2/v2.2.4 不是规划出来的，是实战反馈暴露出来的
- **「**数据卡格式不只是「字段格式」**」** —— v2.2.1.2 P0-C 双格式支持 = 论衡防御体系的「全格式兼容」
- **「内联引用 ≠ 无引用**」** —— 公众号/商业评论的引用是可信度，M 门必须校验其可回溯性，不能因格式不同而放行
- **「**补检索是源头，回填是闭环**」** —— 补检索新增文献必须同步回填文末清单，否则正文引用悬空，T8 必拦
- **「修订也需独立角色**」** —— 论衡角色独立性（现 10 张角色卡）的核心理念应贯穿到修订轮，主控只协调不代笔

- **教训 #65**：集成测试 > 组件测试。组件能跑 ≠ 系统能用

- **教训 #272**：v2.2.0 M-Form-3 算法 bug → v2.2.1.2 升级 comm -13 diff

- **教训 #292**：v2.2.1 P0-C 在「表格格式数据卡」落地短板 → 数据卡-template.md 加表格 fallback 段

- **教训 P1-3**：内联模式下不只 M-Exist-1 空转，G2/M-Form-1/M-Exist-3/G4-2 等所有依赖 [Dxx]/[Lxx] 编号的机械检查都会空转，必须覆盖全部 5 项而非只修 M-Exist-1
