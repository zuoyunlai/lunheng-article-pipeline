## 主动介入机制

发现下游角色卡住（静默超硬卡阈值或无产出）→ 主动介入：

> **⚖️ 本节只定义「何时判定」，不定义「怎么处置」**：介入**触发点**（硬卡阈值 / 介入时机）见本节；**处置口径唯一真源 = `00-主控-扩展职责.md`「§不通过处理」状态机与处置优先级规则**。
> 本节及下方介入流程里出现的「重派 / 重试」，**一律**按其**处置优先级规则**读作**平台层 / 模型层「换档」**，**不得**读作「重跑同一任务」——「kill 后可 respawn 同任务」在该状态机已明列为**已删语义**。

> **kill 的工具映射（零 exec，权威定义）**：论衡主控「kill 超时子代理 / worker 自 `sessions_yield` 挂起的 run（实测挂起 14h+ 占位、需显式收敛）」= `subagents(action=cancel, taskId=<来自 subagents(action=list) 的单一 taskId>)`。这是零 exec 约束下唯一合法的终止方式（不 exec kill 进程；cancel 在 coordinator_only 白名单内，且工具层硬限制只能取消主控自己 spawn 的子代理树——见 `00-主控-扩展职责.md`「会话管理原语作用域」段）。**只接受单数 `taskId`**（传数组报 `taskId required`），批量需逐条调用。取消可能不完整（工具报 error 而非 clean success）——取消后必须再 `subagents(action=list)` 复核是否真停，未停则重试 cancel（幂等）。各角色卡/模板/硬卡阈值表中的「kill」均指此操作。

### 硬卡阈值表（原 8 分钟改为角色分级阈值）

> ⚠️ **与 `SKILL.md`「硬卡阈值表」同源**；两处若冲突，**以 `SKILL.md` 为准**（含 `runTimeoutSeconds` 机械值）。本表另含「超时处理 / 实战背景」两列，为 SKILL 表所无。
> ⚠️ **本表「超时处理」列只描述「已有产物（partial）」情形（「超时 ≠ 零产物」）**；**零产物**情形不看本列，一律按 `00-主控-扩展职责.md`「§不通过处理」状态机（主控亲写兜底 + status 记录 + 告知主人；**不重试**）。

| 角色 | 硬卡阈值 | 超时处理 | 说明 |
|------|---------|---------|----------|
| T1/T2/T3 检索 | **10 分钟** | kill + 接受 partial + 标「部分检索」+ 主控补缺 | 中文检索单次 7s+ |
| T4 分析 | **12 分钟** | kill + 接受 partial + 主控补 | — |

**主控硬性 SOP**：
1. spawn T 角色时记录 `spawn_time = now()`（在 status.md 该角色行写明）
2. **每次收到 subagent 输出**（含 partial 输出）→ 检查是否超硬卡阈值
3. 超阈值 → **立即**（不等下次）按介入 6 步走：kill + 按「§不通过处理」状态机处置（**本步只负责「到点即判定」**，不另立处置口径：零产物 ⇒ 主控兜底、**不重试**；产物已落盘 ⇒ 先 `read` 核对后采纳 partial）
4. status.md 写明 `[硬卡 HH:MM:SS] 超 T5 阈值 15min，kill + 接受 partial`
5. **不准「再等一下」**——硬卡阈值刚性执行（到点即介入），不允许主控决策犹豫

**介入 6 步**：
1. 查 status.md 是否含心跳/ack（缺失 = 没遵循协议 → 拍醒子代理）
2. 用 sessions_history 看子代理最近输出（判断是真卡还是模型思考中）
3. 如果判定为**模型 / 平台可用性**问题（**≠** 硬卡静默零产物）→ 手动 kill 会话，按**平台层「换档」**重派（换 provider 族或下一档 fallback 模型）—— 属「§不通过处理」处置优先级规则第 4 条，**不等于「重跑同一任务」**
4. 如果只是产生物到中途中断（partial output 存在）→ 接受现有产出，手动补齐缺失部分
5. 在 status.md 阶段行写明介入记录：`[介入 HH:MM] 主控介入，session-kill，重派 model=fallback1`
6. **两类上限独立判断**（F4 重构 + 补强）：
   - **同场景「换档」重派 ≤2 次**（= 平台层换档重派，**非**「重跑同一任务」—— 同任务重试已废止，见「§不通过处理」处置优先级规则第 2/3 条），避免无限重试
   - **修订回环 ≤2 轮硬约束**（**T7** 审计打回后 **T5** 重写；二分类修订详见 [`deliverables.md`](../../deliverables.md)「修订回环」）：
7. **并发子代理文件覆盖防护**：主控兜底派发 fallback 前，**必须先查主任务是否还在产出**，避免两份产物对同一文件二次覆盖：
   - **fallback 派发前置检查**：读产物文件 mtime 元数据，若距当前 <2 分钟（主任务刚写盘还在跑）→ **不派 fallback**，再等主任务（**语义等价动作**：主控读文件 mtime 元数据比较，不执行 shell）
   - **命名隔离**：同一角色多份并行时，用 `<文件>.<模型>.md` 命名隔离（如 `06-v2-attack.deepseek-v4-pro.md`），禁止两份同写一个文件名
   - **阈值刚性**：以 `00-主控-扩展职责.md`「硬卡阈值表」（同源 `SKILL.md`）为准，不得以「任务较重」为由临时放宽，避免「主任务其实写好了但被误判超时 → fallback 覆盖」
