## 六、Phase 0 预算机械自查（v2.12.32 新增，回应实测 P0）

> **背景（实测缺陷）**：v2.12.32 无人值守实测中，任务简报**同时**给出「分章最小字数硬指标之和 **5,500**」与「总量上限 **6,000**」，而 §3/§4 另有「反方回应段 ≥200 字 ×4」「最强反方五条完整呈现」等**刚性下限** —— 三者相加使**现实下限 ≈7,000-7,300 > 6,000 上限**，产生一个**永远无法关闭的 P0**（T7 两次复核均判 P0-1 篇幅，直至回环耗尽、只能走 Acknowledged Limitations 交付）。**根因 = 上限与分章硬指标被各自独立写死。**

**铁律：正文上限与其他刚性下限「只允许给定其一」，另一个由恒等式推导。** 两个都写死 = 必出矛盾。（v2.12.41：原「分章最小字数硬指标」已**废除**，见 §七）

```
预算恒等式（均取正文字数口径——不含文末附录）：
  Σ(刚性段落下限) ≤ 正文上限        （v2.12.41：左侧**去掉「分章最小字数硬指标」**——它激励 padding、伤 G14，且与总量上限自相矛盾，见 §七）
```

> **文末附录不进正文上限**：参考文献 / 数据来源 / 案例来源 / 先行者文献 / AI 使用声明 / 致谢属**文末附录**，**不计入正文字数、不参与恒等式、不受正文上限约束**（附录本身不设字数硬上限；主人如需可另行指定，但**不影响正文上限判定**）。

**Phase 0 必做（主控 LLM 推理执行，零 exec）**：

1. **算一项**（v2.12.41：原「分章硬指标之和」项已废除）：**刚性段落下限**（反方回应四要素段 ×N、R1-R4 自评局限、「本文差异化」段等**文档已写死的下限**）。
2. **代入恒等式**：不满足 ⇒ **当场向主人二选一**（**不得自行放宽**）：① 上调正文上限至恒等式右侧；② 削减刚性段落数量/下限。**禁「先写着，超了再说」** —— 实测代价 = 两轮修订 + 7,950 字定稿仍带未关闭 P0。
3. **写回记录**：任务简报「目标篇幅」段写 `预算自查: 5500(分章) + 700(刚性) = 6200 ≤ 正文上限 6500 ✅（文末附录另计，不进正文上限）`（示例格式）；status.md 同步一行。

**口径真源 = 本表**：任务简报模板与主控 Phase 0 清单均**指针到本段**，不重列公式（防漂移）。

## 七、字数的定位：交付契约 vs 内容质量（v2.12.41 新增 —— 防再次被加码成硬门）

> **背景**：本表历史上把字数做成「内容硬门」，由此产生三类实证失败（§2）：**① 机制自杀**（v2.12.32：分章硬指标 + 总量上限 + 刚性下限三者独立写死 → 现实下限 > 上限 → 永远关不掉的 P0，两轮修订 + 7,950 字定稿仍带 P0）；**② 噪声 > 分辨率**（严格档 ±1% vs T5 自报 ±3-5%）；**③ 修订轮被吃掉**（T7+T9 签 accept 0.7% 超，T8 发现 3.4% 超 → 多一轮 14 分钟只为删 140 字）。

**字数的定位（定案）**：

| 场景 | 定位 | 硬度 |
|---|---|---|
| **有外部硬要求**（期刊投稿上限 / 平台限制） | **交付契约** | **硬**：卡上限，粒度 **±5%**（匹配测量噪声） |
| **无外部要求** | **呈现信息** | **软**：T7/T8 报告标注偏差幅度，**不触发修订** |

**三条纪律**：

1. **字数不是质量代理**：篇幅由**论证需要**决定。为命中字数而 padding 会**直接伤 G14（AI 痕迹）与论证密度** —— 两个机制原本互相拉扯。
2. **分章不设字数硬指标**：章级篇幅**只作呈现信息**（T7/T8 标注超预算章节，供主人判断是否结构性失衡）；「结构是否敷衍」由**论证要素齐备**（论点-论据一对一映射 + 反方回应）判定，**不由字数判定**。
3. **无外部要求时，字数不触发任何修订**：只呈现、不阻断。

> **一句话**：**字数是「交付契约」时就硬；当「质量门」时，不仅没必要，而且有害。**

## 八、修订净增上限（v2.12.49 T-5，回应 P1-5）

> **背景（实测）**：对「修订」长期只有**下限压力、无净增上限** ⇒ 逐轮膨胀。实测 **v1→v4：+31.5%**（8,791 → 11,556 字）。

| 约束 | 值 | 判定 |
|---|---|---|
| **单轮净增上限** | **≤ 2%**（按正文汉字；分母 = 上一轮正文汉字数） | 超过 ⇒ **必须等量置换**（删减量 ≥ 新增量 − 2% 额度），否则判**不合格** |
| **净增字段** | `net_delta_cjk = 本轮正文汉字数 − 上轮正文汉字数` | 修订说明头部必填：`net_delta_cjk: +<N> (<pct>%)` |
| **Phase 0 预留** | 定「目标字数」时取**上限的 92%** | 为最多 3 轮修订预留 **~8%** 净增空间（3 × 2% ≈ 6%，留余量） |

**口径一致**：净增按**正文汉字数**（§一唯一口径）计，不计图注 / 图题 / 参考文献 / 附录 / 声明段 / 角色元数据。

## 九、T5 估算失败的恢复路径（v2.12.71 新增，v2.12.72 安全修订）

> **背景**：T5 自报字数可能存在 ±3–5% 噪声。若连续两轮以上估算与复核结果明显偏离，且内容质量已经合格，继续重派 T5 可能只会增加轮次；此时可进入本恢复路径。
>
> **安全边界**：论衡声明 `exec`、`process`、`code_execution` 为禁用工具。本恢复路径**不得要求、暗示或调用任何执行类工具**，也不得以主控身份绕过该边界。字数精确统计若超出当前授权工具能力，必须暂停并请主人在本机自行统计，再将结果作为输入；不得自行执行脚本或命令。
>


### 触发条件

满足以下**全部**三项即触发本恢复路径（不再重派 T5）：

1. 已重派 ≥ 2 次 T5 v3+，且每轮复核字数均显著偏离 T5 自报估算（差距 ≥ 实际字数的 10%）；
2. 差距方向稳定，实测均偏高或均偏低；
3. 当前稿内容已经合格，问题仅是压缩或扩写到目标窗口。

满足 ①② 但 ③ 未满足（如字数差巨大且内容有结构问题）→ **走重写路径而非本路径**，按 `failure-modes.md` / dispatcher 既有协议。

### 恢复路径（4 步，必须严格顺序）

1. **用 `read` 读取当前稿**，并用已授权的 `write` 在项目数据域内保存版本副本（例如项目数据域中的下一版稿件），保留上一版本供追溯。不得使用 `cp`、shell 命令或其他执行类工具。
2. **用 `edit` 做经过审阅的精确替换**：只处理已确认的冗余句、重复过渡语或重复事实陈述；每次替换的 `oldText` 必须完整匹配，匹配失败就停止该项；分批完成后用 `read` 回读，确认内容、引用、图位和结构未受影响。`edit` 无法提供可靠汉字计数时，不得猜测结果，暂停并请主人自行统计后再依据计数判断 §八净增上限。
3. **在版本首部和交接报告中记录主控叠加**：明确标注 `[主控兜底 v{N+1}]`、触发原因、版本关系，以及「子代理实际工作 vs 主控叠加」的分层。不得把本稿描述为 T5 产物。
4. **继续执行 T6 / T7 / G14 / T9 / T8**，不因主控参与修改而跳过独立审查；若无法确认字数或任一硬门状态，则暂停并交主人拍板。

### 边界与禁令

- **不绕过 cap / M 门**：v{N+1} 仍须通过字数 cap（§二）+ M 门全部出口条件 + G14
- **不删引用编号 / 图位 / 反方段 4 要素 / 三支柱字数下限**：这些是论衡硬约束
- **不假装是 T5 产物**：v{N+1} 首部必须显式标 `[主控兜底]`，并在 `drafts/交接报告-T5-v{N+1}.md` 注明「破例主控兜底，因 T5 连续估算失败」
- **不无限重试**：本路径触发后**不再重派 T5**；如果 v{N+1} 仍未达标，走 §七「无外部要求时字数不触发任何修订」或派主人拍板
- **不得把主人侧操作写成流水线动作**：主人可以自行运行本机计数或转换命令，但交付记录必须明确执行者；本路径不取代 T5 正常派发。

### 与既有协议的关系

- **不等同于「配额耗尽」处理**（`执行韧化协议-design.md` §3.5）：配额是账号级问题，本路径是子代理工具受限问题，恢复路径不同
- **不等同于「主控兜底声明」通用规则**（`agents/00-主控-扩展职责.md` L336）：通用规则只说怎么标，本节说明触发条件和**不使用执行类工具**的修订步骤
- **不替代 `failure-modes.md` F1-F9**：F 体系管论证/格式失败模式，本节管字数估算失败这一**特定且高频**的子代理受限问题
