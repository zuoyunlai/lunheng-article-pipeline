## 五、主控上下文预算模型（v2.12.72 批次 2-E）

> **用途**：把 Stats line 从纯事后记账升级为 Phase 0 的事前预算与运行中预警。
> 本模型估算的是**主控会话累计 token**（主控自身 input + output），不是全体子代理总量。
> 当前只有 1 行重量档主控实测，以下预算均为**保守估计**，不足 3 个不同档位实测前不得写成经验证事实。

| 轻量 | 2000–3000 | 80k–140k（估计） | 预警基线，不作为成本承诺 |

| 重量 | ≥10000 | 260k–420k（估计） | 由 12721 字项目主控 291.5k 实测校准，仍保留安全余量 |

### 5.1 运行中判定

- **余量** = `1 - 主控已消耗 token / 当前会话模型可用窗口`；若平台未提供可核验窗口值，记录 `unavailable`，不得伪造百分比。
- **偏低**：余量 `<30%`，status.md 必须追加落盘减负建议；**危险**：余量 `<15%`，除建议外暂停加载非必要全文并向主人告警。
- **超支预警**：累计主控 token `> Phase 0 预算 × 150%`，记录 `overspend_alert`；不把估算误写成精确成本，也不自动改变流水线判定。
- **校准**：每次实战只用主人侧可核验 Stats line 回填；新增实测行后再调整区间，禁止用缺失的子代理 Stats line 反推主控预算。

### 5.2 落盘减负动作（防教训 #268）

1. 已完成 dispatch 话术和中间产物只保留路径、结论与下一步，不在主控上下文驻留全文。
2. spawn 前只 read 当前角色对应的 dispatch 文件；不得从记忆复制话术。
3. 已落盘卡片按 `read` 的 `offset/limit` 局部读取；需要全文时先写明原因并记录在 status.md。
