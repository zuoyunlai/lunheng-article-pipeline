# 方法论-审计清单（G18 真源）

> **版本**：v2.14.0-block-A（W1 落地）
> **性质**：G18 闸门真源（硬性 + 软性检查项）
> **位置**：T7 审计员必查 + T9 同行评审 D2 方法论评分共用
> **触发**：每个项目终检前必跑（与 G0-G18 同档位）
> **轻量档豁免规则**：字数 2000-3000 字时**仅前 6 项必填**，标注 `[轻量档简版]`；其余 6 项可声明 `n/a` 并写一句豁免理由

## 一、设计哲学

G18 不是"找错清单"，是论衡面向顶刊评审的「**研究设计可审计**」承诺：

- **方法论透明，非隐瞒**：G18 的目标是"让评审在 5 分钟内看懂本文怎么做的、为什么这么做、边界在哪"，**不**是"应付检查填表格"
- **诚实优先**：项目类型（应用 / 实证 / 思辨 / 历史）不适用某项时，**显式声明 n/a + 解释**比"强行填"更合规
- **顶刊对齐**：12 项设计参考 *Nature Human Behaviour* / *中国社会科学* / *American Journal of Sociology* 的方法论披露规范（不照搬，按中文学界适配）

## 二、12 项检查清单

每项 = 必填字段 + 4 档判定（通过 / 不通过 / 无法判定 / 路径或参数错误）+ 严重度（🔴 高 / 🟠 中 / 🟡 低 / ⚪ 不适用）。

---

### 1. 研究问题是否可证伪（research_question_falsifiable）

- **必填字段**：
  - `研究问题`（一句话陈述）
  - `可证伪命题`（如不成立，什么样的证据能反驳？）
  - `本文不打算回答什么`（边界声明）
- **判定要点**：是否给出「若 X 则 Y」的命题形态？是否声明了反例空间？
- **常见漏洞**：纯描述性问题（"X 是什么"）、无法证伪的宏大命题（"X 的本质"）

### 2. 因果识别策略（causal_identification，仅适用：实证 / 量化研究）

- **必填字段**：
  - `识别策略`（实验 / 自然实验 / 工具变量 / 双重差分 / 断点回归 / 倾向得分匹配 / 其他）
  - `识别假设`（如 IV 的排他性约束、DiD 的平行趋势）
  - `稳健性检验清单`（至少 2 条）
- **判定要点**：策略与研究问题匹配？假设陈述清晰？稳健性覆盖关键替代解释？
- **轻量档简版**：仅填识别策略 + 一句假设陈述；稳健性检验记 n/a

### 3. 数据来源 / 抽样设计（sampling_design）

- **必填字段**：
  - `数据来源`（一手 / 二手 / 公开数据库 / 主人投喂）
  - `抽样方法`（随机 / 分层 / 目的性 / 滚雪球 / 全样本）
  - `样本量`（N=？，时间跨度）
  - `样本流失率`（如适用）
- **判定要点**：抽样与研究问题匹配？样本量满足统计功效？流失率是否报告？

### 4. 变量操作化定义（variable_operationalization）

- **必填字段**：
  - `核心自变量`（定义 + 测量方式）
  - `核心因变量`（定义 + 测量方式）
  - `控制变量清单`（≥3 项 + 来源）
- **判定要点**：操作化与理论概念对应？是否多重操作化？控制变量来源是否可溯？

### 5. 分析单位与聚合层次（unit_of_analysis）

- **必填字段**：
  - `分析单位`（个体 / 组织 / 事件 / 年份-地区 / 其他）
  - `聚合层次`（如多层模型中的层级结构）
  - `生态谬误风险评估`（如适用）
- **判定要点**：单位与分析方法匹配？跨层次推断是否声明边界？

### 6. 模型设定与稳健性检验（model_specification）

- **必填字段**：
  - `主模型`（公式或结构方程）
  - `替代模型`（≥1 个换主模型）
  - `稳健性检验`（子样本 / 不同窗口 / 不同测量）
- **判定要点**：模型设定有理论支撑？替代模型是否报告？稳健性覆盖关键质疑？

### 7. 内生性处理（endogeneity_handling）

- **必填字段**：
  - `内生性来源`（遗漏变量 / 反向因果 / 测量误差 / 选择性）
  - `处理策略`（工具变量 / 固定效应 / 倾向得分匹配 / 安慰剂 / 其他）
  - `处理效果评估`
- **判定要点**：内生性来源是否全面？处理策略与来源对应？

### 8. 外部效度 / 可推广性边界（external_validity）

- **必填字段**：
  - `研究情境`（国家 / 行业 / 时段 / 制度环境）
  - `可推广性边界`（哪些情境可推 / 哪些不可）
  - `限制条件`（制度依赖 / 文化特殊 / 经济阶段）
- **判定要点**：边界声明具体？避免"普适性宣称"陷阱？

### 9. 伦理与利益冲突声明（ethics_disclosure）

- **必填字段**：
  - `伦理审查`（IRB 编号 / 主人豁免声明 / 不适用说明）
  - `利益冲突`（资助方 / 雇佣关系 / 关联机构）
  - `数据使用合规`（GDPR / 中国数据安全法 / 行业规范）
- **判定要点**：涉人研究是否过 IRB？利益冲突是否如实声明？

### 10. 方法论局限性自评（limitations_self_assessment）

- **必填字段**：
  - `最大局限`（≤3 条，按影响排序）
  - `对结论的影响`（每条局限如何影响主要结论）
  - `未来研究方向`
- **判定要点**：是否主动承认局限？还是被审稿人逼出来？

### 11. 复现性信息（reproducibility）

- **必填字段**：
  - `数据可得性`（公开 / 申请可得 / 不可得 + 原因）
  - `代码可得性`（公开 / 申请可得 / 不可得 + 原因）
  - `复现步骤`（如公开，附 README / DOI / 仓库链接）
- **判定要点**：是否给出获取路径？限制原因是否合理？

### 12. 前置理论框架与本文创新点对照（theoretical_positioning）

- **必填字段**：
  - `前置框架`（≥1 个，最多 3 个；本文基于哪个 / 哪些理论？）
  - `本文延伸`（在前置框架基础上加了什么？）
  - `本文差异`（与最近 3 年先行者文献的关键不同）
  - `新贡献`（数据 / 反打 / 国际视野 / 历史纵深 / 跨学科）
- **判定要点**：与 [理论贡献-protocol.md](理论贡献-protocol.md) 的三层声明对齐？

## 三、方法契约（B2-M3）

G18 的方法字段必须先形成结构化 `method_contract`，再映射到正文 §4；“已完成”不能替代字段值。每个字段只能取 `present`、`not_applicable_with_reason`、`unknown` 或 `owner_supplied` / `unverified` 等明确状态，空白不等于完成。

```yaml
method_contract:
  research_question:
  design:
  sample_or_corpus:
  sampling_frame:
  inclusion_exclusion:
  variables_or_categories:
  analysis_method:
  limitations:
  ethics_or_data_access:
  reproducibility_boundary:
```

最低规则：

1. 实证/量化研究必须填写 `sample_or_corpus`、`sampling_frame`、`variables_or_categories` 和 `analysis_method`；理论、历史或思辨研究可用 `not_applicable_with_reason`，但必须说明原因。
2. `unknown`、`unverified` 和空值不得判为 `present`；缺少关键字段时 G18 结论最多为“无法判定”，不得绿灯。
3. `method_contract` 与正文 §4、T5 交接报告三方必须一致；只在交接报告声明而正文缺失，记 P1。
4. 契约是 G18 的输入约束，不新增第二套方法论门，也不替代主人对研究方向的裁决。

## 四、证据链双向对账（B2-M4）

启用 E1 时，T7/T8 必须同时检查四个方向：

```text
正文引用 → 来源卡 / evidence_id
来源卡 → 正文引用
正文主张 → ClaimEvidenceLink
ClaimEvidenceLink → 证据对象
```

以下任一项即为 P1 或“路径或参数错误”，不得以统计数字或空登记表通过：正文 `[Lxx]` / `[Dxx]` / `[Cxx]` 无对应来源卡；来源卡从未被正文引用；映射表有主张但登记表没有逐字一致的 `ClaimEvidenceLink`；关系指向不存在的证据对象；`unavailable` / `abstract_only` 证据支撑强断言；反向证据未进入讨论或局限性。

报告必须包含结构化 `citation_evidence_reconciliation`：

```yaml
citation_evidence_reconciliation:
  body_without_card: []
  card_without_body: []
  claim_without_link: []
  link_without_evidence: []
  unavailable_overclaim: []
  counter_evidence_unhandled: []
  verdict: pass | fail | path_or_param_error | not_enabled
```

旧项目没有登记表时写 `not_enabled`；登记表存在但为空，不能写 `pass`。

## 五、DOI 身份与语义核验（B2-M5）

DOI 核验必须分层记录，不能把“可解析”当作“可用于当前论述”：

```yaml
identifier_check:
  syntax: pass | fail | unavailable
  resolves: pass | fail | unavailable
  metadata_match: pass | fail | needs_review
  semantic_match: pass | fail | needs_review | not_applicable
  checked_sources: [crossref, publisher, doi_landing_page]
  verdict: pass | needs_review | fail | unavailable
```

最低核验：

- `syntax`：是否为合法 DOI 形态；
- `resolves`：是否能解析到 DOI 目标；
- `metadata_match`：标题、作者、年份、期刊等是否与文献卡一致；
- `semantic_match`：DOI 对应来源是否真的支持当前正文主张，至少记录“支持 / 限定 / 反向 / 仅身份”；
- 只有搜索摘要、没有权威元数据时，最多 `needs_review`，不得写 `pass`；
- DOI 404、标题错配或主题不相关时必须 `fail`，并进入 `待人工核验` 或主人裁决出口。

DOI 校验只读外部元数据；是否调用 Crossref、出版社或 DOI 页面仍受 Phase 0 外部服务 opt-in 约束，未授权或不可用时写 `unavailable`，不得静默猜测。
