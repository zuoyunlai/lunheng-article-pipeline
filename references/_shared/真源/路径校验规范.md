# 路径校验规范

## 用途

论衡所有文件写入操作必须经过 **canonical 路径校验**，确保：
- 所有写入路径在项目目录 `run/<项目>/` 内
- 拒绝绝对路径、路径遍历（`..`）、符号链接逃逸

## 判定逻辑（in-process 伪代码）

论衡**零 exec**：agent 运行时**不执行脚本/命令**，路径校验由主控/子代理**推理模拟**下述 in-process 判定逻辑（与本地 canonical 路径工具同源；后者仅供人类 host 手动复核，agent 零 exec 不调用）。

```python
from pathlib import Path

def validate_target(base_dir: str, target_path: str) -> str:
    """校验写入路径，返回规范化绝对路径；不合法则拒绝"""
    # 1. 拒绝绝对路径
    if target_path.startswith('/'):
        raise ValueError(f"Absolute path not allowed: {target_path}")
    # 2. resolve 前显式拒绝父路径遍历（.. 组件）
    if '..' in Path(target_path).parts:
        raise ValueError(f"Parent traversal not allowed: {target_path}")
    # 3. 构造候选路径并规范化（resolve 解析 symlink + 折叠 . / ..）
    base = Path(base_dir).resolve()
    candidate = (base / target_path).resolve()
    # 4. 包含性检查：canonical 必须仍在 base 内
    candidate.relative_to(base)  # 越界抛 ValueError → 拒绝
    return str(candidate)
```

**判定口诀**（agent 实际执行）：
1. 目标路径是绝对路径 → 拒绝
2. 目标路径含 `..` 段 → 拒绝（resolve 前显式拦截）
3. `base_dir` 与目标路径 join 后 `resolve()` → 得 canonical 绝对路径
4. `candidate.relative_to(base)` 抛错 = 越界 → 拒绝；否则通过

## 设计原则（教训 #284）

1. **告警而非阻断**：路径校验失败时记录错误 + 人在环介入，不静默失败
2. **Canonical = resolve 解析 + 包含性检查**：确保最终路径在 `run/<项目>/` 内
3. **符号链接处理**：resolve 后检查包含性，符号链接指向项目外路径 → 拒绝
4. **不创建目录**：校验器只检查路径合法性，不执行文件系统操作
5. **in-process 而非 subprocess**：判定逻辑用 `pathlib`（`Path.resolve()` + `relative_to()`），不调外部命令——符合零 exec 哲学，也避免净化包剥离 `scripts/` 时误伤代码（教训 #256 同型）

## 判定口径：路径 / 参数问题 = 独立档位（v2.12.40）

路径校验失败**不是**内容缺陷，判定时落「**路径或参数错误**」档（四档口径真源 = [`M-Gate-Algorithm.md`](M-Gate-Algorithm.md) §判定结果分档），处置 = 修正路径 / 参数 / 前置产物后**重跑同一判定**：

| 现象 | 档位 | 禁止的误判 |
|---|---|---|
| 目标产物不存在（如 `final/定稿.md` 未落盘） | 路径或参数错误 | 不得当作 P1 内容问题 |
| 路径越界（绝对路径 / `..` / symlink 逃逸） | 路径或参数错误 | 不得当作内容缺陷，也**不得**静默跳过该检查项 |
| 参数非法（引用了非当前轮的 `v{N}`） | 路径或参数错误 | 不得当作内容缺陷 |
| 无法读取（内容读不出 / 证据不足） | 无法判定 | 不得当作「通过」 |

**为何单列**：路径类失败一旦被并进「不通过」，下游会触发**内容修订轮** —— 修的是本来没有问题的稿子（同族实现与本仓库 2026-09-14 均踩过此坑）。
