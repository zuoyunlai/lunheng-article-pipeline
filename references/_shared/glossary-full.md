## 一、核心角色（10 张角色卡，T8 终检由主控亲完成不 spawn）

### T0 - 主控（Coordinator，含 T8 终检）
- **职责**：流程编排 + 任务派发 + 质量把关 + 人机交互 + **T8 终检亲完成**
- **不做**：不替代任何子代理执行具体工作（除 T8 终检）
- **关键协议**：Phase 0 同意关卡 / spawn-yield 模式 / 完成验证铁律
- **T8 终检职责**：交付物完整性 + 引用闭环 + AI 使用披露 + 主控签字 → `final/定稿.md` + `final/交付说明.md`

### T1 - 文献侦查（Literature Scout）
- **职责**：已发布学术文献 / 政策文件 / 统计年鉴检索
- **输出**：`[Lxx]` 文献卡
- **并行模式**：T1 ∥ T2 ∥ **T3** 独立运行

### T2 - 数据检索（Data Scout）
- **职责**：已发布统计数据 / 行业报告 / 新闻数据检索
- **输出**：`[Dxx]` 数据卡
- **铁律**：只产数据卡，不产案例卡
- **并行模式**：T1 ∥ T2 ∥ **T3** 独立运行

### T3 - 案例检索（Case Scout）
- **职责**：案例/事件/人物/企业案例检索
- **输出**：`[Cxx]` 案例卡
- **0 条空卡协议**：0 条场景输出 `[C-空]`
- **并行模式**：T1 ∥ T2 ∥ T3 独立运行
- **任何量级必 spawn**：含 cases = 0 也走空卡协议

### T4 - 分析（Analyst）
- **职责**：论点拆解 + 论证结构设计 + 大纲编写
- **输入**：T1 + T2 + T3 全部完成后触发
- **输出**：`analysis/分析大纲.md`

### T5 - 写手（Writer）
- **职责**：正文撰写 + 修订执行
- **铁律**：禁做清单 10 项（AI 去味）
- **独立性**：修订轮必须重新 spawn，不能主控代执行

### T6 - 批判伙伴（Critical Companion）
- **职责**：批判性审查（非对抗性，从反方攻击论证）
- **触发**：T5 写手 v2（含主人洞察）完成后、T7 审计前
- **触发阶段**：**Phase 3.6**
- **输出**：`analysis/批判报告-vN.md`
- **七维清单**（详见角色卡 §批判维度）：C1 核心论点可攻击性 / C2 论证链薄弱 / C3 理论假设审查 / C4 立场中立性 / C5 反方观点完整性 / C6 元叙事清理 / C7 一处两用识别（主人可对照报告核验，不再盲信）
- **定位**：不是 adversarial，是 critical companion
- **攻击对象**：v2（含主人洞察），不是 v1

> **关键标识**：本角色在 §四 三检索员段 + §十一 主控 vs 子代理段 + 派发话术段均有 **T6 批判** / Phase 3.6 / T6 独立早期攻击 等显式标注。

### T7 - 审计（Auditor）
- **职责**：质量审计（G0-G14）+ 修订任务书
- **输出**：`audits/审计报告-vN.md`
- **双完整性门**：T2.5（数据卡完整性）+ T7.5（引用完整性，原 T5.5→T7.5）

### T9 - 同行评审（Peer Reviewer）
- **职责**：论文投稿前的预演审稿（**按模式默认开启**，公众号默认关闭主人可选）
- **触发阶段**：**Phase 4.5**（终稿前；T6 ∥ G14 已在 Phase 3.6 同批完成）
- **输出**：`audits/审稿报告-v[N].md`
- **6 维度评分**：原创性 / 方法论 / 证据强度 / 论证结构 / 写作质量 / 引文规范（每维度 1-5 分，总分 30）
- **判定**：26-30 accept / 21-25 minor revision / 16-20 major revision / <16 reject
- **与 T6/T7 的边界**：T6 攻击论证强度（不评分）/ T7 核验形式/事实（不评分，且是形式核验唯一权威）/ **T9 评分**（不做形式核验，引文规范维度消费 T7 的 G1 核验产物做编辑权重，不重复核验）
- **可关闭**：行业分析/学术默认开启（主人 Phase 0 可关），公众号默认关闭（主人可选）
- **借鉴**：academic-paper-reviewer（ClawHub 竞品）
- **不替代真实审稿**：仅 pre-submission 模拟，论文投稿后还需真实审稿人审稿

## 三、数据信任级别

> ⚠️ **两轴不混用（v2.12.28 定案）**：**信任级别 = 文字取值（已发布 / 主人投喂 / 二手转引）** —— 数据卡字段，M-Form-6 / M-Exist-3 校验（见 `templates/数据卡-template.md`）；**来源类型 = 文字（一手来源 / 二手来源 / 单边证据）**；**emoji 🟢🟡🔴 专用于「时效评级」**（🟢当前 / 🟡1-3 年 / 🔴3 年以上）。三者不同轴，不得互相套用。

### 判定标准速查（ECS 实战：D14 头条聚合判 🟢 与 D15 媒体转引判 🟡 口径不一）

| 来源类型 | 判定 | 典型 |
|---|---|---|
| **一手来源** | 官方统计 / 同行评议论文 / 学术专著 / **官方一手发布**（即使经门户转载，链接指向官方原文） | 统计年鉴、期刊论文 |
| **二手来源** | 媒体转引 / 百科类 / 行业报告 / **聚合平台汇编**（头条聚合、数据聚合站） | 媒体报道数字、艾瑞报告 |
| **单边证据** | 平台单方公告 / 自媒体 / 单一来源无法交叉验证 | 厂商自报数据、自媒体估算 |

> **聚合类判定铁律**：头条聚合/数据聚合站 ≠ 一手——除非链接直接指向发布机构原文，否则一律按**二手来源**起步。T2 打标时在数据卡「来源类型」字段写明判定依据（官方原文 / 媒体转引 / 聚合汇编 / 单方口径），T7 G12 按此抽验。

### Level 1：已发布公开数据（最高信任 · 信任级别 = **已发布**）
- **定义**：通过正规渠道发布的官方/学术数据
- **示例**：
  - 官方统计年鉴（国家统计局）
  - 学术论文中的研究数据（已发表）
  - 行业协会公开报告（中国汽车工业协会）
- **验证要求**：来源 URL 可核验（已发布数据，G1/G2 核验）
- **引用形式**：内联引用 `(来源，年份)` 或编号引用 `[Dxx]`

### Level 2：主人投喂数据（中信任 · 信任级别 = **主人投喂**）
- **定义**：主人提供的一手数据、内部资料、专家访谈记录
- **示例**：
  - 主人提供的企业内部销售数据
  - 主人进行的问卷调查结果
  - 主人的实地考察笔记
- **验证要求**：主人确认记录（主人投喂数据）
- **引用形式**：标注 `[主人提供]` 或 `[内部数据]`

### Level 3：二手转引（低信任，严格限制 · 信任级别 = **二手转引**）
- **定义**：从新闻报道、自媒体、二手资料转引的数据
- **限制条件**：
  1. 必须回溯到一次文献（新闻/报告必须引出原始来源）
  2. 顶部标注 `[二手转引]` 警告
  3. **T7** 审计 G12 专项检查
- **禁止场景**：核心论据、统计数据、精确数字
- **终稿导出**：emoji 标记仅限工作稿；导出 latex/docx/pdf 前按 [`_shared/format-export.md`](format-export.md) §四·五 清洗为正文括注，禁止 emoji 进交付稿（学术严肃性）

### 基线引用 [D-基-xx-xx] 格式

- **背景**：论衡 v2.3.7 论文三实战中 T2 数据检索员产出 6 条基线数据（资金/阈值/案例/其他），命名为 `[D-基-R-01]` `[D-基-T-01]` `[D-基-C-01]` `[D-基-E-01]` 等。但 T5 写手传递时可能简化成"基线一致"或具体数字，导致基线编号格式丢失，影响证据可追溯性。v2.3.7 升级后**基线数据编号格式正式规范化**。
- **格式定义**：`[D-基-<类别>-<序号>]`
  - `D-基`：基线数据前缀（区别于普通数据卡 `[Dxx]`）
  - `<类别>`：单字符类别码
    - `R` = Resource（资源/资金/成本）
    - `T` = Threshold（阈值/拐点/临界值）
    - `C` = Case（案例事件）
    - `E` = Evidence（其他证据）
  - `<序号>`：两位数序号（01-99），项目内唯一
- **示例**：
  - `[D-基-R-01]` = 资金基线第 1 条（如"开模打样成本"）
  - `[D-基-T-01]` = 阈值基线第 1 条（如"60% 一致性阈值"）
  - `[D-基-C-01]` = 案例基线第 1 条（如"某家居品牌原创失败事件"）
  - `[D-基-E-01]` = 其他证据基线第 1 条（如"10.6% 市场增速"）
- **数据卡模板要求**：T2 数据检索员产出基线时，必须按上述格式在数据卡 entry 顶部标 `**基线编号**：[D-基-R-01]` 字段。
- **写手传递要求**：写手 v1/v2/v3/v4/v5 引用基线数据时，**必须保留完整 `[D-基-xx-xx]` 格式**，不允许简化成"基线一致"或裸数字。M-Form-6 + M-Exist-3 双格式检查会拦截丢失基线编号的引用。
- **任务简报要求**：§四 数据基线段必填基线编号清单（如"资金基线：[D-基-R-01]；阈值基线：[D-基-T-01]"），写手 v1 看清单引用。
- **T7 审计检查**：G12 数据信任一致性 + 基线编号双格式检查——丢失编号 = P1 必补。

### ✅ 适用场景
- 学术论文（社科/人文）
- 商业评论/行业分析
- 公众号深度长文

## 九、外部服务声明

### 🌐 涉及的外部服务
1. **Tavily API**：web_search / tavily_search / tavily_extract
2. **OpenAlex API**（中文数据源第一梯队，**只读公开学术元数据 API，无需 Key**）：web_fetch 拉取文献/数据元数据，**仅发送检索关键词**，不发送个人信息/机密数据
3. **Crossref API**（中文数据源第一梯队，**只读 DOI 元数据，无需 Key**）：同上，仅发送检索关键词
4. **图像生成 provider（封面，可选默认关闭）**：image_generate 调用**宿主配置的默认图像 provider**（可能为 OpenAI / Google / MiniMax 等，以宿主 OpenClaw 配置为准；论衡文档不规定 vendor 路由 / 失败降级链，详见 SKILL.md「封面图像生成与数据外发披露」）
5. **大模型推理 provider**（当前模型，如 deepseek / MiniMax / Anthropic / GLM 等）：各角色卡调用 LLM 时，将**文献卡/数据卡/案例卡/草稿/分析大纲全文**发送给模型 provider
6. **中文数据源**：**OpenAlex + Crossref 默认启用**（只读公开 API，无需 Key，仅发检索关键词）；**原第二梯队（万方/科情/NSTL）已取消**（需 Key + 申请/付费/机构门槛，长期未使用）；**可选抓取层 Firecrawl**（`firecrawl_api_key`，抓取 paper.edu.cn）默认关闭，需主人显式启用 + 自配 key，论衡不存储 key，未启用时零调用

> **术语澄清**：「零 exec」= 不执行 shell 命令（`exec` 工具禁用），是**执行能力边界**；「零外发」= 不向外部发送数据，是**数据传输边界**。两者**不是一回事**。
>
> **内置功能（零外发）**：**数据图表 SVG** 由主控用 `write` 工具本地手写矢量图，**零外发，不依赖任何外部服务**（禁止文生图）。「零外发」**仅指数据图表 SVG**——检索（web_search/tavily/web_fetch）和**封面（image_generate）都会外发数据**。仅「封面」才调用 `image_generate`（**默认关闭**，需主人在 Phase 0 勾选启用；外发内容 = 图像 prompt；provider 不可用或主人不同意时改走 SVG 矢量封面，**不跨 vendor 自动降级**）。

### 🔒 数据流方向
- **向外发送**：
  - 检索关键词（web_search / tavily_search）
  - 目标 URL（web_fetch / tavily_extract，含 OpenAlex/Crossref 学术元数据 API——仅发送检索关键词）
  - 图像生成 prompt（image_generate，默认关闭，需主人同意）
  - **大模型推理全文**：文献卡/数据卡/案例卡/草稿/大纲/正文全文发送给当前模型 provider
- **不发送**：原始文献内容 / 主人投喂数据 / 中间产物（除非主人显式同意外发；大模型推理全文属上列外发项）

### 🛡️ 主人拒绝外部服务时的备选方案
1. **Web 检索**：主人手动提供文献/数据 PDF
2. **封面生成**：
   - 方案 A：主人提供封面图片
   - 方案 B：使用 SVG 手绘（本地生成）
   - 方案 C：使用 Ollama 本地模型（如 llama3.2-vision）

## 十一、关键术语

### 主控 vs 子代理
- **主控**：T0，流程编排者，不替代子代理执行具体工作（除 T8 终检）
- **子代理**：**T1-T7**，专项任务执行者（T8 终检 = 主控亲完成无独立子代理）

### spawn vs yield
- **spawn**：主控通过 `sessions_spawn` 创建子代理
- **yield**：主控通过 `sessions_yield` 挂起等待子代理完成

### 真源 vs 副本
- **真源**：论衡 skill 目录 `references/`（本 skill 的流水线真源）
- **副本**：ClawHub skill ZIP / GitHub 仓库

### 蒸馏 vs 压缩
- **蒸馏**（Distillation）：从日记忆提炼长期记忆（有损压缩）
- **压缩**（Compact）：减少重复内容（无损压缩）

## 十二、核心原则（单一真源，其他文档只引用不复制）

1. **证据底座先行 + 三角验证**：论点必能映射到 [Lxx] + [Dxx] + [Cxx]（涉企业行为/事件必须配案例卡，至少两项齐全）；检索不到就标缺口，严禁编造
2. **人在环四节点**：Phase 0 / 2.5 / 3.5 / 5 必须让主人过目，**无明确决策记录 = 未通过，不得推进**（Phase 3.5 允许「无补充」，但必须记录）。**无应答兜底**：主人 **60 分钟**（默认）无应答 → 主控写 status `pending_owner` 并**告警挂起**，不静默推进；Phase 5 复用「不答 = 接受当前定稿」。节点设计不变（「无明确决策 = 未通过」保持）。
3. **反方论证强制 + 强相关性原则**（防材料堆砌，2026-08-13 教训 #34）：每条材料必答「它支撑哪个论点」；数量封顶 [Lxx] 8-12 / [Dxx] 30-50 / [Cxx] 5-8 共 50-70 条；反向淘汰自查（删除它哪条论点会塌，无影响→砍）；相关性优先于时效
4. **独立审计 + 原创性保证**（2026-08-13 防「重复/改写已公开文章」）：审计员只审不改，引用分级抽验（C级 100% / B级 ≥50% / A级 ≥10%）；先行者检索（T1 主动搜「是否已有公开深度文写过类似核心论点」）+ 差异点声明（T4 大纲必声明与已公开文章的差异点）+ G7 原创性审计（核心论点与他人重复且未声明 → P0）
5. **模型分工**：检索用便宜快模型，分析/写作用推理强模型，审计用顶配，主控负责路由；顶配档全不可用 → 显式告知主人禁止静默降级
6. **时间锚点显式化 + 文件保留原则**：所有卡片引用必带年份；案例卡额外填「检索截止日期」+「事件时间窗口」；任一 Phase 失败或项目收尾，**论衡 agent 不执行任何删除操作**——已写文件保留在 `run/<项目名>/` 供主人手工清理（防误删红线）；项目归档同样由主控出清单、主人手工 `mv`/`cp`（agent 不执行），详见 [`project-archive-sop.md`](project-archive-sop.md)。**「归档」= 复制/移动到 `run/.archive/`；「删除」= 主人自行处理**——两个动作都由主人在 host shell 完成，论衡 agent 一律不碰。
7. **可选项准入判据（本修订定案）**：**只给「有真实成本或真实取舍」的东西开关**（外发数据 / 花钱的 API / 额外产物）；**零成本的质量门与透明度项由条件决定，不由偏好决定** —— 分三态：`默认启用`（无开关，如方法论足迹面板）/ `按条件自动`（语言 + 体裁 + 档位，如 G14 闸）/ `按模式`（如 T9 同行评审）。要关闭只能走「**显式豁免 + 交付说明披露**」窄口。配套铁律：**一条款一真源**（类别清单只在一处定义，其余文档只引用不重列；重列必漂移）、**工具级 opt-in 与服务级外发同意分列**（绝不合成一张表）、**流程真源必须能表达可选性**（`phase-order.yaml` 节点带 `condition` / `degrade` / `exempt`）。详见教训 #338。
