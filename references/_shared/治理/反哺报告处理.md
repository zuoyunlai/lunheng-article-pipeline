# 反哺报告处理（原 `agents/00-主控-扩展职责.md` §二十，v2.12.61 分层外移）
> 背景：v2.0 讲过「反哺」机制但 v2.2 实战未自动执行，导致 P1「我接触过」/P2 数据无源 / P2 图注精度 3 类问题在实战中重复出现。改为默认只产出，**不自动 commit** 到角色卡。
>
> ⚠️ **v2.12.40 升级为「机制保护」硬约束**：反哺报告 / 角色卡 / 机制文件（技能定义 / 脚本 / 补丁配置）的任何改动**一律需人工 approve，禁止自动合并**；违反与「改动即最严重违规」同级。完整条文（含诚实边界：这是**流程层**约束，不是工具层拦截，故人工确认不可省）见 [`_shared/真源/关键协议.md`](../真源/关键协议.md) §机制保护。

**主控会话结束时**（Phase 5 终检后）执行 4 步：

1. **读取** T7 审计员交付的 `audits/反哺报告-vN.md`
2. **列出建议 merge 的反哺规则**到 `final/交付说明.md` 末段「建议 merge 的反哺规则」清单
3. **不调用 edit/write 工具 commit 任何角色卡**——等主人人工 review 后手动 merge
4. **实战教训沉淀建议（教训 #276，教训 #135，待主人 review 后生效）**：本次实战暴露的机制级问题（如模型 fallback 缺失、交付边界混淆、字数口径不一致）→ 主控产出建议草稿 `run/<项目>/audit-lessons.md`（教训 #N 格式：现象/根因/解决/立项），不依赖主人事后提示。**判据**：实战中出现「机制缺失/执行层跳过/设计漏洞」任一 → 必建议沉淀；纯项目内容问题（如某论点论据弱）不沉淀（属反哺报告范畴）。**只写 `run/<项目>/audit-lessons.md`（workspace 内），跨仓同步由主人手工完成**（与 `agents/07`/`agents/08` 的「跨 workspace 写入封禁」一致）。**v2.3.7 升级后协议**：
   - **教训编号体系**：主控侧 `memory/lessons.md`（OpenClaw agent general lessons，适用范围广）与论衡侧 lessons 主文件（paperwriter-specific lessons，仅论衡技能用）是两套独立编号体系。
   - **判据**：教训是否**论衡特定**？是 → 在 `audit-lessons.md` 标「建议同步论衡侧」；否 → 仅标主控侧。
   - **触发时机**：论衡实战结束时（如 T8 终检完成），主控检查「本轮实战教训是否影响论衡机制」（如 fallback 缺失 / 写手铁律缺位 / M-Gate 算法漏洞）→ 是 → 在 `audit-lessons.md` 标「建议双侧同步」；纯 OpenClaw 通用的教训 → 仅主控侧。
   - **示例**：论文三教训 #142（主控误判字数 spawn T5 v5） → **仅主控侧**（因为「spawn 前必验产物最终态字数」是 OpenClaw general lessons，不是论衡特定）。
   - **示例**：v2.3.1 教训 #119（claude-opus-5 静默无响应） → **建议双侧同步**（因为论衡 T7 审计员也用这个 fallback 机制）。
   - **实现路径**：主控只在 `run/<项目>/audit-lessons.md` 列出「论衡特定教训」清单＋同步建议 → 由主人人工 merge 到两侧 lessons 主文件；**agent 不写工作区外路径**。
   - **同步校验建议（本机实战 P1-7 互斥发现，待主人 review）**：项目结束除写 `run/<项目>/audit-lessons.md` 外，提示主人做「项目级 → 工作区级」同步校验——确认论衡侧 lessons 主文件与主控侧 `memory/lessons.md` 的教训编号**没有脱节**（避免两套独立编号体系各自续号后丢失对应关系）。校验方法：若本项目的「论衡特定教训」只进了主控侧未进论衡侧 → 提示主人补同步。

如反哺报告为空（无新增问题），主控建议写「本轮反哺报告：T5 未发现可沉淀新增问题」，避免机制被跳过。**空报告同样不修改角色卡**。

**v2.12.40 补：机制面改动的 approve 记录**：主控在 `status.md` 记「机制面改动候选（反哺规则 / 角色卡 / 机制文件）」+ approve 结果；**无记录 = 未发生**。清单只列建议，**不得**调用 `write`/`edit` 改角色卡或机制文件（真源 = [`_shared/真源/关键协议.md`](../真源/关键协议.md) §机制保护）。
