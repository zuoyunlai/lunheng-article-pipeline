# 项目归档 SOP

> **来源**：ECS v2.7.13 实战报告问题域 D-1（报告建议「T9 完成后无明确项目归档 SOP，主控需手写归档路径」——论衡多版本迭代一直未把归档单独成文）
> **边界**：本 SOP 定义「归档什么 + 归档到哪 + 谁执行」。**归档移动是 host shell 文件操作，论衡零 exec 承诺下 agent 不执行 `mv`/`rm`**——主控负责产出归档清单与建议目标路径（写进交付说明），**移动动作由主人本人在 host shell 手工执行**（与图件 PNG 转换「主人手工 rsvg-convert」同一模式，见 图表-SVG-template.md）。

## 一、触发时机

**T9 同行评审接受 / 主人 Phase 5 验收通过后**，主控在 `final/交付说明.md` 末段追加「项目归档清单」节，然后提醒主人执行归档。归档不是流水线闸门（不归档不阻断交付），是收尾整洁动作。

## 二、归档内容清单（全量）

| 类别 | 内容 | 路径 |
|------|------|------|
| 简报与状态 | 任务简报 / status.md | `run/<项目名>/01-任务简报.md`、`status.md` |
| 证据底座 | 文献卡 / 数据卡 / 案例卡 | `literature/`、`data/`、`cases/` |
| 加工产物 | 分析大纲 / 批判报告链 | `analysis/`（含全部 vN 版） |
| 写作链 | 初稿全版本 + 修订说明 | `drafts/`（含 `drafts/archive/`） |
| 审计链 | 审计报告 + 反哺报告 + G14 报告 | `audits/` |
| 终稿交付 | 定稿 / 图件 / 证据包 / 交付说明 | `final/`（全量） |
| 心跳与临时 | 子代理心跳 / 临时文件 | `run/<项目名>/.tmp/`（如存在，一并归档） |

**只读快照原则**：归档的是项目**当时完整状态**（含中间稿与失败尝试），不是只留终稿——审计链可追溯是论衡交付的一部分。归档只增不删，原 `run/<项目名>/` 目录**保留不动**，直至主人确认无误后再自行决定清理。

> ⚠️ **遥测排除规则（v2.12.40，回应外部安全扫描「遥测收容不足」）**：上表「简报与状态」行中的 `status.md` **含运行期遥测**（`session id` / `sessionKey` 等会话标识；v2.12.42 起余额与探测结果**不再采集**，但历史项目文件仍可能含——排除规则不变），**归档/打包时默认排除**：
> - 归档、压缩、导出、分享项目目录前，**必须**先排除 `status.md`（或只归档其**脱敏副本** `status.redacted.md`）。
> - **脱敏副本规格**：`sessionKey` / `session id` 截前 8 字符 + `…`（或哈希前 12 位）；余额/可用性列只保留档位符号（✅/⚠️/❌），**去除具体数值**；其余结构不变（保留可观测性）。
> - 同理适用于 `.tmp/` 下的心跳文件（含 `sessionKey` 时可同规则脱敏）。
> - 真源 = [`关键协议.md`](../真源/关键协议.md) §遥测收容。

## 三、目标路径命名规范

```
run/.archive/<项目名>-<YYYYMMDD-HHMM>/
```

- 例：`run/.archive/口腔AI智能化-20260908-0754/`
- 时间戳 = 项目启动时间（Phase 0 落任务简报的时刻），与 status.md 记录一致，便于多项目排序
- 归档后如需在 run/ 留一个指向最新归档的链接，由主人自行决定（agent 不建链接）

## 四、主控职责（收尾时）

1. T9 接受 / 主人验收后，read 项目目录树（零 exec，read 各子目录已知产物路径）
2. 在 `final/交付说明.md` 末段写「项目归档清单」节：
   - 建议归档目标路径（按上节命名规范）
   - 待归档条目清单（按第二节类别，逐条列实际路径）
   - 提醒主人：`mv run/<项目名> run/.archive/<项目名>-<启动时间戳>/` 或整目录复制二选一；agent 不执行移动
3. 项目级教训沉淀仍按主控扩展职责「实战教训沉淀建议」段执行（`run/<项目>/audit-lessons.md` → 主人 review 后 merge），归档前提醒主人把该文件一并纳入归档清单

## 五、主人操作（host shell，agent 之外）

```bash
cd run/                      # 论衡工作区 run/ 目录
mkdir -p .archive
# 方案 A：移动（run/ 下不再保留活动副本）
mv 口腔AI智能化 .archive/口腔AI智能化-20260908-0754/
# 方案 B：复制保留（run/ 下继续留活动副本）
cp -r 口腔AI智能化 .archive/口腔AI智能化-20260908-0754/
```

移动/复制完成后，原目录中间态（如 `.tmp/` 心跳）是否需要清理，属**主人自己的决策**——由主人在 host shell 自行处理；**论衡 agent 在任何阶段都不执行删除操作**（零 exec + 防误删红线）。

## 六、与既有机制的关系

- 归档 ≠ 删除：归档后原 run 目录默认保留，清理权在主人
- 归档 ≠ 发布：ClawHub/多格式导出（format-export.md）是交付动作，归档是收尾动作，互不依赖
- 版本号/引用完整性检查仍走发布自审门（发布流程，开发者侧执行），归档不触发任何发布门
