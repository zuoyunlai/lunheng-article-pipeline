#### 2. P0-1: SKILL.md 能力边界前置声明 ✅
**问题**：M 门算法文档中大量 shell 命令示例容易让用户混淆"论衡能不能执行 shell"

**修复方案**：采用方案 C（最小改动）——在 SKILL.md 顶部补充能力边界说明

**修复内容**：
在 SKILL.md 第一个标题后新增 `## ⚠️ 执行能力边界（重要：先读这一段）` 段落：

```markdown
**论衡技能的执行能力**：
- ✅ **可以**：read / write / edit / web_search / tavily_search / memory_search 等 15 项工具
- ❌ **不可以**：exec / process / browser
- ℹ️  **M 门算法**：主控 LLM 通过 `read` 读取算法文档，按伪代码**推理判定**，不执行实际 shell 命令
- ℹ️  **跨平台 sha256**：需要主人在 host shell 手动计算后回填

**为什么这么设计**：
- 论衡是纯推理流水线，所有验证都通过 LLM 推理完成（读文件 → 正则匹配 → 集合运算 → 判定）
- M 门算法文档中的 bash 命令是「人类验证示例」，方便主人手动复核，**不是 agent 执行的代码**
- 这样设计确保了跨平台兼容（Windows / macOS / Linux）和安全性（零 shell 执行风险）
```

**验证**：
```bash
head -60 SKILL.md | grep -A 10 "执行能力边界"
```

**影响**：用户在阅读 SKILL.md 时立即了解论衡的能力边界，不会误以为论衡会执行 shell 命令
